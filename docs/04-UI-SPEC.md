## 1. 文案纪律（先读这条）

**界面上只允许出现两类文字：字段值，和本文件列出的固定标签。**

不允许出现：解释性副标题、使用提示、玩法说明、"系统判定""AI 认为""提示：…"这类旁白、emoji 装饰、图例注释。

需要新增任何固定文案（按钮名、空状态文字、错误提示）→ 先在本文档登记，再实现。不要自己发挥，这是本项目最容易引起返工的地方。

**`aria-label` 不受本条限制。** 它是给屏幕阅读器读的，不显示在界面上、不占视觉空间，可以为控件写描述性标签（如"难度""时长""附件"）。但它不该变成第二套文案体系——只说明这个控件是什么，不解释怎么用。

**状态中文名（已登记，2026-10-28）**：

| 值 | 显示 |
|---|---|
| `todo` | 待办 |
| `doing` | 进行中 |
| `reviewing` | 待确认 |
| `done` | 已完成 |
| `discarded` | 已丢弃 |
| `archived` | 已归档 |

这组词会出现在错误消息里（如「任务不能从「待办」直接变为「已完成」」），W6 的右栏 ① 区也会用到。权威实现在 `src/main/db/stateMachine.ts` 的 `LABEL`，改词要两边同时改。

**显示格式（已登记，2026-10-28，W6B 日历交付时补）**：

| 场景 | 格式 | 例子 |
|---|---|---|
| 月份标题 | `{YYYY} 年 {M} 月` | `2026 年 10 月` |
| 星期列头 | 单字，周一起 | `一 二 三 四 五 六 日` |
| 日浮层标题 | `{M} 月 {D} 日 周{X}` | `10 月 27 日 周二` |
| 日浮动层行尾分值 | `{N} 分`；整数不带小数位，小数最多 2 位 | `50 分`、`11.5 分` |
| 类型标签 | 与 §4① 同源 | `每日` / `限时` / `活动` |
| 悬浮条形态切换按钮 | `⋯`（单字符，无文字） | `⋯` |
| 悬浮条快速加任务占位 | `一句话加任务…`（省略号是单个 `…`） | `一句话加任务…` |

这五条是**格式**不是文案，仍受本节第 10 行约束：不许在它们外面再包解释性文字（如"当月共 3 项""点击查看详情"）。

**错误消息也算界面文案。** `AppError.message` 是面向用户的中文短句，可直接渲染（02 §1），但它的模板必须先在本节登记。允许的动态成分只有三类：上表的状态中文名、任务标题、日期字段的中文名（如「起始日」）。`retryable` 字段已经表达了能不能重试，文案里不要再写"请重试""操作失败"。

## 2. 主窗布局

窗口：默认 `1440 × 920`，最小 `680 × 520`，`backgroundColor` 跟随主题，无自绘标题栏（用系统标题栏，避免拖拽区与输入框冲突）。

```
┌───────────────────────────────────────────────────────────────┐
│  顶栏 56px：左 应用名 · 中 (空) · 右 [悬浮条开关] [设置]        │
├──────────────────────────────────┬────────────────────────────┤
│                                  │  ① 当前任务        (弹性)   │
│   会话区  flex:1  min 520px       │  ─────────────────────────  │
│                                  │  ② 日历            (240px)  │
│   ┌─ 消息流（滚动）────────────┐  │  ─────────────────────────  │
│   │ 气泡 / 草稿卡片 / 审核卡片  │  │  ③ 积分            (120px)  │
│   └────────────────────────────┘  │  ─────────────────────────  │
│   ┌─ 输入区 固定 96px ────────┐  │  ④ 明细            (弹性)   │
│   │ [+] [多行输入]      [发送] │  │                            │
│   └────────────────────────────┘  │  w = 400px 固定            │
└──────────────────────────────────┴────────────────────────────┘
```

右栏宽 `400px` 固定，四区块纵向堆叠，各区块上下分隔线 `1px`。①④ 弹性、②③ 固定高。整栏可整体隐藏（右侧边界拖拽或顶栏开关）。

## 3. 会话区

### 3.1 气泡

| role / kind | 视觉 | 备注 |
|---|---|---|
| user / text | 右对齐，主色浅底，圆角 14，max-width 78% | 图片在上、文字在下，图最多 4 张九宫格 |
| assistant / text | 左对齐，无底或极浅底，圆角 14 | 支持 markdown：段落、有序/无序列表、行内代码、粗体 |
| assistant / task_draft | 卡片组，宽度撑满 88% | 见 §3.2 |
| assistant / task_review | 单张卡，左侧色条表示 verdict（pass 主色 / partial 琥珀 / need_evidence 蓝 / fail 灰） | 见 §3.3 |
| system / reminder | 居中细条，无气泡，`14px` 次级色文字 | 点击跳转对应任务 |
| system / error | 左侧灰底卡，带 `[重试]` | 不阻断会话 |

**渲染时按 `meta.kind` 收窄，不要按 `Message.kind`。** 两者是两个独立字段，且名字并不一一对应：`kind: 'text'` 的消息其 `meta` 是 `{ kind: 'none' }`（`MessageMeta` 里没有 `'text'` 成员）。用外层 `kind` 去 switch 会在 `text` 这一支上取不到任何 meta 字段。逐条映射：

| `Message.kind` | `Message.meta.kind` | meta 携带 |
|---|---|---|
| `text` | `none` | 无 |
| `task_draft` | `task_draft` | `drafts` |
| `task_review` | `task_review` | `taskId` / `verdict` |
| `reminder` | `reminder` | `reminderId` / `taskId` / `title` / `fireAt` |
| `error` | `error` | `code` / `message` / `retryable` |

### 3.2 草稿卡片（核心组件）

一张卡片 = 一个 `TaskDraft`。同一消息内多张时纵向排列，间距 12px。

```
┌──────────────────────────────────────────────┐
│  [每日·限时·活动 三选一]                      │  ← 顶部一行类型切换
│  标题（可点击就地编辑）              [+ 20]   │  ← 右上角是分值徽标
│  detail_md（最多 3 行，超出折叠）              │
│  ─────────────────────────────────────────    │
│  ○ 步骤 1                                     │
│  ○ 步骤 2                                     │
│  ─────────────────────────────────────────    │
│  [难度 ▾] [30 分钟] [10-30 18:00]  [丢弃][确认]│
└──────────────────────────────────────────────┘
```

类型切换会改变第三行的时间控件：

| type | 时间控件 |
|---|---|
| 每日 | `21:00`（每日提醒时刻）+ 可选结束日期 |
| 限时 | `10-30 18:00`（截止时刻） |
| 活动 | `10-30 09:00`（发生时刻） |

上表是**显示格式**。`TaskDraft.dueHint` 字段本身存完整 ISO8601（02 §2），渲染层负责 ISO ↔ `datetime-local` 的时区换位。**不要为了显示方便把年份截掉再写回字段**——跨年时会错一年，而 `dueAt` 同时喂提醒、逾期判定、效率系数三条链路。「补当前年」这种猜法一律不许用。

切换类型时，`reminderOffsets` 自动换成该类型默认值（限时 → 前 1 天/前 1 小时；活动 → 前 7/3/1 天），并在卡片下方以只读小字列出触发点，例如 `前 1 天 · 前 1 小时`。用户可在任务详情里改。

难度下拉的显示名（已定稿，2026-10-28）：

| 值 | 显示 |
|---|---|
| `trivial` | 琐事 |
| `easy` | 简单 |
| `medium` | 中等 |
| `hard` | 费劲 |
| `epic` | 大工程 |

下拉选项与卡片上的难度标签都用这一组，**不显示英文原值，不附加括号或说明**。除此之外不加任何难度描述文字（如"预计 30 分钟以内"）。

**下拉里实际可选哪几档，由类型决定**（`src/shared/taskRules.ts` 为唯一来源，不要在组件里另写一份）：

| 类型 | 下拉里出现的选项 |
|---|---|
| 每日 | 琐事 / 简单 / 中等 |
| 限时 | 简单 / 中等 / 费劲 |
| 活动 | 中等 / 费劲 / 大工程 |

切换类型时若当前难度不在新类型的可选项里，用 `snapDifficulty` 归位到最近一档（平手取低档），并**跟着重算分值**。

交互规则：

- 标题、类型、难度、时长、时间五项**可就地修改**。
- **改难度后**分值即时刷新，本地按 `@shared/points/rubric` 算，不调 `points.preview`（那是 IPC，W2 接线后才可用；且纯计算没必要过进程）。
- **改时长不影响分值**。v0.9 起时长已退出积分公式（02 §5.2），它只用于 AI 判难度、排提醒、算逾期。原来是"改难度/时长后刷新"，那句话已废。
- `missing_info` 非空时，在卡片底部以「待补」标签逐个列出，**不加任何引导语**。
- `confidence < 0.5` 时，卡片左边框变虚线（视觉弱提示，不写文字）。
- 确认 → `ai.confirmDraft` → 卡片变为已确认态（变灰、按钮消失、显示任务 id 关联），不可再改。
- 丢弃 → 卡片淡出移除，`ai.rejectDrafts`。
- 一个消息里 3 张卡片**独立处理**，不做批量确认。

### 3.3 审核卡片（S4 证据）

四条状态，卡片结构相同，动作区不同：

```
┌──────────────────────────────────────────────┐
│ ▌ 交物理作业                      限时 · 20分 │  ← 左侧 3px 色条 = verdict
│   截图显示已导出 PDF，含完整实验数据          │  ← reason，AI 的判断依据
├──────────────────────────────────────────────┤
│  证据： [pdf ×] [IMG_2041.jpg ×]  [+]         │  ← 已有证据，可删可加
├──────────────────────────────────────────────┤
│                          [继续做]  [完成 +20] │
└──────────────────────────────────────────────┘
```

| verdict | 色条 | 动作区 | 说明 |
|---|---|---|---|

**证据标签显示什么**：`Attachment`（02 §2）目前只有 `id/kind/url/mime/bytes/width/height`，**没有 `name`**，所以标签上的是类型角标（`pdf` / `jpg`，取 mime 子类型），不是文件名。这不是偷懒——要显示 `报告.pdf` 就得给 `attachments` 加列、给 `Attachment` 加字段，那属于附件功能本身（W2 的附件子项）。在那之前**不要自己造一个 `name` 塞进 `Attachment`，也不要把完整 mime（`application/pdf`）直接显示出来**。
| `need_evidence` | `--accent` 蓝 | `[补证据]` + `[继续做]` | **没有"完成"按钮**，因为点不了。`reason` 处显示 `followup` |
| `pass` | `--accent` | `[完成 +N]` + `[继续做]` | |
| `partial` | `--warn` 琥珀 | `[完成 +12]` + `[继续做]` | 按钮数字是 `computeAwardedPoints` 的实算值，不是百分比（示例：`medium` 20 × 0.6 = 12）；卡片内按 `verdict.gaps` 逐条列出未完成项 |
| `fail` | `--text-faint` 灰 | `[继续做]` | 不给完成按钮 |

证据交互：

- `[+]` 支持粘贴截图、选择文件、或直接打字（一段文字说明也算证据）。
- 图片证据存 `attachments`，卡片内显示 48×48 缩略图，点开大图。

**两类任务在卡片上多一行（v0.7 积分改版的直接结果）：**

| 类型 | 增加的内容 | 文案 |
|---|---|---|
| 限时 | 右上角分值旁显示提前/逾期量 | `提前 4 天` / `提前 30 小时` / `逾期 3 天`，取不到 `completedAt` 时不显示 |
| 活动 | 一行结果选择，改选后分值立即重算 | `[结果 ▾] 超预期 / 达标 / 不佳`，默认 `达标`。**只在有 `[完成 +N]` 按钮的卡上出现**（`pass` / `partial`）；`fail` 与 `need_evidence` 不显示——没有完成动作就没有分值可算，摆一个改了没反应的下拉只会让人困惑 |

活动的 `result` 是必填的（默认 达标）。选「超预期」是 ×1.2、选「不佳」是 ×0.85，见 02 §5.2。**不要给这三个词加解释**（比如"超预期：排名前 20%"）——用户自己知道自己的考试考成什么样。
- 文字证据在卡片内单行显示，溢出省略号，点击展开。
- **`need_evidence` 状态下不允许绕过**：补完证据后卡片下方出现 `[重新审核]`，点了才重跑 AI。
- 连续 3 次 `need_evidence` 后，动作区右侧出现 `[直接标记完成（不计分）]`，弱化样式（`--text-faint`）。这是防死锁的出口，不是后门——点了就是不入账。

### 3.4 输入区

- 多行自适应，1~6 行，`Enter` 发送、`Shift+Enter` 换行。
- `[+]` 打开附件，或直接 `Ctrl+V` 粘贴截图、拖入文件。
- 粘贴图片后，输入区上方出现缩略图条，每张带删除角标。
- 发送后输入框清空、但**保留焦点**。
- AI 思考中：发送按钮变为禁用态并显示细环进度，输入框仍可输入（允许连打，队列化）。

## 4. 右栏四区块

### ① 当前任务

按类型分三组，组间 12px 间距，组标题为：`每日` / `限时` / `活动`。空组不显示标题。

- **每日组**：每行 = 一个今日 occurrence。左侧圆形勾选框、标题、右侧连续天数（`7` 这样的纯数字，不带"天"字以外的修饰）。
- **限时组**：状态点、标题单行截断、右侧显示剩余时间（`2h` / `明天` / `逾期`）。
- **活动组**：同限时，右侧显示距发生时间的倒计时（`7d`）。
- 组内排序：doing 优先 → priority 降序 → 时间升序（null 最后）→ sortKey。
- 组间固定顺序：每日 → 限时 → 活动。每日在最上，因为它每天都得看一眼。
- 点击行展开详情（`detail_md` + 步骤勾选 + 提醒偏移 + `[完成]`），就地展开，不弹窗。
- 步骤勾选只改子任务状态，不影响父任务；父任务 `[完成]` 时若还有未勾步骤，弹一个就地确认条（不是 modal）。
- 已完成的限时/活动不在此列表，进 ④。

### ② 日历

月视图，7 列，高度固定 `240px`。顶部一行：`‹  2026 年 10 月  ›`。

**格子结构**

```
┌──────┐
│  27  │   ← 日期数字，14px
│   ·  │   ← 红点行，固定 6px 高，即使没点也占位（防止有/无红点的格子高度跳动）
└──────┘
```

- **红点**：该日有任务时，日期下方出现一个 `4px` 实心红点，颜色 `--dot:#E5484D`。
- 该日任务**全部完成**时，红点变为同色**空心圈**（`border:1.5px solid`，内部透明）。这条是我加的：否则一个月过完，日历全是红点，看不出"哪天真的干完了"。**如果你不想要，去掉即可，不影响结构。**
- 一天有多个任务仍是**一个点**，不叠加 —— 点数量在 7 列窄格里根本看不清。
- 今日格：数字加粗 + 1px 边框。
- 非本月日期：不显示（不填充上月/下月灰字），保持视觉干净。
- 空白日：只有数字，无点。

**点击日期 → 展开当日任务**

点击任意有任务的日期，从日历块底部**以浮层方式**展开一个列表（宽 400px、最大高 200px、内部滚动、带阴影、覆盖 ③④ 区域，不挤压布局）。点击外部或再点同日收起。

```
┌────────────────────────────────────┐
│ 10 月 27 日 周二               ×   │
├────────────────────────────────────┤
│ 18:00  交物理作业   限时  ·  23 分 │
│ 09:00  英语六级考试  活动  ·  50 分 │
└────────────────────────────────────┘
```

- 每行：`时间 · 标题 · 类型标签 · 分值`。已完成的行标题加删除线、整体降透明度。
- **分值的语义是"计划/实得原值"，渲染层不重算、不做标记**（v0.18）：`calendar.dayDetail` 对已完成项给 `points_awarded`、未完成项给 `points_planned`，两者可能不等（质量/效率系数），列表只照原值显示。要区分两者得新增登记文案，本轮不做。
- 点击行 → 右侧 ① 区滚到该任务并短暂高亮。
- 空日期（无任务）点击不响应，不弹空面板。
- **空态**（v0.18）：只有红点日（`total > 0`）可点；若点开后 `dayDetail` 返回空（两次调用之间数据变了），**保留浮层标题、列表区留白**，最小高度 40px 防止浮层塌成一条线，不出现"暂无任务"之类文字（§7 空状态留白原则）。

**数据来源**：`calendar.dayIndex(year, month)` 一次取当月红点，`calendar.dayDetail(day)` 点击时才查。**不允许**渲染层为 30 个格子各发一次请求。

**日历只呈现限时与活动。** 每日任务不进日历、不点红点（Q2 已定），它们归 ① 区的「每日」组和会话管理。实现方不要"顺手"把 occurrence 混进 `dayDetail`，那会让日历变成一片红。

### ③ 积分

- 大数字：当前余额，`32px/600`。
- 右侧两行小字：`今日 +N`、`本周 +N`。
- 下方一条 7 日迷你柱状（无坐标轴、无图例）。
- 无任何说明文字。

**分值显示格式（全界面统一，写在 `shared/format.ts` 的 `fmtPoints()` 里，不许各处自己 `toFixed`）：**

| 实际值 | 显示 | 不显示 |
|---|---|---|
| 23 | `23` | `23.00` |
| 10.75 | `10.75` | `10.8` / `10.750` |
| 5.5 | `5.5` | `5.50` |
| -10.75 | `-10.75` | `-10.8` |

规则：最多 2 位小数，末尾的 0 去掉。因为积分是小数（02 §5.2），界面上任何"取整显示"都会让余额和明细对不上——用户会认为账算错了。

**实现约束**：`fmtPoints` 的唯一实现是 `String(roundPoints(v))`，复用 `rubric.ts` 的 `roundPoints`，不要在里面另写 `Math.round` 或 `toFixed`——"全项目 `Math.round` 只准出现在 `roundPoints` 内"这条禁令同样管格式化函数。`String()` 天然去掉尾零，不要再额外裁剪；输入若已过 `roundPoints`，也不会出现 `5.750000000000001` 这类尾巴。

### ④ 明细

- 时间倒序流水：`HH:mm  标题或原因  ±N`，`±N` 用上面的 `fmtPoints`。
- 正数用主色，负数用灰红。
- 顶部一行：`今日` / `本周` / `本月` 三个切换（segmented，无说明）。
- 点击条目 → 若有 `taskId`，滚动并高亮对应任务。
- **撤销入口**：满足三条的流水行（`reasonCode === 'task_done'`、`occurrenceId === null`、`reversedAt === null`）在行尾给一个 `[撤销]`，点它调 `task.undo({ id })`。三条缺一条都不显示——已冲销的行再撤就是重复冲销；`occurrenceId` 非空的是每日打卡，走 `occurrence.undo`（每日组的勾选框），不在这里撤销。
- 撤销成功后该行原地变成已冲销态（`reversedAt` 非空），`[撤销]` 消失；`task.undo` 报「超过 24 小时的完成记录不能撤销」时就地提示，不改行。**超窗的行不预先隐藏**：判断窗口要读 `completed_at`，渲染层不重复算这条规则，交给主进程裁决。
- 行结构（v0.20）：整行是一个主按钮（点它滚到对应任务），`[撤销]` 是行尾**独立的第二个按钮**——`<button>` 不能嵌套，所以"整行可点"与"行尾撤销"必须是兄弟节点。已冲销行整行降不透明度（不另加文字、不加 tooltip）。

## 5. 悬浮窗规格（R8）

独立 `BrowserWindow`，两个渲染入口共用一套 `HudPanel` 组件，只是外壳不同。

### 5.1 基础窗体参数（两种模式相同）

```ts
new BrowserWindow({
  width, height,                       // 按模式计算
  frame: false,
  transparent: true,
  backgroundColor: '#00000000',
  resizable: false,
  movable: mode === 'float-pod',       // dock-bar 不可拖
  skipTaskbar: true,
  alwaysOnTop: true,
  hasShadow: false,
  roundedCorners: false,
  focusable: true,
  show: false,                          // ready-to-show 后再显示，避免白闪
  webPreferences: { preload, contextIsolation: true, sandbox: true },
})
win.setAlwaysOnTop(true, 'pop-up-menu')   // 不用 'screen-saver'，否则盖住全屏视频
win.setVisibleOnAllWorkspaces(true)        // macOS 有效，Windows 无副作用
```

### 5.2 模式 A：`dock-bar`（顶部贴边常驻）

```
收起态  h = 32
┌──────────────────────────────────────────────────────────────┐
│ ● 3/5   今日 +42                        ⋯        最近待办标题 → │
└──────────────────────────────────────────────────────────────┘
   x = 8, y = 0, w = screen.width - 16

展开态  h = 260（向下展开，不推挤屏幕内容）
┌──────────────────────────────────────────────────────────────┐
│ ● 3/5   今日 +42                        ⋯        最近待办标题 → │
├──────────────────────────────────────────────────────────────┤
│  ○ 报告初稿                                        30min     │
│  ● 客户回访                                        10:00     │
│  ○ 报销单                                          +20       │
│  ⋯ 最多 6 条                                                │
├──────────────────────────────────────────────────────────────┤
│  [+] 一句话加任务…                                    [↵]    │
└──────────────────────────────────────────────────────────────┘
```

- 顶部圆角只在下方两角（`border-radius: 0 0 14px 14px`），贴边感。
- hover 300ms 后展开（`hud.setExpanded(true)`），鼠标离开 500ms 后收起。用主进程控制窗口高度而非 CSS，否则窗口裁切。
- **必须处理**：展开时是否抢占焦点。默认 `focusable: true` 仅展开时；收起态 `win.setIgnoreMouseEvents(true, {forward:true})` 会让输入框不可用，所以改为收起态保留可点、只是高度小。
- 全屏应用检测：用户在全屏（游戏/视频/演示）时隐藏，退出全屏后恢复。策略在 `hud.autoHideFullscreen`。
  **v0.17：本轮不实现自动检测。** 纯 Electron 无原生依赖时拿不到"别的应用是否全屏"（`BrowserWindow.isFullScreen()` 只对自己窗口；`display.bounds` 与 `workArea` 比对只在任务栏自动隐藏的全屏场景有信号，borderless 全屏完全不触发）。先用 `pop-up-menu` 层级 + `[悬浮条开关]` 手动隐藏覆盖这个场景，`hud.autoHideFullscreen` 的 key 与默认值保留、标"未实现"，W10 真机评估是否引入原生模块。**不许写永远为 false 的假检测。**
- **v0.20：展开列表的行尾暂不实现。** 上图里的 `30min` / `10:00` / `+20` 本轮不显示，行只有标题——时间得联表取、分值要区分 `points_awarded` 与 `points_planned`（§4② 已说明两者可能不等），W10 打磨再补。上图保留为目标形态，不是当前实现的减配说明。

### 5.3 模式 B：`float-pod`（自由浮窗）

- 收起态：`56 × 56` 圆形，显示积分环（圆环进度 = 今日完成率）+ 右下角待办数角标。
- 拖动：整个圆可拖（`-webkit-app-region: drag`），松手 `hud.moveTo` 持久化坐标。
- 吸附：拖到距屏边 < 24px 时贴边，距顶/底 < 24px 时贴角。
- 点击（非拖动）→ 展开为 `360 × 480` 面板，从圆的位置向屏幕内侧弹出，面板内就是同一份 `HudPanel`（任务列表 + 输入框 + 今日积分）。
- 展开时窗体从 56×56 变 360×480，需重算坐标防溢出屏幕。
- 再次点击外部/ESC 收起为圆。
  **v0.20 实现口径**：Electron 感知不到"点在窗口外"，所以用窗口 `blur` 近似——点到 HUD 外面会失焦、切走别的应用也会失焦，两种都收起。副作用符合"点外部收起"的字面语义，可接受。

### 5.4 模式切换

`hud.setMode` → 主进程销毁旧 bounds 设置新 bounds（不重建窗口，避免闪烁）→ 广播 `hud.mode.changed` → 渲染层切换外壳组件。位置、展开态各自记忆。

### 5.5 悬浮窗内容来源

与主窗**同一份**数据，通过同一个 `DomainEvent` 流。悬浮窗启动时自己调 `app.getBootstrap` 拿全量，之后只靠事件增量。**不要**让悬浮窗去读主窗的 zustand。

### 5.6 悬浮窗的交互边界

允许：快速加任务（一句话，走 `msg.send`，AI 解析后草稿仍回主窗会话，悬浮窗只显示一条"已添加"的轻提示；**v0.17：`msg.send` 归 W4 未接，W4 之前改走已接的 `task.createManual` 直建 `deadline / medium / 无 due_at`，W4 接上后升级为 AI 解析**）、勾选完成、展开看列表、切换模式。

不允许：任务详情编辑、日历、积分明细、设置。这些一律回主窗。悬浮窗保持"一眼看完、一步操作"。

## 8. 响应式与多屏

- 主窗 `< 1000px` 时右栏自动收起为图标条（宽 `48px`，只留四个区块的图标，点开以浮层显示该区块）。窗口最小 `680px`，会话区 `min 520px` 与图标条并存不冲突。
- 悬浮窗跟随所在 `display` 的 `workArea`（不是 `bounds`，避开任务栏）。
- 显示器配置变化（插拔、分辨率改）时重算 bounds，越界则归位主屏顶部。
- DPI 缩放：所有像素值按 `devicePixelRatio` 由 Electron 处理，CSS 用 px 即可，但要测 125% / 150%。

## 9. 提醒的醒目程度（R15）

你要求"醒目"。醒目不等于"打断"——半夜弹个全屏遮罩会让人想卸载。所以做两级，默认第一级。

### 9.1 `normal`（默认）

触发时同时做四件事：

1. **HUD 变色 + 脉冲**：整条变 `--dot` 色，`2s` 内脉冲 3 次（`opacity 1→0.6`），若处于收起态则自动展开并保持 `8s`。
2. **会话注入**：会话流插入一条 `system/reminder` 居中细条，并自动滚到底（若用户正在输入则不抢滚动位置）。
3. **主窗提示**：若主窗处于最小化，`win.flashFrame(true)` 闪任务栏；若在前台，右栏 ① 对应任务行短暂高亮 `--dot` 描边。
4. **系统通知**：Windows toast，标题为任务标题，正文为偏移标签（如"前 1 小时"）。

### 9.2 `strong`（可选，需用户为单个任务开启）

在 `normal` 全部动作之上，追加：

- 一条横向横幅从屏幕顶部滑下（`height:64px`，全宽，`--dot` 底色），**不遮挡内容**，`15s` 后自动收，可手动 ✕。这是"醒目"但不阻塞的做法。
- 外部渠道强制发（即使该任务没配邮件 / 外部推送）。

**不做**全屏遮罩、不做必须点击才消失的模态、不做声音（除非以后单开一项）。理由：提醒的目的把人拉回来，不是惩罚他。

### 9.3 静默时段

`settings['reminder.quietHours']` 默认 `22:00–08:00`。落在其中的提醒：

- 不弹 toast、不推外部渠道
- 只在会话流留一条，HUD 不脉冲
- 顺延到 `08:00` 补一次 `normal` 提醒（只补最近的一条，不把整夜攒的 10 条一次刷出来）

### 9.4 提醒条目的样式

```
┌──────────────────────────────────────┐
│  ⏰  交物理作业 · 前 1 小时            │   ← 居中细条，14px，次级色
└──────────────────────────────────────┘
```

- 用 `--dot` 小圆点而非 emoji 图标，与日历红点同源。
- 可点击跳转到任务；hover 出现 `[稍后提醒]`（snooze 15 分钟）。
- 不加"别忘了""加油"这类文案，见 §1。
