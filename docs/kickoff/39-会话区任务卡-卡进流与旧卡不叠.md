## 1. 现状（已核实，别复读）

- 待提交卡：`ChatPanel` 在 `MessageList` 与 `ChatInput` **之间**渲染 `.submit-list`（`max-height: 42%`、独立区）。`pendingSubmit` 由 `useChatData` 从 `pending_review` 派生。
- `MessageList` 是自写窗口化（`messages` 数组 + `heights` map + 绝对定位 `Row`）。`ChatPanel` 顶部的注释写着 36 §7 的结论：塞非消息内容进去会把测量搞坏。**所以这次不是搬 div，是给它加一个参与测量的末尾行。**
- 旧审核卡：`reviewViews.isLatest` 只让旧卡「不显示按钮」，卡本身照渲染 → 同一任务上下堆两张（截图）。
- 取消 / 通过：`pendingList` 与 `taskById` 都是派生量与按需 `task.get` 缓存，取消后卡自然消失、任务 `done` 后仍拉得到 → **这两条现状已满足，改造后不许退化**。
- 滚动条：`.msg-scroll` 与任务列表都只有 `overflow-y: auto`，没有 `::-webkit-scrollbar` → 走 Chromium 默认 ~15px。

## 2. 待提交卡进对话流

**`MessageList.tsx` 加 `tail` 插槽**

- 新增可选 prop `tail?: ReactNode`。
- 它作为**额外一行**渲染在所有消息之后，用与消息行同一套 `Row`（同一个 `ResizeObserver` 测量），行 id 用文件内常量（如 `'__tail__'`），高度存进同一个 `heights` map。
- **高度必须计入 `total`**：`total` = 所有消息高度累加 + tail 高度（无 tail 时为 0）。否则 `msg-spacer` 撑不开、滚不到底、`indexAt` 越界。
- 无 tail 时，`total`、`first`/`last`、`scrollTop` 行为与现在**完全一致**。
- tail 的 key 固定，**不随待提交条数变化**——否则每加一条就整行重测、滚动位置抖动。

**`ChatPanel.tsx`**

- 删掉 `.submit-list` 容器与它的渲染位置。
- `pendingSubmit.length > 0` 时，把整组 `SubmitCard` 作为 `tail` 传入；多条时纵向排列、间距 8px。
- **tail 自己不滚动**，滚动交给 `.msg-scroll`。

**`chat.css`**：删 `.submit-list` 整条规则（不留死样式）。`SubmitCard` 卡面（`border` / `radius` / `padding`）不变。

## 3. 同一任务只留最新一张审核卡

把过滤逻辑写成**纯函数**放 `chatViewModel.ts`（`tsconfig.test.json` 没有 DOM，hook 测不了；已有 `toEvidenceViews` 先例）：

- 输入：`Message[]`；输出：过滤后的 `Message[]`。
- 规则：倒序扫出每个 `meta.kind === 'task_review'` 的 `taskId` **最后一条**消息 id；正序输出时，审核消息只有 id 命中才保留，其余丢弃；非审核消息全部保留。
- 语义命名清楚（如 `latestReviewOnly`），入参出参都是不可变。

`useChatData` 用它派生 `visibleMessages`；`ChatPanel` 改传 `visibleMessages` 给 `MessageList`。

- **`messages` 本身不动**（翻页与 `loadMore` 的拼接还靠它），只过滤渲染数组。
- `reviewViews` 构造**不改**（已按 message.id 索引，过滤后自然只剩最新的有 view）；`isLatest` 字段保留。

## 4. 无证据时的一行小字

`SubmitCard.tsx` 的 `.review-actions` 内，`evidence.length === 0` 时在**按钮组左侧**渲染：

- 文字：**`还没有证据`** —— 就这四个字，不加标点、不加第二句。
- 位置：同一行最左（`margin-right: auto`），按钮仍在右侧。
- 样式：`--text-faint`、12px、`white-space: nowrap`。
- 证据数 ≥ 1 时**不进 DOM**（不是隐藏、不是 `opacity: 0`）。
- 不许改 `[提交]` 的 `disabled` 逻辑，不许加别的文字。

## 5. 滚动条

只加在这两处，**不加全局规则**，不碰 HUD / 日历 / 积分：

- `chat.css` 的 `.msg-scroll`
- `tasks.css` 里任务列表的滚动容器（就是 `overflow-y: auto` 那个）

规格（两处一致）：

- 宽 `6px`、高 `6px`；轨道透明。
- thumb：`rgba(0, 0, 0, 0.16)`、`border-radius: 3px`、无边框。
- thumb hover：`rgba(0, 0, 0, 0.28)`。
- 不要箭头按钮（`::-webkit-scrollbar-button { display: none }`）。

## 8. 验收（三条）

1. **卡在流里**：点完成 → 卡出现在对话流末尾（与消息同列），不再有独立分隔区；传图 → `[提交]` 变亮；多条待提交时依次排列，能滚到底。
2. **小字**：不传图时 `[提交]` 左侧有 `还没有证据`；传图后这行消失。
3. **旧卡消失**：同一条任务连审两次 → 对话流里只剩最新那张审核卡，旧的没了；**另一个任务**的卡不受影响。另一条任务走完取消 → 它的卡直接消失；走完通过 → 卡仍在。
