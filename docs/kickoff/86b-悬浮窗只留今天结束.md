## 问题（用户 2026-11-07 报障，已取证）

用户要求悬浮窗「只留今天和往后 7 天」，但今天上午仍看到昨天及更早的已完成/失败任务。

根因是 86 单的一行实现（`src/renderer/hud/hudModel.ts`）：

```ts
if (task.status === 'done' || task.status === 'missed') return true
```

86 施工词的原文是「`status` 是 `done` 或 `missed` → **保留**（**今天**刚结束的必须看得见，不受窗口限制）」，括号里的「今天」没有被实现出来。于是：

- 首载补拉（`mergeTodayFinished`）当天筛过的行，进入快照后**跨天不消失**；
- 会话期间的 `task.updated` 事件推进来的 `done`/`missed` 同样永久留在列表里；
- 真实库取证：今天 `2026-11-07`，悬浮窗里仍能命中 `updated_at` 为 `11-01` / `11-03` / `11-05` / `11-06` 的 `done` / `missed` 行。

第二个连带问题：`useHudData.ts` 里 `const today = localDayOf(new Date())` 是**每次渲染现算**，但没有任何机制在零点触发一次渲染。悬浮窗挂着过夜，即便过滤规则正确也不会重算。

## 一、`hudModel.ts`：done/missed 加「今天」限定

`withinHudWindow(tasks, today)` 里第一条规则改成：

- `task.status === 'done' || task.status === 'missed'` → 仅当 `localDayOf(new Date(task.updatedAt)) === today` 时保留，否则丢弃
- 用文件里已有的 `localDayOf`（`@shared/localDay`，本文件已 import `toLocalDay`，同源新增一个 import 即可）
- 其余两条规则**一个字不动**：`dueLocalDay(dueAt) === null` 仍然保留；其余仍按 `today <= dueDay <= today+7`
- 注释写清三件事：①「今天」指 `updatedAt` 落在本地今日（跨天就该沉掉）；②86 单漏了这层限定，用户 2026-11-07 报障；③历史 `done`/`missed` 在悬浮窗不显示不等于数据没了，主界面照旧

## 二、`useHudData.ts`：跨零点重算 `today`

现在是：

```ts
const today = localDayOf(new Date())
```

改成组件内的状态 + 定时重算：

- `const [today, setToday] = useState(() => localDayOf(new Date()))`
- 新增一个 `useEffect`（空依赖数组）：
  - 计算到「下一个本地零点 + 2 秒」的毫秒差，`setTimeout` 到点后 `setToday(localDayOf(new Date()))`，然后**重新排下一次**（递归排程，允许函数自调用）
  - 组件卸载时 `clearTimeout`，并清掉下面的事件监听
  - 同时监听 `window` 的 `focus` 事件，触发时也执行一次 `setToday(localDayOf(new Date()))`（兜机器休眠跨零点、定时器被节流的情况）
- `rows` 的 `useMemo` 依赖数组保持 `[snapshot.occurrences, snapshot.tasks, today]`，不增不减
- **不许改** `handleEvent` 的任何一个分支、不许改 `mergeTodayFinished`（它内部自己算今天，与本单无关）

注意：`rows` 的分母/分子（`total` / `done`）都由 `rows` 派生，会自动跟着变，**不要**另算。

## 三、测试

### 3.1 必红点（现有断言与新规则相反，必须改写）

`tests/renderer/hudModel.test.ts` 里这条用例的语义**反了**：

```ts
it('done / missed 的旧任务不受窗口限制', () => {
  const tasks = [
    makeTask({ id: 'done', title: '完成', status: 'done', dueAt: '2026-01-01' }),
    makeTask({ id: 'missed', title: '失败', status: 'missed', dueAt: '2026-01-02' })
  ]
  expect(withinHudWindow(tasks, TODAY).map(t => t.id)).toEqual(['done', 'missed'])
})
```

改成「done / missed 只保留今天结束的」，断言三件事：

1. `updatedAt` 落在今天（用 `new Date(2026, 9, 28, 10).toISOString()` 这类**本地构造再转 ISO** 的写法，别写死 `Z` 时间，否则在非 +8 时区会差一天）→ 保留
2. `updatedAt` 落在昨天（同上构造 `new Date(2026, 9, 27, 10)`）→ 丢弃
3. 一条 `dueAt` 是很久以前、但 `updatedAt` 是今天的 `missed` → 保留（证明判定看的是 `updatedAt`，不是 `dueAt`）

`makeTask` 的默认 `updatedAt` 是 `'2026-10-28T00:00:00.000Z'`（本地 `10-28 08:00`，与 `TODAY = '2026-10-28'` 同日）。**不要**依赖这个巧合，用例里显式传 `updatedAt`。
