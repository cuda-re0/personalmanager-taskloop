# 55 · 更正：日历日视图只显示每日任务，方向反了（v0.55b）

> **类型**：缺陷更正（架构方直接实施，未走外部施工方）。
> **起因**：用户 2026-11-01 19:49 截图报「怎么只显示每日任务呢，不应该是只不显示每日任务吗」——11 月 1 日的日视图里只有「23点前睡觉」，而红点在 3 / 10 / 13 / 17 号。

## 1. 现象与根因

点某天后，日历层（③④ 位置）列出的全是每日任务的打卡行，限时 / 活动任务一条都不出现。

**根因是契约自相矛盾，不是实现把过滤写反了：**

| 位置 | 原文 | 说明 |
|---|---|---|
| 04 §4② 第 500 行（v0.28 裁决） | 该日任务列表**沿用 `occurrence.listByRange(day, day)`**，每行 = 完成状态勾 + 标题 | 实现照着这条做了 |
| 04 §4② 第 510 行 | **日历只呈现限时与活动。** 每日任务不进日历、不点红点（Q2 已定） | 与上一条直接冲突 |

而红点走的是 `calendar.dayIndex`，SQL 里写死 `type IN ('deadline','event')`。两边口径不一致，于是出现**「3 号有红点、点开却什么都没有」**——用户看到的正是这个。

`calendar.dayDetail`（同样是 `type IN ('deadline','event')`）从做完起就没有任何调用方，是个死通道；`calendarModel.ts` 里为它准备的 `sortDayDetail` / `floorTitle` 一直留着。

## 2. 改动

| 文件 | 改动 |
|---|---|
| `useCalendarData.ts` | `useDayOccurrences` → **`useDayTasks`**，走 `window.api.calendar.dayDetail({ day })`，结果过 `sortDayDetail` 兜底；事件订阅去掉 `occurrence.*`（每日任务不再影响本层）。删掉 `DayViewRow` 与 `dayViewRows` |
| `CalendarDayView.tsx` | 行 = **时刻 · 标题 · 类型 · 分值**（`row.time` 为空串时不渲染时刻位），类型标签复用 `TYPE_LABEL`、分值复用 `fmtPoints`；已完成用 `row.status === 'done'` 加 `.calendar-row--done`（整行降透明），**不再画勾** |
| `calendar.css` | 新增 `.calendar-row-time` / `.calendar-row-type` / `.calendar-row-points`（小字弱色、等宽数字）；删掉 `.calendar-dayview .task-check` 那条已成死规则的覆盖 |
| `tests/renderer/calendarDayViewWiring.test.ts` | 行结构断言改为时刻/类型/分值；零请求断言改盯 `.dayDetail(` 唯一；**新增一条**「日历层不拉 occurrence」 |
| `docs/04-UI-SPEC.md` | 第 500 行改写为 `calendar.dayDetail`，并注明 v0.28 那条与本文件末尾第 510 行的冲突 |

## 3. 口径（写死，别再改回去）

- 日历里**只出现** `deadline` / `event`。每日任务归 ① 区「每日」组与会话管理。
- 红点（`dayIndex`）与日视图（`dayDetail`）必须同源，否则必然出现"有红点却点开空"。
- 每日任务的打卡**不在日历里做**，本层不再有勾选控件。

## 4. 验收

1. 点 11-03（截图里有红点那天）→ 列表出现那天的限时 / 活动任务，每行带时刻、类型、分值。
2. 点 11-01 → 列表为空（那天只有每日任务「23点前睡觉」，它不该出现）。
3. 已完成的行整行变淡，但没有「已完成」字样。
4. 点行 → ① 区对应任务高亮，日历层不关闭。
