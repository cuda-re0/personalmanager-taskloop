## B 常量与规则（写死，不许自由发挥）

**B1 预设值（2026-11-05 官方核实，不许改）**

```
zhipu:    baseUrl  https://open.bigmodel.cn/api/paas/v4
          task     glm-5.3-flash
          chat     glm-4.7-flashx

deepseek: baseUrl  https://api.deepseek.com
          task     deepseek-flash
          chat     deepseek-flash
```

- `deepseek-chat` / `deepseek-reasoner` 已于 2026-07-24 弃用、不在官方模型列表，**不许**用它们
- 现行只有 `deepseek-flash` 与 `deepseek-v4-pro`。选 `deepseek-flash` 的依据：支持图片输入（审核要看证据图）、支持 `json_object`（parse / review 依赖）、单价最低
- baseUrl **不带 `/v1`**：官方 OpenAI 格式就是裸域名，`endpointOf()` 自己抢 `/chat/completions`
- 事实备注（本单不处理）：DS 的 thinking 模式默认开启，解析会比智谱慢；thinking 下 `temperature` 无效。本单只做供应商切换，不碰请求体

**B2 `vendorOf` 归一化**

```
s = baseUrl.trim().toLowerCase()，再去掉结尾所有 '/'
s === ''                    → null
s 含 'open.bigmodel.cn'     → 'zhipu'
s 含 'api.deepseek.com'     → 'deepseek'
其余                        → null
```

- 用子串匹配，**不许**用 `new URL()`（用户可能填半截地址，解析会抛）
- 它只负责画高亮，判错最多是按钮不亮，不影响实际请求

**B3 保存语义**

点按钮**只改草稿不写库**，仍要点「保存」。理由：切换供应商后 Key 必须重填，两步分开才不会把“新地址 + 旧 Key”的坏组合静默写进库。

**B4 明确不做（越界即返工）**

- 不改 `ai.provider.name`（死字段，全仓无读取）
- 不加第二个 Key 文件、不做双 baseUrl
- 不改 `glmClient` 的请求体（DS 兼容 `response_format` 与 `reasoning_effort`，无需特判）
- 不碰 `dist/`、不跑 `npm run pack`
