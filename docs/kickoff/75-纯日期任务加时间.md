## 背景

限时/活动任务的 `due_at` 有三档精度，按字符串形状判定（`src/shared/due.ts:6`）：

- `2026-11-06` → `day`（只知道哪天）
- `2026-11-06T06:30:00.000Z` → `minute`（有真实时刻）

v0.66 的编辑入口是**单框分流**：`minute` 给 `datetime-local`，`day` 给 `date`。于是「完成压电换能器实验（11-06）」这类任务点开只有日历，**没有任何地方能补一个具体时刻**，而实验、作业往往是有时间的（下午两点、晚上八点）。

用户要求：这类只有日期的任务，也要能加时间。

**做法**：行内与详情都改成「日期框 + 时间框」并排。时间留空 = 仍是纯日期（`day` 精度，`due_at` 原样写回）；填了时间 = 升级成 `minute` 精度（本地解析后 `toISOString()`）。**绝不允许**因为出现了时间框就给空时间补 `23:59`。

### A. `src/renderer/main/features/tasks/tasksModel.ts`

```
 *  不再决定控件类型——两处编辑都是「日期 + 时间」两个框，时间可留空。 */
```

A3. 新增三个导出：

```ts
/** 日期框 value：`YYYY-MM-DD`。minute 取本地日期，day 取原串前 10 位；month / null → '' */
export function dueDateValueOf(dueAt: string | null): string

/** 时间框 value：`HH:mm`。day / month / null → ''（没有时刻就是空，不许补 23:59） */
export function dueTimeValueOf(dueAt: string | null): string

/** 日期 + 时间 → 写库的 dueAt。time 为空 → date 原样返回（day 精度）；否则本地解析后 toISOString()（minute 精度） */
export function duePatchOfParts(date: string, time: string): string
```

实现约束，逐条写死：

1. `dueDateValueOf`：
   - `duePrecisionOf` 为 `minute` → `toDatetimeLocal(dueAt).slice(0, 10)`
   - 为 `day` → `(dueAt as string).slice(0, 10)`（**不绕 Date**）
   - `month` / `null` → `''`
   - **禁止**写成 `new Date(dueAt).toISOString().slice(0, 10)`：那按 UTC 取日，东八区 00:30 的任务会串到前一天。
2. `dueTimeValueOf`：
   - `minute` → `toDatetimeLocal(dueAt).slice(11, 16)`
   - 其余（`day` / `month` / `null`）→ `''`
3. `duePatchOfParts(date, time)`：
   - `time === ''` → 返回 `date` 原样（不加 `T00:00`、不加 `T23:59`、不转 Date）
   - `time !== ''` → `new Date(`${date}T${time}`).toISOString()`（`YYYY-MM-DDTHH:mm` 按本地时区解析，与 `toDatetimeLocal` 同一口径）
   - `date === ''` 时返回 `''`（调用方会先早退，这里只做兜底，不抛错）

A4. `canEditDueOf` 一字不改。
