### B3 校验（全部抛 `appError('INVALID_INPUT', ...)`，消息逐字写死）

| 条件 | 消息 |
|---|---|
| `title.trim() === ''` | `标题不能为空` |
| `title.trim().length > 40` | `标题不能超过 40 个字` |
| `intervalMinutes` 非整数 / < 1 / > 1440 | `间隔必须在 1 到 1440 分钟之间` |
| `windowStart` 与 `windowEnd` 一个有一个没有 | `提醒区间要么都填，要么都不填` |
| 非空时格式不是 `HH:mm`（正则 `^([01]\d|2[0-3]):[0-5]\d$`） | `时间格式应为 HH:mm` |
| `setEnabled` / `remove` 找不到 id | `这一项不存在` |

- `title` 存 `trim()` 之后的值
- 新增时 `lastFiredAt = null`、`enabled = true`
- `windowStart === windowEnd` **允许**，语义等同全天（见 B4）

### B4 两个纯函数（必须单独导出，供测试直接调）

```ts
export function inWindow(hhmm: string, start: string | null, end: string | null): boolean
export function isDue(pulse: Pulse, now: Date): boolean
```

`inWindow` 判定顺序写死：

1. `start === null || end === null` → `true`
2. `start === end` → `true`
3. `start < end` → `start <= hhmm && hhmm < end`
4. `start > end`（跨午夜）→ `hhmm >= start || hhmm < end`

`isDue` 判定顺序写死：

1. `!pulse.enabled` → `false`
2. `!inWindow(本地 HH:mm, windowStart, windowEnd)` → `false`
3. `pulse.lastFiredAt === null` → `true`
4. 否则 `now.getTime() - Date.parse(pulse.lastFiredAt) >= pulse.intervalMinutes * 60_000`

本地 `HH:mm` 取法：`now` 按本机时区格式化成 `HH:mm`（两位补零）。**不许用 UTC**。

### B5 调度器（`pulseScheduler.ts`）

```ts
export const PULSE_TICK_MS = 20_000
export function startPulseScheduler(): () => void
```

- 照 `reminderScheduler.ts` 的写法：`setInterval(run, PULSE_TICK_MS)`，返回 `stop()`（内部 `clearInterval`）
- **启动时不补发**：错过的次数一律不弹，只等下一个 tick 自然到期。这点与 `reminderScheduler` 的补发逻辑相反，别照抄那段
- `run()` 整个包在 `try/catch` 里，单轮异常只 `console.warn('[pulse] 本轮扫描失败', e)`
- 每轮：取所有 `enabled = 1` 的项 → 逐个 `isDue` → 到期的调用 `firePulse`

`firePulse(pulse, now)` 的动作与**顺序**写死（对齐 `reminderService.fireOne` 的口径）：

1. `messageService.appendMessage({ threadId: 'main', role: 'system', kind: 'reminder', mode: 'task', linkedTaskId: null, meta: { kind: 'reminder', reminderId: pulse.id, taskId: null, title: pulse.title, fireAt: now.toISOString(), offsetMin: null } })`
2. `broadcast({ type: 'message.appended', message })`
3. `pulseRepo.markFired(pulse.id, now.toISOString())`
4. `showMainWindow()`（`windowManager` 那个导出）

**顺序不许反**：消息落库成功之后才写 `last_fired_at`。第 1 步抛错就整条跳过、不写 `last_fired_at`，下一轮 tick 会再试。

第 4 步每轮最多调一次（同一 tick 里多条到期，只在第一条后调）。**不要**用 `app.dock.bounce` 之类的新 API，项目里没有先例。
