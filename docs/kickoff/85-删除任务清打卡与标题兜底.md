## §0 三条现象（用户真机验出，已核代码 + 已核库）

用户点「删除」之后：任务行还在 → 还能点勾完成 → 完成后拿到 1 分 → 行依然在，只是标题空了。

已在用户库里取到实证：两条 `status='discarded'` 的任务，今天的 `task_occurrences` 仍是 `done`；`point_ledger` 里有对应的 `+1 task_done`。

| 编号 | 现象 | 根因 |
|---|---|---|
| A | 删除后任务行仍出现在今日列表 | `taskService.removeTask` 只 `softRemove`（写 `status='discarded'`），**不动 `task_occurrences`**；今日列表由 `occurrenceRepo.listByDay` join tasks 得来，**不过滤任务状态** → 行照样在 |
| B | 已删除的任务还能点勾、还能得分 | `pointsService.awardOccurrence` 只 `requireById` 任务与 occurrence，**不校验 `task.status`**；`stateMachine` 也管不到这条路径（打卡不迁任务状态） |
| C | 完成/删除之后行标题变成空串 | `occurrenceRepo.update` 返回的 `Occurrence` 由 `requireById` 得来，**没有 `taskTitle`**（join 才带）；`occurrence.updated` 广播的就是它，渲染层 `mergeTodayOccurrences` 又用 `map.set(o.id, o)` **整体替换**旧对象 → `taskTitle` 丢；任务在 `tasks` 里还能查到时有 `task?.title` 兜底，删除后查不到 → `occurrence.taskTitle ?? task?.title ?? ''` 得到空串 |

C 不是删除独有的：任何 daily 打卡都会让该行短暂丢 `taskTitle`，只是有 `task?.title` 兜着看不出来。HUD 侧早就撞过同一个坑（`src/renderer/hud/useHudData.ts:115` 有专门的保留补丁），任务面板没有。

## §1 A：删除任务时清掉「今天及以后、未完成」的打卡行

### 1.1 `occurrenceRepo` 新增一个函数

```
/** 删除某任务 fromDay 当天及以后、状态不是 done 的 occurrence；返回删除行数 */
export function removeUnfinishedFrom(taskId: string, fromDay: string): number
```

SQL 语义：

```
DELETE FROM task_occurrences
 WHERE task_id = ? AND day >= ? AND status <> 'done'
```

**为什么保留 `done`**：`point_ledger.occurrence_id` 的外键是 `ON DELETE SET NULL`，删掉已完成的 occurrence 会让那条流水丢掉「对应哪一次打卡」的线索，对账说不清。已完成的打卡是既成事实，不因为后来删任务就抹掉。

**为什么 `status <> 'done'` 而不是只删 `pending`**：`skipped` / `missed` 都属于「没发生」的行，留着只会在别的查询里冒出来。统一「非 done 全删」。

### 1.2 `taskService.removeTask` 改成事务

现状是一行 `taskRepo.softRemove(id, nowIso())`。改成：

```
export function removeTask(id: string): void {
  return tx(() => {
    const now = nowIso()
    taskRepo.requireById(id)                 // 不存在 → NOT_FOUND，保持在改状态之前
    taskRepo.softRemove(id, now)
    occurrenceRepo.removeUnfinishedFrom(id, todayLocalDay())
  })
}
```

写死的边界：

- `requireById` 必须在 `softRemove` **之前**：先确认存在，再改状态，最后清行，任一步失败整笔事务回滚。
- 不改 `removeTask` 的签名（仍是 `void`），不改 `CH.task.remove`、不改 `guards`、不改 preload。
- 不删历史（`day < today`）的 occurrence，也不删任何 `done` 行。

## §2 A：今日列表过滤已丢弃任务

`occurrenceRepo.listByDay` 的 WHERE 加一条：

```
AND t.status NOT IN ('discarded', 'archived')
```

- **只改 `listByDay`**。`listByRange` 一个字不动——用户已裁决「日历保留历史打卡」，删掉的任务在日历上仍要看得见。
- `listByTask`、`countByTask`、`markMissedBefore` 不动（统计与 streak 反查要用全量历史）。
- `OCCURRENCE_COLUMNS_JOINED` 已经 join 了 `tasks t`，不需要改 join。

效果：今日列表（`occurrence.today` → `listToday` → `listByDay`）不再出现已删任务的打卡行；HUD 走同一条链路，也一并干净。

## §3 B：已删除的任务不许打卡得分

`pointsService.awardOccurrence` 在拿到 `taskBefore` 之后、算 streak 之前加一道闸：

```
if (taskBefore.status === 'discarded' || taskBefore.status === 'archived') {
  throw appError('CONFLICT', '任务已删除', { detail: `task=${taskBefore.id} status=${taskBefore.status}` })
}
```

- 抛在 `tx()` 内部，整笔事务回滚：不写流水、不改 occurrence、不动 streak、不加 `daily_stats`。
- 只加在 `awardOccurrence`。`skipOccurrence` / `undoOccurrence` **不加**：撤销必须永远可用（要能冲销流水），跳过写一条 skipped 也无害。
- 错误文案固定为 **「任务已删除」**，这是本单唯一新增的界面中文串，写进 §5 白名单。

## §4 C：广播载荷缺 `taskTitle`，渲染层要兜住

只改渲染层，**不动主进程的广播**（改广播要连带改 `Occurrence` 的构造路径，面更大）。

`src/renderer/main/features/tasks/useTasksData.ts` 的 `mergeTodayOccurrences`：

现在 incoming 是 `map.set(o.id, o)`，整体替换。改成**保留旧值**：

```
for (const o of incoming) {
  if (o.day !== today) continue
  const prev = map.get(o.id)
  map.set(o.id, o.taskTitle === undefined && prev ? { ...o, taskTitle: prev.taskTitle } : o)
}
```

规则写死：**只补 `taskTitle`，其它字段一律用 incoming 覆盖**。不要顺手补 `taskType`，也不要改成合并整个对象——其它字段（status / pointsAwarded / completedAt）必须是最新的。

### 4.1 顺带一处：删除后今日列表要立即刷新

同一个 `switch` 的 `task.removed` 分支现在只 `reloadTasks()` + `reloadDoneTasks()` + `reloadMissedTasks()`。加一行 `reloadOccurrences()`。

- 只加在 `task.removed` 分支。`task.updated` 分支**不要加**（每次改任务都多打一次 IPC，现有注释明确写了不加）。
- 位置：与另外三个 reload 并列。
