# 27 · P0：生产产物里 connection 模块被打成两份，IPC 全瘫

基线 `d8bfb9f`。单开跑，别和 UI 单并行（会同时 build）。

## 现象（已由架构方在产物里复现，不是猜测）

`npm run build` 出来的 `out/main/index.js` 里有**两份** `connection` 模块：

```
:328   let current$1 = null          ← 副本 A 的连接变量
:380   function initDb$1(file)       ← 写 current$1
:7075  initDb$1()                    ← 入口 whenReady 调的是 A
:2344  let current = null            ← 副本 B
:2408  function getDb()              ← repo 全部调用 B，读 current
:7079  createHudWindow()             ← resolveLayout → getDb 抛「数据库尚未初始化」
:7080  registerIpcHandlers()         ← 因上一行同步抛，永远执行不到
```

后果：双击 `启动.cmd`（它会先 build 再跑）打开的应用，窗口在、数据全空，所有 IPC
都是 `No handler registered`。dev 模式同样有双副本（施工方已验证），只是 dev 少了
`createHudWindow` 的同步路径时未必每次都炸。

注意：`initSql` 这类模块级常量只有一份，函数却成对出现——说明不是两个文件，而是
**同一个 `src/main/db/connection.ts` 被 rollup 当成两个 module id 加载了两次**。
`function migrate` / `function applyPragmas` / `function appError` 等也都有两份，复制
范围覆盖 `db/**` 整个域。

## 任务

1. **定位**：为什么同一文件有两个 id。首要怀疑——入口 `input` 用的是绝对路径
   `resolve('src/main/index.ts')`，而模块内 import 全走相对路径；本机工作区路径含中文，
   Windows 下的大小写/规范化差异可能让 rollup 拿到两个 id。验证方法：把 `input` 改成
   相对字符串 `'src/main/index.ts'`，build 后看 `grep -c "function getDb"` 是否变 1。
   其他可能：alias 与相对路径混用（`@shared` 之外是否还有别名）、`?raw` 之类带 query 的
   import、node_modules 里同名模块被 externalize 边界切开。
2. **修根因**，不许改产物、不许在 `out/**` 里打补丁、不许为了绕过而删 `treeshake: false`
   （那条是 W1/W2 空壳函数的既定要求，动它会让接线点被摇掉）。
3. 如果修法必须动 `src/main/**` 的 import 写法，**在报告里逐个列出**，别顺手改业务逻辑。

## 算过

- `out/main/index.js` 里 `function getDb`、`function initDb`、`function migrate`
  各 **1 份**；`function initDb$1` 等带 `$1` 的域内函数**0 份**。
- `npm run build` + 隔离 userData 起 `electron .`：窗口有数据（任务列表能渲染，
  控制台无 `No handler registered`），建一条任务成功落库。
- 四命令绿（当前 47 文件 / 562 条）。
- 白名单：`electron.vite.config.ts`（或定位到的构建配置）+ 必要时 `src/main/**` 的 import 行；
  `src/renderer/**`、`docs/**` 一律不动。
