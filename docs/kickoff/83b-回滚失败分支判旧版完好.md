## §0 为什么要改（83 审出来的缺口）

83 落地后，`applyUpdate` 的失败分支是这么判的：

```
const rolledBack = covered ? false : rollbackInstall(resourcesApp)
if (!covered && !rolledBack) { 不 relaunch、不 quit、return }
```

但 `rollbackInstall` 的第 1 步是「`out.bak` 不可读 → 直接 `return false`，一个目录都不动」。而**最常见的回滚失败恰好是「备份没了、旧版还在」**：覆盖时先 `rmSync(outBak)` 再 `renameSync(outDir, outBak)`，只要那一步改名失败（文件被占、权限），`out` 仍是**完好的旧版本**、`out.bak` 已不存在 —— 于是 `rolledBack === false`，程序被判定成「回滚也失败」，把窗口全销毁、进程留在后台。用户看到的是「更新到一半窗口全没了」，而实际上旧版一点没坏，本该照常重启。

一句话规则：**回滚没做成，先自己看一眼现在的 `out` 还能不能用。能用就按回滚成功处理（重启），不能用才走不重启分支。**

## §1 判定函数

在 `updateService.ts` 里新增并**导出**（导出是为了单测能直接钉它，与 83 的 `REQUIRED_FILES` 同理）：

```
export function isInstallIntact(resourcesApp: string, version: string): boolean
```

判定为 `true` 当且仅当两条同时成立：

1. `missingCritical(resourcesApp)` 返回空数组（用的是默认清单 `REQUIRED_FILES`，即相对 `resources/app` 的 `out/...`）
2. `versionOf(join(resourcesApp, 'package.json')) === version`

任一不成立返回 `false`。**不许**吞异常、不许把 `missingCritical` 里 `statSync` 的失败当成通过——`missingCritical` 已经把读不到算作缺失，直接用它的返回值。

## §2 `applyUpdate` 的接入（两处，别多改）

### 2.1 先取当前版本

`applyUpdate` 函数体开头、**任何文件操作之前**，取一次运行中程序的版本：

```
const currentVersion = app.getVersion()
```

必须在这里取：覆盖会把新的 `package.json` 拷进去，之后再读就不是「旧版」了。

### 2.2 失败分支的判定

把现在的：

```
const rolledBack = covered ? false : rollbackInstall(resourcesApp)
if (!covered && !rolledBack) { …不重启… }
```

改成三段语义（伪代码，实现自己写）：

```
const rolledBack = covered ? false : rollbackInstall(resourcesApp)
const intact     = covered || rolledBack ? false : isInstallIntact(resourcesApp, currentVersion)

if (!covered && !rolledBack && !intact) {
  // 真·双失败：out 与备份都不可用
  原有逻辑（app.off('before-quit', holdQuit) + console.error + return）
}

if (intact) {
  console.warn('[update] 回滚未完成，但旧版仍完好（关键资源齐全、版本 ' + currentVersion + '），按回滚成功处理')
}

app.off('before-quit', holdQuit)
app.relaunch()
allowQuit = true
app.quit()
```

写死的边界：

- `intact` 只在 `covered === false && rolledBack === false` 时才需要算；`covered` 或 `rolledBack` 为真时**不要**多跑一次目录扫描。
- 三分支的其余动作一个字不改：成功/回滚成功仍是 `relaunch → allowQuit = true → quit`，真·双失败仍是 `off` + `console.error` + `return`（不 `relaunch`、不 `destroy`、不 `quit`）。
- `holdQuit` 的挂载/摘除、`allowQuit` 的语义、`relaunch` 只调一次，全部保持 83 现状。
- 日志里**不许新增任何界面中文串**；控制台日志可写路径与版本号。
