## 交付

1. **`hudService`**：持有 `{ mode, expanded, visible, displayId, bounds }`，所有变更都经它（渲染层只调通道，不直接算坐标）。持久化：`hud.mode` / `hud.displayId` / `hud.position`（float-pod 坐标）/ `hud.expanded`。
2. **`dock-bar`**：贴边常驻，收起 `h=32`、展开 `h=260`；hover 300ms 展开、离开 500ms 收起（计时在渲染层，见下"三个坑"）；展开高度由主进程 `setBounds`，**不许用 CSS 改高度**（窗口会裁切）。
3. **`float-pod`**：收起 56×56 圆（积分环 = 今日完成率，右下角待办数角标）；展开 360×480 面板，从圆的位置向屏幕内侧弹（方向算法见下）；吸附阈值 24px；位置记忆。
4. **五条通道**：`setMode`（换 bounds + 广播 `hud.mode.changed`，不重建窗口）/ `setExpanded`（两模式通用）/ `moveTo`（clamp + 落库）/ `setVisible`（`win.hide()/showInactive()`）/ `getState`（含 `visible`）。
5. **`HudPanel` 组件**：两模式共用一份，外壳不同。内容：`● 3/5`（今日 occurrence 完成数/总数）、`今日 +42`（`today.points`，不自己算）、最近待办标题、展开后的任务列表（最多 6 条）+ 一句话输入框。
6. **顶栏开关**：`AppHeader` 56px，左应用名、右 [悬浮条开关]，切换调 `hud.setVisible`；初次挂载用 `hud.getState().visible` 定初始态。
7. **多屏 / DPI**：启动按 `hud.displayId` 找显示器，找不到（拔屏）回落主屏；`screen.on('display-removed' | 'display-metrics-changed')` 后重新 clamp。
8. **HUD 内的写操作**（只这两类，04 §5.6）：
   - 勾选每日任务 → `occurrence.complete({ id })`；限时/活动 → `task.complete({ id, quality: 'met' })`（与 W6 右栏 `[完成（计分）]` 同参数）。失败时把 `error.message` **原样**显示在一条轻提示里（都是 04 §1.1 登记过的串），不自己造文案。
   - 一句话加任务 → `task.createManual`（已接），落 `deadline / medium / 无 due_at`。04 §5.6 原写"走 `msg.send`"，但 `msg.send` 归 W4 未接，v0.17 已改口径：W4 接上后升级为 AI 解析，本轮直建。

## 尺寸与坐标（照抄，别自己发明）

统一用 `display.workArea`，**不是 `display.bounds`**——`bounds` 含任务栏区域，用它会压到任务栏下面。04 里写的 `y = 0` 是"任务栏在下方"时的等价值，以 workArea 为准。

| 形态 | x | y | w | h |
|---|---|---|---|---|
| dock-bar 收起 | `workArea.x + 8` | `workArea.y` | `workArea.width - 16` | `32` |
| dock-bar 展开 | 同上 | 同上 | 同上 | `min(260, workArea.height - 8)` |
| float-pod 收起 | 记忆坐标，无则 `workArea.right - 56 - 24` | 记忆坐标，无则 `workArea.y + 24` | `56` | `56` |
| float-pod 展开 | 见下 | 见下 | `360` | `min(480, workArea.height)` |

float-pod 展开方向（"向屏幕内侧弹"）：

```
水平：圆在屏幕右半 → panelX = podX + 56 - 360（以圆右边缘为基准向左长）
      圆在屏幕左半 → panelX = podX（向右长）
垂直：podY + 480 超出 workArea 底部 → panelY = workArea.y + workArea.height - 480（向上收）
最后整体 clamp 进 workArea（x/y 双向）
```

吸附（松手后）：距左/右边缘 < 24px → 贴边；距顶/底 < 24px → 贴角。吸附后再 clamp 一次。

## 三个必须按此实现的坑

1. **`-webkit-app-region: drag` 会吞掉点击**。收起态的圆整块可拖，但 drag 区域收不到 `click`/`mouseup`。所以"点击展开"必须放在一个 `no-drag` 的子元素上（圆心占比约 60% 的热区）。不这么写，"点击展开"永远不触发，你会以为是状态机坏了。
2. **拖动结束的坐标不要靠渲染层**。drag 区域收不到 `mouseup`，渲染层拿不到"松手"这一刻。做法：主进程监听 `win.on('move')`，**300ms 去抖**后视为拖动结束，在去抖回调里做 clamp + 吸附 + 写 `hud.position`。`hud.moveTo` 照常实现（clamp + 落库），供程序化移动用，但 float-pod 的拖动不依赖它。
3. **hover 计时在渲染层，改尺寸在主进程**。渲染层 `mouseenter` 起 300ms 定时调 `setExpanded(true)`，`mouseleave` 起 500ms 定时调 `setExpanded(false)`；定时器要能被下一次进入取消（否则快速划入划出会抖）。主进程只负责 `setBounds` 并重新 clamp。

## 红线（审核逐条查）

1. **不重造数据**：积分、完成数、streak 只从 `bootstrap` 与 `DomainEvent` 读，HUD 里不许有任何积分运算、不许 `Math.floor` 参与分值（02 §5.2b、STATE 口径 7）。
2. **不读主窗状态**：HUD 不许读主窗的组件状态/全局 store，两条渲染进程各自独立（04 §5.5）。
3. **不新增通道、不新增 settings key**：五条 hud 通道、五个 settings key 就是全部。缺什么写进报告让架构方补契约，不许自己加。
4. **不许假实现**：全屏自动检测不实现就不实现（见上），不许写一段永远为 false 的检测代码假装做了。
5. **文案纪律**：HUD 上只许出现 04 已登记的元素与串（`● 3/5`、`今日 +42`、任务标题、错误 `message` 原样）。不许加说明文字、图例、提示语、"点击展开"这类标签。
6. **窗口层级不变**：`setAlwaysOnTop(true, 'pop-up-menu')` 不许改成 `screen-saver`（会盖全屏视频）。
7. **`createMainWindow` 零改动**；`bus.ts` 零改动；`src/shared/**` 零改动。
