## §0 为什么改

58c 把提醒改成「唤主窗到最前」，实测主窗**已存在**时四条 `restore → show → moveTop → focus` 正常。但如果主窗被用户关掉了，`showMainWindow()` 走的是这条：

```
if (!win) { createMainWindow(); return }
```

`createMainWindow()` 建出来的窗口是 `show: false`，靠自己的 `ready-to-show` 才 `show()`。**`moveTop()` / `focus()` 一次都没执行**，所以「关掉主窗 → 到点提醒」这个场景下，窗口建出来了、也会显示，但**不保证在最前**——正好砸在 58c 想解决的痛点上。

这处是 58c 交付时施工方主动上报的缺口，不是猜测。

**明确不做（越界即返工）：**

- **不改** `createMainWindow()` 的签名、默认值、内部那段 `ready-to-show`。
- **不改** `hudService` 的"主窗关闭时只出 HUD"逻辑。
- **不加**任何界面文字、提示、动画。
- **不碰**任何测试文件。

## §1 空窗分支补 `moveTop` / `focus`

`src/main/windowManager.ts` 的 `showMainWindow()`，把

```
if (!win) {
  createMainWindow()
  return
}
```

改成：

- 用 `createMainWindow()` 的返回值拿到新窗口句柄
- 在该句柄上挂**一次性** `ready-to-show`：先 `show()`，再 `moveTop()`，最后 `focus()`
- 然后 `return`

要求：

- 两句 `show()` 会连着执行（`createMainWindow` 内部那个监听在前）。`show()` 幂等，**不要为此去改 `createMainWindow` 传 `{ show: false }`**——那样会牵动启动路径。
- 顺序必须 `show → moveTop → focus`，与 §1 已有那条一致。
- 加一行注释说明：`createMainWindow` 建的窗是 `show:false` + `ready-to-show` 才显示，58c 那四条在这个分支不会执行，所以这里补挂一次。
