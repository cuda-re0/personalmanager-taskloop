## §2 `planReminders` 增加重复任务分支

签名不变：`planReminders(task: Task, now: Date): PlannedReminder[]`。

执行顺序：

1. `status` 过滤（`todo` / `doing`）—— 一行不改
2. `task.type !== 'daily'` —— 走原来的偏移逻辑，**一行不改**
3. `task.type === 'daily'` —— 新分支，按下述规则

### 规则（伪代码，实现自己写）

```
r = parseRepeatRule(task.repeatRule)        // 79 的 shared/repeatRule
if (r.unit === 'D') return []               // 每天 / 每 N 天：不提醒

anchor = task.activeFrom ?? toLocalDay(new Date(task.createdAt))
today  = toLocalDay(now)
last   = min(today + REPEAT_HORIZON_DAYS, task.activeTo ?? '9999-12-31')

lead = r.unit === 'W' ? [0] : r.unit === 'M' ? [-1, 0] : [-3, 0]

result = []
seen   = new Set<number>()                  // 按 epoch ms 去重
for day from today to last:
    if (!matchesRepeatDay(task.repeatRule, day, anchor)) continue
    for off in lead:
        d  = addDays(day, off)
        if (d < today) continue                       // 过去的丢，不补发
        if (task.activeTo !== null && d > task.activeTo) continue
        at = localInstant(d, task.dailyTime ?? DEFAULT_DAILY_TIME)   // 本地时区
        if (at.getTime() <= now.getTime()) continue   // 严格大于 now
        if (seen.has(at.getTime())) continue
        seen.add(at.getTime())
        result.push({ offsetMin: null, fireAt: at.toISOString(), level: 'normal' })
sort result by fireAt asc
return result
```

### 写死的边界

- **`offsetMin` 必须是 `null`**。`NULL` 在 `reminders` 里表示"绝对时间"，`uq_reminder_task_offset` 的 `WHERE offset_min IS NOT NULL` 保证多条绝对时间提醒可共存。写 `0` / `-1440` 会撞唯一索引，每个任务只能留一条。
- **`PlannedReminder.offsetMin` 的类型要从 `number` 放宽成 `number | null`**（下游 `ReminderInsert.offsetMin` 已经是 `number | null`，只差这一处）。
- `level` 一律 `'normal'`。重复任务的提醒不分轻重。
- 时刻取值统一走一个归一函数：`dailyTime` 为 `null` / `''` / 非 `HH:mm` / 时分越界 → 一律回落 `09:00`。**不许只写 `task.dailyTime ?? DEFAULT_DAILY_TIME`**——空串会造出 `Invalid Date`，`toISOString()` 直接抛 `RangeError`。
- `localInstant(day, hhmm)`：拆 `YYYY-MM-DD` 与 `HH:mm`，用 `new Date(y, m-1, d, hh, mm)`（本地时区）构造。**不要**用 `Date.parse(day + 'T' + hhmm)`——那会按 UTC 解析。
- 遍历上界 `last` 的日期分量、`activeTo` 比较，全部用**本地日字符串** `YYYY-MM-DD` 比较，不经过 UTC。
- 同日多条不合并、不去重（同一任务只有一个 `repeat_rule`，天然不会重叠）。去重只防 lead 窗口跨月边界重复。
- `REPEAT_HORIZON_DAYS = 30`、`REPEAT_REFILL_DAYS = 7`，两个常量放 `reminderPlan.ts` 并导出。
- `parseRepeatRule` 在 `planReminders` 内要**自己兜住**：库里若有坏规则，这一轮返回空数组即可，不许把异常抛给 `syncForTask` / 写任务的 handler。

## §3 物化：`ensureRepeatRows`（不许整表重建）

### 3.1 `reminderRepo.ts` 新增两个函数

```
/** 某任务"绝对时间"提醒里最大的 fire_at；没有返回 null */
export function maxActiveAbsoluteFireAt(taskId: string): string | null

/**
 * 重复任务的提醒物化：清掉换过规则的旧行，再补插缺失的行。
 * 不删计划内的行 —— snooze 改过 fire_at 的那条必须留着。
 */
export function ensureRepeatRows(
  taskId: string,
  rule: string,
  rows: Omit<ReminderInsert, 'taskId'>[]
): Reminder[]
```

`ensureRepeatRows` 在**一个 `tx()` 里**依次做：

1. `DELETE FROM reminders WHERE task_id = ? AND status IN ('active','paused') AND offset_min IS NULL AND (repeat_rule IS NULL OR repeat_rule <> ?)` —— 规则从「每周一」改成「每周二」，旧的周一那批行必须清掉，否则两套并存
2. `SELECT fire_at FROM reminders WHERE task_id = ? AND offset_min IS NULL AND status IN ('active','paused')` 取现有集合
3. `rows` 里 `fireAt` 不在集合里的逐条 INSERT
4. 返回 `listByTask(taskId)`

**为什么不能复用 `replaceForTask`**：它删的是 `status IN ('active','paused','failed')` 全部行。重复任务每轮补建都重建一次，用户点过的「稍后提醒」（改了 `fire_at` 但仍是 active）会被抹掉。

### 3.2 `reminderService.syncForTask` 分流

```
const task = ...                            // 原样
if (task === null) return []                // 原样

if (task.type === 'daily') {
  const rule = serializeRepeatRule(parseRepeatRule(task.repeatRule))   // 先解析成对象再序列化
  if (parseRepeatRule(rule).unit === 'D') {
    // 日级不提醒：把历史 active 行清空（用户从"每周"改成"每天"时必须生效）
    return reminderRepo.replaceForTask(taskId, [])
  }
  const rows = planReminders(task, now).map(...)         // offsetMin:null / repeatRule:rule / level:'normal' / channels:task.reminderChannels / status:'active'
  return reminderRepo.ensureRepeatRows(taskId, rule, rows)
}

// 其余类型：原来那套 planReminders + replaceForTask，一行不改
```

`rows` 的每个元素必须带 `repeatRule: rule`（第 3.1 步 1 的清理靠它区分新旧规则）。

## §4 滚动补建

### 4.1 `reminderService` 新增

```
export function ensureRepeatHorizon(now: Date): void
```

对 `listTasks({ status: ['todo', 'doing'] })` 里每个 `type === 'daily'` 的任务：

- `max = reminderRepo.maxActiveAbsoluteFireAt(task.id)`
- `max === null` 或 `Date.parse(max) < now + REPEAT_REFILL_DAYS * 86400000` → `syncForTask(task.id)`
- 否则跳过（窗口还够，别每轮白干）
- **单个任务抛错只 `console.warn('[reminder] 重复任务补建失败', task.id, e)`，不中断整轮**

### 4.2 `reminderScheduler.ts` 接线

`startReminderScheduler` 里：

- `run()` 内，`fireDue` **之前**加 `ensureRepeatHorizon(new Date())`，同样包在现有 `try/catch` 里
- 启动段 `syncAll()` **之后**加一行 `ensureRepeatHorizon(new Date())`

顺序不许反：先补建再扫描，否则新任务的第一条要等 30 秒后才可能被扫到。

## §8 测试（新建 `repeatReminder.test.ts`，8 条）

纯函数测试，`now` 用死值，照 `tests/main/reminderPlan.test.ts` 的 `makeTask` 写法造任务。

1. `EVERY:1:D` → `planReminders` 返回 `[]`
2. `EVERY:3:D` → 返回 `[]`
3. `EVERY:1:W:1,3`（每周一、三）→ 只出周一与周三的日期，每条一个，所有 `offsetMin === null`、`level === 'normal'`
4. `EVERY:1:M:15`（每月 15 日）→ 14 日与 15 日各一条
5. `EVERY:1:Y:11-06`（每年 11-06），**`now` 必须钉死为 `2026-11-01 00:00` 本地** → 11-03 09:00 与 11-06 09:00 各一条。（若把 `now` 取成"今天"11-06，11-03 那条会被纪律 1「过去的丢」过滤掉，这条断言必然假红）
6. `dailyTime = '21:30'` → 每条 `fireAt` 的本地时刻为 21:30；`dailyTime = null` → 为 09:00
7. `now` 为当天 10:00、`dailyTime = '09:00'`、`EVERY:1:W:<今天星期>` → 今天那条**不出现**，下一个命中日出现
8. `activeTo` 早于某提醒日 → 该条不出现在结果里

**断言纪律**：时间一律用本地分量断言（`getFullYear()` / `getMonth()` / `getDate()` / `getHours()` / `getMinutes()`）。**禁止**用 `fireAt.slice(0,10)` 或 `toISOString().slice(0,10)` 比日期 —— 那是 UTC 日，东八区下 09:00 会被判成前一天，测试会假红/假绿。
