## §1 数据契约

在 `src/shared/types/ipc.ts` 里新增并导出（放 `HudMode` 附近）：

```ts
/** 悬浮条读数（v0.62）：null = 这一路拿不到（LHM 没起 / 传感器缺失 / 读到的值不合法） */
export interface SensorReading {
  /** CPU Package 温度，整数摄氏度 */
  cpu: number | null
  /** GPU Core 温度，整数摄氏度 */
  gpu: number | null
  /** 采集时刻（ISO），渲染层不用它，排障时看日志 */

}
```

**硬性约束：**

- 两个字段都必须是 `number | null`，**不允许** `undefined`、`NaN`、`-1` 当哨兵。
- `NaN` / `Infinity` / 超出 `1..125` 范围的值一律转成 `null`。
- 温度取整用 `Math.round()`，`95.0 → 95`。

## §3 新服务 `src/main/services/sensorService.ts`

### §3.1 对外只暴露三个东西

```ts
export const LHM_PORT = 8085
export const LHM_URL = `http://127.0.0.1:${LHM_PORT}/data.json`
export const CACHE_MS = 1500
/** 读一次；两路互不影响，哪一路失败只让那一路是 null */
export async function readSensors(): Promise<SensorReading>
/** 测试用：清缓存 */

```

另外把两个解析函数导出，供单测直接调（**必须导出**，否则没法测）：

```ts
/** 从 LHM 的 data.json 文本里挑出两个温度；解析失败返回 { cpu: null, gpu: null } */
export function pickTemperatures(rawJson: string): { cpu: number | null; gpu: number | null }
/** `"62.0 °C"` / `"62,0 °C"` → 62；没有数字或超范围 → null */
export function parseTemperature(value: unknown): number | null
```

### §3.2 LHM 解析规则（写死，不要"优化"成按名字猜）

JSON 是一棵树（LHM 的老 OHM 格式），每个节点可能有 `Text`、`SensorId`、`Type`、`Value`、`Children`。

深度优先遍历整棵树，只看 `Type === 'Temperature'` 的叶子：

- **CPU**：`SensorId` 以 `/intelcpu/` 或 `/amdcpu/` 开头，且 `Text === 'CPU Package'`。
- **GPU**：`SensorId` 以 `/gpu-` 开头，且 `Text === 'GPU Core'`。

命中多个时取**第一个**（遍历顺序稳定即可，不要排序）。

**为什么不按 `SensorId` 写死下标**：`/intelcpu/0/temperature/26` 是这台 Intel 机器的序号，换硬件就变。前缀 + `Text` 能跨厂商。

**为什么不按 `Text` 单独匹配**：内存条也有 `DIMM #1` 之类的温度，光看 `Text` 会误命中。前缀把硬件类别卡死。

### §3.3 数值解析

`parseTemperature` 的规则：

- `typeof value !== 'string'` → `null`。
- 取字符串里**第一段**匹配 `-?\d+(?:[.,]\d+)?` 的数字，逗号当小数点处理（LHM 的 `Value` 是 locale 格式化过的，有些区域是 `62,0 °C`）。
- `Math.round()` 后如果 `< 1` 或 `> 125` → `null`。
- 解析不出数字 → `null`。

**为什么下限是 1 而不是 0**：LHM 对没读到的传感器会给 `0.0 °C`，那是"没有值"不是"零度"。本机 NVMe 的 `Composite Temperature` 就恒为 `0.0 °C`，收进 UI 就是一条假数据。

### §3.4 读取流程

```
readSensors():
  若距上次采集 < CACHE_MS 且缓存非空 → 直接返回缓存
  cpu = null, gpu = null
  尝试 GET LHM_URL（超时 1200ms）
    成功 → pickTemperatures(body) → 填 cpu / gpu
    失败（连不上 / 超时 / JSON 坏 / 状态码非 200）→ 两路都保持 null，**只 console.warn 一次**
  若 gpu === null → 尝试 nvidia-smi（超时 1500ms）
    成功且能解析出 1..125 的整数 → 填 gpu
    失败 → 保持 null，**不 warn**（没独显是正常情况，不刷日志）
  写缓存（含 at: new Date().toISOString()）
  返回
```

`nvidia-smi` 调用参数写死：

```
nvidia-smi --query-gpu=temperature.gpu --format=csv,noheader,nounits
```

返回值可能是多行（多卡），只取**第一行**。

**为什么 LHM 失败时不重试、不等待**：每 2 秒都会再问一次，这一次失败下一次自然补上。重试只会让 HUD 主进程多等几百毫秒。

**日志节制**：LHM 连不上会每 2 秒发生一次，**不许每次都 warn**，用一个模块级布尔量保证同一失败原因只 warn 一次，成功一次后复位。

### §3.5 拉起 LHM

同一个文件里再导出一个：

```ts
/**
 * 应用启动时调一次：LHM 没在跑就拉起它。
 * - 只在打包版（app.isPackaged）里动作，开发模式直接返回
 * - 先探 LHM_PORT，已有服务就不重复拉
 * - exe 不存在就返回（用户没装 LHM 时不能崩）
 * - 本进程生命周期内只尝试一次
 */
export async function ensureLhmStarted(): Promise<void>
```

实现要点：

- `const exe = join(dirname(process.execPath), 'lhm', 'LibreHardwareMonitor.exe')`；`existsSync(exe)` 为假就返回。
- 探测：`GET LHM_URL` 成功即认为已在运行，返回。
- 拉起用 `shell.openPath(exe)`（**不是** `spawn`）：`shell.openPath` 走 ShellExecute，会按清单弹 UAC，这是唯一能让 `requireAdministrator` 程序起来的方式。
- `openPath` 返回非空字符串代表失败（用户点了 UAC「否」或别的错），`console.warn` 一行，**不重试、不弹窗、不影响应用**。
- 模块级 `let launchAttempted = false`，置位后不再进。

**这个文件里 `import { shell } from 'electron'` 只允许出现在 `ensureLhmStarted` 内部使用**（顶层 import 可以，但除该函数外不许调用 electron 任何 API）。

**调用点**：`src/main/index.ts` 的 `app.whenReady()` 里，放在 `createHudWindow()` 之后、`registerIpcHandlers()` 前后都行，用一个延时避免和窗口首帧抢：

```ts
// 悬浮条温度（v0.62）：LHM 是管理员程序，拉起会弹 UAC；
// 延后 3 秒，等窗口先画出来，避免开机自启时 UAC 抢在前台
setTimeout(() => {
  void ensureLhmStarted()
}, 3000)
```

## §9 已知影响（写给你和用户看，不要"顺手"处理）

- **LHM 必须常驻**。它退出后 CPU 温度立刻变 `--`，GPU 还能靠 `nvidia-smi` 撑着。
- **每次开机弹一次 UAC**。用户选的就是这个方案。如果哪天嫌烦，可以在 LHM 里勾「Run On Windows Startup」，然后把 §3.5 的调用去掉。
- **LHM 12MB 在 `dist/taskloop/lhm/`**，没进 `pack.mjs`。重新打包绿色版时如果整目录重建，LHM 会丢——那是打包流程的事，本单不处理。
- **温度是 LHM 的采样值，不是实时值**。LHM 自己约 1 秒刷一次，我们再 2 秒问一次，所以界面上最多滞后约 3 秒。看得出趋势，看不出瞬时尖峰。
- **`0.0 °C` 被当成 null**（§3.3 下限 1）。本机 NVMe 的 `Composite Temperature` 恒为 0.0，是 LHM 读不到的占位值。
- **主进程每 2 秒一次 HTTP + 可能一次 nvidia-smi**。LHM 开着时是 7.5ms；LHM 没开时会多一次 83ms 的子进程（异步，不阻塞窗口）。
