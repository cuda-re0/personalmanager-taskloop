# ① 保留「今日已完成」并变淡显示（v0.27）

> **起点**：`66a9664`。开工前 `git status --porcelain` 应为空；非空停下来问。
> 必读：`docs/04-UI-SPEC.md` §4①（含 v0.27 补则）、§1（文案纪律）。

用户拍板：「已完成的变淡显示吧。」——① 的三组都要**保留今天完成的行**，变淡显示；
**第二天自动消失**，不做任何清理逻辑。这是用户裁决，不是设计选择。

---

## 1. 现状（先读再改）

- `useTasksData.ts:100`：渲染层只拉 `ACTIVE_STATUS = ['todo','doing','reviewing']`，
  `done` 任务**根本不进数据层**——这是要改的第一处。
- `tasksModel.ts:49`：每日组只渲染 `status==='pending' && day===today` 的 occurrence，
  打完卡当天行即消失。
- 明细流水的高亮联动因此多数不可观察（`580707d` 审核时的已知矛盾），本单修好后**回归可达**。

## 2. 改法

### A. 限时 / 活动组：done 且今天完成的保留

- `useTasksData` 增加一路拉取：`status: ['done']` 的任务，渲染层过滤
  `completedAt` 的本地日 === 今天。若 `taskRepo.list` 已支持按完成时间过滤参数就优先用
  （查 `src/main/db/repositories/taskRepo.ts`）；**需要动 repo 才能实现时，先把打算改的
  函数签名写进报告第 5 段，等我确认**——不许顺手扩接口。
- 两组内排序：活跃行在前（原排序不动），**今日已完成的沉底**（内部保持原排序）。
- 已完成行：**无 `[完成]` 按钮、无剩余时间 / 倒计时**（右列留空），整行变淡。

### B. 每日组：今天全部 occurrence 都显示

- `tasksModel.groupTasks` 的每日组过滤改成 `day === today`（pending + done 都要），
  排序 pending 在前、done 沉底（各段内部按原 sortKey）。
- done 行：勾选框呈已勾状态且 **disabled**（点了没反应 ≠ disabled，要真的 `disabled`），
  连续天数照常显示，整行变淡。

### C. 变淡样式

- `tasks.css` 新增一个完成态类，`opacity: .5`（与明细已冲销行同一档，全站只用这一种「弱化」表达）。
- 不加删除线、不加「已完成」文字、不加 tooltip（§1 文案纪律）。

### D. 跨天行为（不需要写代码，但要有测试锁住）

- 明天：`completedAt` 不再是今天 → 限时/活动的行自动消失；每日组 `day !== today` 自动消失。
- 都靠过滤天然实现，**禁止**写任何「清理」「定时删行」逻辑。

### E. 高亮联动回归

- 04 §4④ 已写明高亮是条件行为；本单后今日完成的行也高亮可达。行为代码零改动
  （`emitFocusTask` 链路在 `580707d` 已验），只是目标出现了。
