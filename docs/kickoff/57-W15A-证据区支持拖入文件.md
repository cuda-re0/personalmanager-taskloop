# 57 · 证据区支持把文件直接拖进来（v0.57）

> **类型**：功能新增（走外部施工方）。
> **需求原话**：用户 2026-11-01 20:29「任务提交照片审核要能直接拖入，不用非得走路径选择」。
> **裁决**：① 只有**证据区**接收（不是整张卡）；② 一次拖多个就**逐个串行上传**。

## 1. 现状（已查证，别重新调研）

- 证据区组件是 `src/renderer/main/components/EvidencePanel.tsx`：只有一颗 `[+]` 按钮 + 一个隐藏 `<input type="file">`，点开必然弹系统文件对话框。
- 两张卡共用它：`SubmitCard.tsx`（待提交卡）、`TaskReviewCard.tsx`（审核卡）。**改一处两卡同时生效**。
- 聊天输入框 `ChatInput.tsx` **早就有拖拽**（`onDragOver` + `onDrop` → `addFiles(dataTransfer.files)`），本单**不动它**，只把它当作口径参照。
- 上传链路：`onPick(file)` → `actions.addEvidence(taskId, file)` → `attachment.add`(base64) + `task.addEvidence`，**一次一个文件**，返回 `Promise<string | null>`（`null` = 成功）。
- **当前没有全局拖放兜底**：`src/renderer` 里对 `dragover` / `drop` 的 `preventDefault` 只出现在具体接收区。把文件拖到没有接收者的地方，Chromium 会把文件当导航目标，Electron 里表现为**整窗被 file:// 页面替换（白屏）**。这是本单必须一起补的（§3.5）。

## 2. 目标行为

拖一个或多个文件到证据区 → 按顺序逐个走现有上传链路 → 每张图/文件按现有 `EvidenceChip` 规则出现（图片缩略图、其他类型给扩展名角标）。传送中整区禁用（沿用现有 `busy` 表现）。

## 3. 改动清单

### 3.1 纯函数（1 文件）

`src/renderer/main/features/chat/chatViewModel.ts` 新增并导出：

```
filesFromDrop<T>(files: ArrayLike<T> | null, canAccept: boolean): T[]
```

规则（写死）：

- `canAccept === false` → 返回 `[]`
- `files === null` 或 `files.length === 0` → 返回 `[]`
- 其余 → `Array.from(files)`，**保持原顺序**（串行上传依赖顺序）

用泛型而不是 `FileList`，因为测试环境没有 DOM。

### 3.2 `EvidencePanel.tsx`

1. **`onPick` 签名改为 `(file: File) => Promise<unknown> | void`**（现有 `(file: File) => void` 会让串行 await 落空，三个调用方里 `ChatPanel` 已经返回 Promise，`ChatPanel.tsx` **不用改**）。
2. 容器 `.review-evidence` 上加三个处理器：
   - `onDragOver`：**始终** `event.preventDefault()`（不 preventDefault 浏览器就不认这个放置区）。仅当 `canAdd && !busy` 时 `event.dataTransfer.dropEffect = 'copy'`，否则设为 `'none'`，并且仅此时置高亮。
   - `onDragEnter`：`canAdd && !busy` 时置高亮。
   - `onDragLeave`：`event.currentTarget.contains(event.relatedTarget as Node)` 为真时**不清高亮**（否则鼠标划过子元素会闪），否则清。
   - `onDrop`：`event.preventDefault()`；先清高亮；再 `const files = filesFromDrop(event.dataTransfer.files, canAdd && !busy)`；`files.length === 0` 直接返回；**用 `useRef` 防重入**（上一轮还没跑完时再拖进来的整批丢弃，不排队）；然后 `for (const file of files) { await onPick(file) }`。
3. 高亮态用组件内 `useState<boolean>`，容器 `className` 追加 `review-evidence--over`。
4. `openSignal` / `[+]` / `<input type="file">` / 缩略图逻辑**一律不动**。`canAdd === false` 时仍然不渲染 `[+]` 与 input（保持现状），但容器**照样挂 `onDragOver`**（只为 preventDefault，不高亮、不上传）。

### 3.3 两张卡的 `runAction` 必须能被 await

现在两处都是 `void fn()`，返回值是 `undefined`，`await` 会立即通过 → 串行会退化成并发上传。改法（两个文件各一处，语义相同）：

- `TaskReviewCard.tsx`：`runAction` 返回类型 `void` → `Promise<void>`；`void fn()` → `return fn()`（保留 `.then` 里的 `setError`、`.finally` 里的 `setBusy(false)`）；开头的 `if (busy) return` → `return Promise.resolve()`。
- `SubmitCard.tsx`：同上，把 `busy` 换成它的 `disabled`、`setBusy` 换成 `setLocalBusy`。
- 卡上其它按钮调用 `runAction` 的地方**不需要改**（丢弃返回值合法）。
- 串行三张时 `busy` 会在每张之间闪一下 `false`，这是接受的代价，**不许为此改成计数器或 Promise 队列**。

### 3.4 样式（1 文件）

`src/renderer/shared/styles/chat.css` 新增一条规则（放在 `.review-evidence` 规则之后）：

- 选择器 `.review-evidence--over`
- `outline: 1px dashed var(--accent); outline-offset: 3px; border-radius: 6px; background: var(--accent-weak);`

用 `outline` 不用 `border`（不改变布局高度）。**不加任何文字提示**（不加"拖到这里"之类）。

### 3.5 全局兜底（1 文件，**必须做**）

`src/renderer/main/index.tsx`，在 `createRoot(...)` **之前**：

- `window.addEventListener('dragover', event => event.preventDefault())`
- `window.addEventListener('drop', event => event.preventDefault())`

理由与边界：这两个监听只负责"别让浏览器把文件当导航目标"，不处理任何上传；组件内的 `onDrop` 先执行、自己 `preventDefault` 并处理文件，冒泡到 `window` 时已被消费。**HUD 窗口（`src/renderer/hud/index.tsx`）本单不做**——它是独立窗口、不承载任何拖放目标；如需一致另开单。

### 3.6 测试（1 文件，加 3 条）

`tests/renderer/evidenceViews.test.ts` 追加 **3 条** `filesFromDrop` 用例（该文件已有 `toEvidenceViews` 的用例，风格照抄）：

1. `canAccept === false` → `[]`（即使传了 3 个文件）
2. `files === null` → `[]`
3. 正常：传 3 个元素的数组 → 返回 3 个、**顺序与入参一致**

**不许改已有用例**。

### 3.7 文档（1 文件）

`docs/04-UI-SPEC.md` 里证据区那一节（搜 `review-evidence` 或「证据」段）追加一句：`证据区接受把文件直接拖入，落点仅限该区域；一次拖入多个按顺序逐个上传；拖入时该区域虚线高亮，不出现任何文字提示。`

## 8. 已知风险（不改，写在这里防扯皮）

- 串行上传期间 `busy` 会在每张之间闪一下 `false`，理论上有一瞬间能点别的按钮。接受。
- 拖入的如果是文件夹或系统虚拟文件，`dataTransfer.files` 里可能为空或不可读，按"空就忽略"处理，不做特殊文案。
- 全局 `dragover` 的 `preventDefault` 会让整个窗口都显示"可放置"光标，这是浏览器层的既有表现，不做差异化光标。
