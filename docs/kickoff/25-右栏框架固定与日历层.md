# 右栏框架固定 + 日历层替换积分区（v0.28）

> **起点**：`8ea91ed`。开工前 `git status --porcelain` 应为空；非空停下来问。
> 必读：`docs/04-UI-SPEC.md` §4①②③④（本轮 §4②③④ 均有改写）、§1（文案纪律）。

用户两条，都是右栏布局层面的裁决：

1. 「创建任务板块的任务详细展开会压缩下面的积分区域，既然它装了滑动条，那大框架就应该是固定不能动的才对。」
2. 日历浮层**修错了**——不要浮层。「效果应该是点击日历，下方的积分层变成日历层，里面放有那一天的任务和任务完成情况。」

`66a9664` 里浮层的定位修复（`floorTopOf`、贴行/翻面）随本单**整体作废**，不是打补丁。

## 1. 问题 A：右栏框架固定

### 根因

`tasks.css`：`.tasks-panel` 是 `flex: 1 1 auto`（内容高做 basis），`.points-panel` 也是
`flex: 1 1 auto`。详情展开 → ① 的内容高变大 → 两个弹性块重新分摊 → 积分区被压缩。
（`.calendar-panel` 是 `flex: 0 0 auto; height: 240px`，没事。）

### 改法

右栏三段的高度配额**固定**，内容变化只发生在各段内部滚动：

| 块 | 配额 |
|---|---|
| ① 任务 | `flex: 1 1 auto` + `min-height: 0`（吃剩余空间，**内部滚**——它已有 `overflow-y: auto`，缺的是不允许别人被它挤压） |
| ② 日历 | 不动（240px 固定已是如此） |
| ③④ 积分 | **定高配额**：真机量详情**收起**状态下 `.points-panel` 的实际高度，取整为 `flex: 0 0 <H>px`（内部已有两处 `overflow-y: auto`，缺的同样是不被压缩） |

- 量出来的 `<H>` 写进报告第 1 段和测试断言（锁住这个数，像 460/980 那样）。
- **判定**：详情展开 / 收起前后，② 和 ③④ 的 `offsetHeight` 一个像素都不变；
  变化的只有 `.tasks-panel` 内部的滚动条。
- 明细列表已在内部滚，这条改完横向纵向都不许再溢出。

## 2. 问题 B：日历层替换积分区

### 交互

- 点日历某天 → **③④ 积分面板整块被「日历层」替换**（同 v0.26 明细标签的就地替换模式：
  不弹层、不覆盖、不新窗口）。
- 日历层内容：**那一天的任务 + 完成情况**——沿用浮层现有的 `occurrence.listByRange(day, day)`
  数据与行结构，每行 = 完成状态勾（空心=未完成、实心=已完成，复用 `.task-check` / `.task-check--on`）+ 任务标题。
- **不加**「已完成 / 未完成」文字、不加统计语句（§1）。当天没有任务的行文与浮层空态一致。
- 点行 → `emitFocusTask(taskId)` 高亮 ① 对应任务（浮层原有的联动保留），日历层**不关闭**。
- **再点同一天 = 关闭**，回到积分面板；点其他天 = 内容切到那天（选中态本来就这么工作）。
- 浮层原来的 `×` 关闭按钮随浮层一起删——关闭路径只剩「再点同一天」一种，够用。

### 删净清单（浮层机制）

| 位置 | 删什么 |
|---|---|
| `CalendarPanel.tsx` | `floorTopOf`、`FLOOR_MAX_HEIGHT`/`FLOOR_GAP`/`FLOOR_MARGIN`、`CellAnchor`、`anchor`/`floorHeight`/`panelHeight` 状态、`useLayoutEffect` 量高、`.calendar-floor` 的渲染与 `floorRef`、浮层头部与 `×` |
| `calendar.css` | `.calendar-floor` 全部规则（含注释）、浮层相关样式 |
| `calendarPanelWiring.test.ts` | 浮层定位的 3 条结构断言（贴行/翻面/钳零锚点）全部作废重写 |

### 结构

- `selectedDay` 状态留在 `CalendarPanel`；但「积分槽位显示谁」需要 `index.tsx` 参与——
  把「当前选中的日历日」提升为 `index.tsx` 的状态（`dayDetail: string | null`），
  `CalendarPanel` 收 `selectedDay` / `onSelectDay` 两个 props，`index.tsx` 据此条件渲染
  `<PointsPanel />` 或 `<CalendarDayView />`（新组件，放 `features/calendar/`）。
- 数据拉取在 `CalendarDayView` 挂载时进行（同明细零请求原则：没选日子不发请求），
  沿用 `useCalendarData` 里现成的 listByRange 路径。
- **接受的副作用（写明，不要自己加码）**：积分面板被替换期间其 tab 状态（今日/本周/本月/明细）
  会重置——条件渲染、回来自动回默认。用户此前未对积分 tab 状态提出保留要求，不要为此做状态提升。

## 6. 真机手点（必须真机；起不来如实写起不来）

```bash
Remove-Item Env:ELECTRON_RUN_AS_NODE -EA SilentlyContinue; npm run build; npm start
```

1. 展开一条任务详情 → **下面积分区、日历的高度纹丝不动**；详情区自己在 ① 内滚动。
2. 收起详情 → 布局无跳动。
3. 点日历 10 号 → 积分区变成日历层，列出 10 号的任务与勾选状态。
4. 打卡一条每日任务 → 切到今天看日历层，勾从空心变实心（事件刷新）。
5. 点日历层里一行 → ① 对应任务高亮，日历层不关。
6. 再点同一天 → 回到积分面板；点其他天 → 内容直接切换。
7. 全程无横向滚动条、无新增文字。
