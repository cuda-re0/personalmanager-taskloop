## 一、问题与定性

会话区（主页面）里每次提醒触发会写一条 `kind='reminder'` 的消息，渲染成 `ReminderRow`：标题红字 + 「稍后提醒」「知道了」两个按钮。

现状 `src/renderer/main/components/ReminderRow.tsx:33` 用一个组件本地 state：

```
const [settled, setSettled] = useState(false)
```

注释自己写着「不落库，重启后按钮会再出现」。**这是缺功能，不是 bug**：用户点过「知道了」之后，切页 / 重启 / 窗口重建都会回到 `settled=false`，红字和两个按钮原样回来。

`alerts.acked_at`（v0.88）记录的是「这条投递没升级」的投递记录，粒度是 `source_id = reminderId`；同一条 reminder 被 snooze 后再次触发会产出**第二条** alert 行，所以**不能用它判断"这条消息处理过没有"**。结论：在 `messages` 上记消息级的已处理事实。

### 2.5 业务层

`src/main/services/messageService.ts`：

- `PatchMessageInput` 同步加 `settledAt?: string | null`；
- 新增导出函数 `settleReminderMessage(id: string): Message`，行为按下面顺序写死：

1. `requireMessage(id)` 取现消息（不存在 → `NOT_FOUND`，用现有的 `requireById` 即可，不要自己造错误）。
2. `message.kind !== 'reminder'` → 抛 `appError('INVALID_INPUT', '只有提醒消息可以标记已处理')`，`detail` 带上实际的 kind。
3. `message.settledAt !== null` → **直接返回**这条消息，不写库、不广播（幂等，用户连点两下、两个窗口同时点都只能留下一次记录）。
4. 取 `at = nowIso()`，`patchMessage(id, { settledAt: at })` 得到新消息。
5. 若 `message.meta.kind === 'reminder'`：调 `alertService.ackAlert(message.meta.reminderId)`，**包 try/catch 只 `console.warn`**——alerts 记不上不能连累界面状态（与 `reminderService.fireOne` 里 `recordAlert` 的口径一致）。
6. `broadcast({ type: 'message.patch', messageId: id, patch: { settledAt: at } })`。
7. 返回第 4 步的消息对象。

注意：`messageService` 现在**没有** import `appError` / `broadcast` / `alertService`，需要自己补 import；`nowIso` 已在用。**不要**把 alert 的 ack 逻辑写进 repo 层。
