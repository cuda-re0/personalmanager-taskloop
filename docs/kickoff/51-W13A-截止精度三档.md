## 0. 一句话目标

现在用户说「11 月 5 号前交报告」，模型只有两条路：编一个钟点（09:00 / 23:59 就是这么来的），或者填 `null`。**没有"只填日期"这个出口。**

本单把 `due_hint` 从"必须带时分"放宽成**三档精度**：只到月、只到日、到分。有日期就记，不编时刻，不丢信息。

## 2. 核心规则（这段是本单的宪法，别自己发挥）

### 2.1 三档精度，由字符串形状直接判定

| 形状 | 精度 | 举例 |
|---|---|---|
| `YYYY-MM-DDTHH:mm…` | `minute` | `2026-11-05T15:00:00.000Z` |
| `YYYY-MM-DD` | `day` | `2026-11-05` |
| `YYYY-MM` | `month` | `2026-11` |

**不做第四种**（不做到年、不做到季度）。形状不匹配一律非法。

> 为什么用字符串长度而不是加列：`due_at` 无 CHECK 约束，加列要迁移 + 改冻结契约字段表；字符串形状自带精度、零迁移。**这是用户拍板的选择，不要再讨论。**

### 2.2 「截止瞬间」的归一规则

`day` / `month` 没有真实时刻，但下游需要一条**可比较的时间线**。统一按下表归一，**只用于计算，不回写 `due_at`**：

| 精度 | 归一后的截止瞬间（本地时区） |
|---|---|
| `minute` | 原样解析 |
| `day` | **当天 23:59:59.999** |
| `month` | **当月最后一天 23:59:59.999** |

- 月末天数按真实日历算（2 月平年 28、闰年 29、4 月 30、1 月 31），**不许写死 30/31**。
- 实现提示：以输入月 `M`（1–12）取月末，`new Date(y, M, 0)` 就是该月最后一天的本地零点，再补到 23:59:59.999。这是规则不是完整实现，怎么写你自己定。
- **`due_at` 存的仍是原样的 `2026-11-05` / `2026-11`**，绝不写回 `2026-11-05T23:59:59.999`。

### 2.3 合法性校验

形状对不代表日期对。`2026-13-01`、`2026-02-30`、`2026-00` 必须判**非法**（构造 Date 后回读年月日是否一致）。

### 2.4 非法值一律 `null`，不抛错、不猜

三处入口（schema / parse.toDueHint / taskService.toDueAt）都保持现在的兜底姿态：非法 → `null`，由上层决定是"重试"还是"留空"。

## 3. 逐文件改动

### 3.1 新建 `src/shared/due.ts` —— 精度的唯一实现处

纯函数，**不许 import 任何主进程 / 渲染层模块**（它两边都用）。导出 **1 个类型 + 4 个函数**：

| 导出 | 签名 | 语义 |
|---|---|---|
| `DuePrecision` | `type = 'minute' \| 'day' \| 'month'` | — |
| `duePrecisionOf` | `(raw: string \| null \| undefined) => DuePrecision \| null` | 形状 + 合法性判定，非法 → `null` |
| `dueInstant` | `(raw: string \| null \| undefined) => Date \| null` | §2.2 的归一，非法 → `null` |
| `dueLocalDay` | `(raw: string \| null \| undefined, timeZone?: string) => string \| null` | 截止日的本地 `YYYY-MM-DD`；`month` → 月末那天；`day` → 原串前 10 位 |
| `dueHasTime` | `(raw: string \| null \| undefined) => boolean` | 等价于 `duePrecisionOf(raw) === 'minute'` |

约束：
- `timeZone` 参数只为测试能钉时区而存在，生产不传。
- `dueLocalDay` 对 `day` 精度**不要**走 `new Date()` 再转时区——那个串本身就是本地日历日，直接取前 10 位。走 Date 会在西半球串到前一天。
- 头部注释写清：这是「due_at 时间线的唯一解析处」，禁止在别处再写 `new Date(dueAt)`。
