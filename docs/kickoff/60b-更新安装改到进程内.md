## §0 为什么退掉 60 §2.5 的 cmd 路线

60 里的覆盖动作交给 `apply.cmd`，脚本要写死的三个绝对路径里含中文（本机安装位置是 `...\WorkBuddy\任务管理审核\dist\taskloop`）。bat 按 UTF-8 写、cmd 按系统 ANSI 代码页读，靠第 2 行 `chcp 65001` 兜。这条**在本机无法验证**（施工环境与架构环境都调不动 cmd.exe），而它的失败模式是「应用退出后不再回来」，只能人工双击恢复。

改成**进程内覆盖**：主进程自己用 Node `fs` 拷完再 `app.relaunch()`。

- Unicode 路径由 Node 处理，不存在代码页问题；
- 失败可以回滚后照常启动，最坏结果是「这次没更新」，不是「应用打不开」。

## §2 新的 `applyUpdate(): void`

前置计算（与原来一致，不要改）：

```
resApp = join(dirname(process.execPath), 'resources', 'app')
src    = join(UPDATE_DIR, 'app')
```

执行顺序写死：

1. 再读一次 `readManifest()`；`null` 则直接 `return`（什么都不做、不退出）。
2. **先 `app.relaunch()`**（见 §2.2 修订），再 `BrowserWindow.getAllWindows().forEach(w => w.destroy())`。用 `destroy()` 不用 `close()`：`close` 会被 `close` 事件里的拦截逻辑挡下，窗口留着就还占着 `out/renderer/**`。
3. 备份：
   - `resApp/out.bak` 存在 → 先删掉（递归 force）
   - `resApp/out` 存在 → `renameSync(out, out.bak)`
   - `resApp/package.json` 存在 → `copyFileSync(pkg, pkg.bak)`
4. `copyTree(src, resApp)` —— 递归复制，覆盖同名文件，目录不存在就建。
5. 校验：读 `resApp/package.json` 的 `version`，必须**严格等于**第 1 步读到的 `manifest.version`。
6. 成功：**保留 `out.bak`**（留最后一次可手工恢复的副本），不删。
7. 任何一步抛异常、或第 5 步不相等 → 回滚：
   - 删 `resApp/out`（可能是拷了一半的）
   - `resApp/out.bak` 存在 → `renameSync(out.bak, out)`
   - `resApp/package.json.bak` 存在 → `copyFileSync(pkg.bak, pkg)`
   - 打一行 `console.error`
8. 无论成功失败，最后 `app.quit()`。

**为什么失败也要重启**：第 2 步已经把窗口 destroy 了，留着进程就是一块空白。重启后载入的还是旧代码（版本没变），`attemptedVersion` 已在 `checkUpdate` 里写过，不会再自动尝试第二次。

**硬规定：**

- `app.relaunch()` **只许调用一次**（位置见 §2.2）；**不要**用 `app.exit()`（跳过退出清理）。
- 回滚本身失败时只 `console.error`，不要抛、不要弹窗、不要改写任何界面状态。
- **不要**用 `fs.cpSync`（本机这套环境会静默杀进程，`pack.mjs` 已经踩过）。自己写一个 20 行以内的递归：`readdirSync(withFileTypes)` → 目录递归 / 文件 `copyFileSync`，目标目录 `mkdirSync(recursive)`。
- **不要**从 `scripts/` 里 import 任何东西（那是构建期脚本，打进主进程是错的）。
- 覆盖期间不要动 `node_modules`（better-sqlite3 的 `.node` 被加载后文件是锁定的，拷它必失败）。本单只覆盖 `out/` 与 `package.json`。

### §2.1 关于「先 rename 再 copy」

不要改成「直接往 `out` 上覆盖」。

- 直接覆盖会留下上一版的 hash 资源（`main-XXXX.js` 之类），新旧混在一个目录里，出问题时分不清哪份在跑；
- rename 之后再 copy，得到的是一个干净目录；
- 回滚只需要 rename 回来，不用逐文件恢复。

`out.bak` 是**目录改名**得来的，不是拷贝，不占额外空间、不耗时。

### §2.2 修订（施工方上报的时序风险，架构方裁定：采纳）

`src/main/index.ts:80` 的 `window-all-closed` 处理器会调 `app.quit()`。`applyUpdate` 里 `destroy()` 全部窗口的瞬间这个事件就到了，quit 序列在我们自己的 `relaunch()` 之前就启动了。理论上 quit 是异步的、同步栈走完前进程不会退，但**失败模式是「退出了却不回来」**，不值得赌。

改法（**是移动，不是新增**）：把 `app.relaunch()` 从函数末尾**移到**第 1 步 `readManifest()` 判空之后、`destroy()` 之前。末尾只留 `app.quit()`。

> 为什么不能两次都调：Electron 文档明确「`app.relaunch` 被调用多次，退出时会启动多个实例」。移动，不是加一遍。
