## 三、规格

### §1 `NewTaskForm.tsx`

1. **不动共享常量。** `TYPE_LABEL` / `TYPE_ORDER` / `chatViewModel.ts` 一行都不许改 —— `TYPE_LABEL` 的类型是 `Record<TaskType, string>`，把 `pulse` 塞进去会直接破类型。本文件内自行定义：

   - 本地类型 `FormKind = TaskType | 'pulse'`；
   - 本文件内的常量 `PULSE_KIND = 'pulse'`、`PULSE_LABEL = '周期提醒'`。

2. `type` state 的类型改成 `FormKind`，初值仍是 `'deadline'`。

3. chip 排渲染顺序固定：先 `TYPE_ORDER` 三项（文字取 `TYPE_LABEL[item]`），最后追加一项 `PULSE_KIND`（文字取 `PULSE_LABEL`）。`aria-pressed`、`new-task-type--on` 的判定照旧用 `item === type`。

4. `changeType(next: FormKind)`：`next === PULSE_KIND` 时**不调** `coerceDifficulty`（周期提醒没有难度），只设 `type` 并清空 `when`。

5. `type === PULSE_KIND` 时的字段结构（顺序写死）：

   | 位置 | 元素 | 说明 |
   |---|---|---|
   | 标题行 | 复用现有 `.new-task-title` 输入，`aria-label="标题"` | 不改 |
   | 第一行 `.new-task-fields` | 间隔数字：`type="number"`、`min={1}`、`step={1}`、类 `.new-task-num`、`aria-label="间隔"` | 默认 `30` |
   | 同上 | 单位下拉：类 `.new-task-select`、`aria-label="单位"`，两项 option（值 `minute` / `hour`，文字 `分钟` / `小时`） | 默认 `minute` |
   | 第二行 `.new-task-fields` | 开始：`type="time"`、类 `.new-task-time`、`aria-label="开始"` | 可空 |
   | 同上 | 结束：`type="time"`、类 `.new-task-time`、`aria-label="结束"` | 可空 |

   **不渲染**难度 select、时长 input。第二行复用 `.new-task-fields`，不新增类名。

6. `canSubmit` 分两套：

   - `type !== PULSE_KIND`：保持现状 `title.trim().length > 0`。
   - `type === PULSE_KIND`：**四条同时成立**才算可提交 ——
     ① `title.trim()` 非空；
     ② 间隔文本能转成整数；
     ③ 换算后的分钟数（选 `hour` 乘 60）落在 `1..1440`；
     ④ 两个时间**同时为空或同时非空**（只填一个不算可提交）。

7. `submit()`：

   - `type === PULSE_KIND`：调 `actions.createPulse({ title: title.trim(), intervalMinutes: 换算后的分钟数, windowStart: start === '' ? null : start, windowEnd: end === '' ? null : end })`；返回 `true` 才 `close()`。
   - 其他类型：走现有 `createManual` 分支，逐字不动。

8. `reset()` 追加：间隔回 `'30'`、单位回 `'minute'`、两个时间清空。新增的四个 state 名字自定（`intervalText` / `unit` / `start` / `end` 沿用 `PulseSection` 的命名即可）。

9. 标题输入的 `Enter` 提交、`丢弃` 按钮、`确认` 按钮的 `disabled={!canSubmit}` 三处照旧，不要为 pulse 另写一套。
