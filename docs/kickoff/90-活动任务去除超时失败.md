# 90 · 活动任务不吃「超时失败」，也不显示逾期

## 一、问题与定性

用户诉求（2026-11-10 原话）：考试、比赛的成绩要等外部出，活动任务应该「就挂在那儿，不用完成，直到出成绩」，也不要显示「逾期」。

代码现状取证：

1. **显示层**：`src/shared/format.ts:50` 的 `fmtRemaining` 不看类型——只要过了截止瞬间就返回 `'逾期'`，活动任务行右侧因此一直挂着「逾期」两个字，像在催命。
2. **判定层**：`src/renderer/main/features/tasks/reviewFlow.ts:74-76`：

```
if (task.type === 'event' && verdict.verdict === 'fail') return 'missed'
return isOverdue(task.dueAt, now) ? 'missed' : 'revive'
```

第 74 行只拦了 `fail`。活动任务一旦拿到 `partial`（AI 看到"你参加了，但没看到成绩"这类），会落到第 76 行，**过了截止 24 小时就被判 `missed`**——这才是真正的「超时失败」。

AI 提示词本身没问题：`review.system.md` 里活动看不到结果只会给 `need_evidence`，不会乱判 fail。所以**不要动提示词**。

## 二、规格

### 2.1 活动不再显示「逾期」

`src/shared/format.ts` 的 `fmtRemaining`，把

```
if (diffHours < 0) return '逾期'
```

改成：已过截止时，活动（`type === 'event'`）返回**空串**，其余类型（`deadline`）照旧返回 `'逾期'`。

- 只动这一行（或这一行的返回值），**下面所有分支一个字都不要动**：活动未到期时仍要正常显示 `7d` / `2h` / `明天` 那套。
- 函数上方注释补一句：活动的结果由外部判定，超时既不失败也不催，过截止就不再显示剩余时间。
- 这个函数同时被主进程（提醒负载 `remainLabel`、MCP 的 `remaining`）调用，改一处三处生效，**不要在其他地方另写判断**。

### 2.2 活动不吃超时判定

`src/renderer/main/features/tasks/reviewFlow.ts` 的 `decideReview`，把第 74-76 行那两行换成按下面顺序的分支（`pass` / `need_evidence` 那两条**保持原位不动**，在它们之后）：

1. `task.type === 'event'` 时：
   - `verdict.verdict === 'fail'` → 仍返回 `'missed'`（**结果不达标仍然算没完成，这是产品口径，别一起删掉**）
   - 其余（`partial`）→ 一律返回 `'revive'`，**不看 `dueAt`**
2. 非活动：照旧 `isOverdue(task.dueAt, now) ? 'missed' : 'revive'`。

即活动任务的**时间维度彻底退出判定**，只剩"AI 明确判不达标"这一条失败路径。

函数上方那段「活动（`type === 'event'`）的 `fail` 无条件判 `missed`……」的注释要跟着改：写清现在活动只看 `fail`、`partial` 与时间无关，`isOverdue` 只服务限时任务。

`OVERDUE_GRACE_MS` 与 `isOverdue` 本身**不改**，它们继续只管限时任务。
