# 44b · 修一处：记忆行编辑态被另一行的提交收掉

> 基线：`58f2bd5` + 44（W12B）未提交改动。**只改一个文件**
> `src/renderer/main/features/settings/SettingsDrawer.tsx`（`MemoryBlock` 内）。
> 不许动其它文件、不许调样式、不许顺手改别的东西。

## 1. 现象（44 审核时发现，点一下必现）

编辑记忆 A（改了字、没按回车），直接点记忆 B 的内容：**B 的输入框一闪就没了**，B 之后改了也存不上。

## 2. 根因

`commitEdit` 的 `.then` 里**无条件** `endEdit()`，而 `endEdit` 清的是组件级的
`editingId` / `draft` —— 它不知道用户已经切到另一行了。

时序（点 B 的那一瞬）：

1. mousedown → A 的 input 失焦 → `commitEdit(A)` 置 `closing=true`、发 IPC（异步）；
2. click → `beginEdit(B)`：`editingId = B`、`draft = B 原文`；
3. A 的 IPC 返回 ok → `endEdit()` → `editingId = null`、`draft = ''` → **B 的编辑框被收掉**；
4. 且 `endEdit` 顺手把 `closing` 置回 `true`，B 之后就算失焦也不会保存。

不是竞态（不需要拼手速），本地 IPC 往返一定晚于同一次手势里的 click。

## 3. 改法（3 处，规则写死）

1. 加一个 ref `editIdRef: useRef<string | null>(null)`：
   - `beginEdit` 里写 `memory.id`；
   - `endEdit` 里置 `null`。
   它与 `editingId` 同步换值，但**异步回调里读它拿到的是最新值**（`editingId` 在 `.then` 闭包里停在提交那一帧）。
2. `commitEdit` 成功后，只在「此刻仍在编辑这一行」时收尾：

   ```text
   if (editIdRef.current === memory.id) endEdit()
   ```

   否则什么都不做 —— 别清 `editingId`、别清 `draft`，另一行的编辑态照旧。
3. 失败分支**不变**（留在编辑态、错误原文落块底）。

`commitEdit` 的依赖数组不需要加 `editIdRef`（ref 稳定）。其余逻辑一律不动。

## 4. 验收（2 条）

1. 点记忆 A 改两个字（不按回车），直接点记忆 B 的内容 → **B 的输入框保持打开**，能继续改，回车后生效。
2. 接着点回 A 的内容 → A 显示的是刚才改后的新字（说明 A 那次提交真落库了，没被收尾动作丢掉）。

## 5. 交付

贴 `git diff`（这一步 `SettingsDrawer.tsx` 还是未跟踪文件，可能为空，那就手写 hunk）+ 四命令结果。**不提交**。

## 6. 已知未修（不在本单范围）

`closing.current` 仍是组件级单例：若 A 的提交**失败**返回时 B 正在提交，会把 B 的 `closing` 复位成 `false`，
表现为 B 的失焦可能多存一次同样的内容（幂等，无数据损坏）。要修需按行维护一组 flag，另开单。
