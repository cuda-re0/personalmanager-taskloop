# 58 · 提醒骨架：调度 + 双窗口（v0.58，W8A）

> **类型**：功能新增（走外部施工方）。**这是 W8 的第一半**：只做「截止/发生之前」的提醒，逾期提醒与失败状态在 59。
> **需求原话**：用户 2026-11-01「关键是怎么提醒」。
> **裁决**（用户逐条选定）：
> - 提醒手段**只有两种，都做成自建窗口**，不用 Windows 原生通知；
> - 轻 = 顶部横幅（悬在屏高 1/4 处、点一下消失、不开任何窗口）；
> - 重 = 屏幕中间小窗（关掉算收到、任务状态不变）；
> - **每日任务不弹提醒**；
> - 分级：限时前面全轻、最后一次重；活动前面全重、最后一次轻；
> - 程序靠 HUD 常驻（关主窗不退出，已确认无需托盘）。

## 2. 分级规则（写死）

`level` 复用现成枚举 `ReminderLevel = 'normal' | 'strong'`，不新增字段：

| 场景 | 轻 `normal`（横幅） | 重 `strong`（小窗） |
|---|---|---|
| `daily` 任务 | **不生成任何提醒** | — |
| `deadline` | 前 N−1 条 | **最后一条** |
| `event` | **最后一条** | 前 N−1 条 |
| 只有 1 条时 | `deadline` → 无 | `deadline` → 那一条；`event` → 无 |

即：按 `fire_at` **升序**排列后，`deadline` 的最后一条是 `strong`、其余 `normal`；`event` 的最后一条是 `normal`、其余 `strong`。`event` 只有一条时就是那一条 `normal`。

## 3. 改动清单

### 3.1 纯函数（新建 1 文件）

`src/main/services/reminderPlan.ts`，导出：

```
planReminders(task: Task, now: Date): { offsetMin: number; fireAt: string; level: ReminderLevel }[]
```

规则（写死）：

1. `task.status` 不是 `todo` / `doing` → 返回 `[]`。
2. `task.type === 'daily'` → 返回 `[]`。
3. `task.dueAt === null` 或 `task.reminderOffsets.length === 0` → 返回 `[]`。
4. 每条 `offsetMin` 的 `fireAt = dueInstant(dueAt) + offsetMin * 60_000`，转回 ISO 字符串。
5. **只要 `fireAt > now` 的**（严格大于，等于也不算）。过去的直接丢，不补发。
6. 按 `fireAt` 升序排序后再分配 `level`（规则见 §2）。
7. 排序用 `fireAt` 字符串比较即可（ISO 同格式可字典序比较），**不要用 offsetMin 排序**——日/月级任务下 offset 与 fire_at 不同序。

### 3.2 提醒服务（新建 1 文件）

`src/main/services/reminderService.ts`，导出四个函数：

- `syncForTask(taskId)`：`planReminders` → `reminderRepo.replaceForTask(taskId, rows)` → 返回 `Reminder[]`。`rows` 的字段按 `ReminderInsert` 填，其中 `level` 用 plan 的值，`channels` 用 `task.reminderChannels`，`status: 'active'`。
- `syncAll()`：对全部 `todo` / `doing` 任务跑一遍 `syncForTask`。
- `fireDue(now)`：取 `reminderRepo.listDue(now)`（按 fire_at 升序），逐条 `fireOne`。
- `fireOne(reminder)`：写一条 `messages(kind='reminder')` → 广播 `message.appended` → `markFired` → 交给窗口队列。

`fireOne` 细节（写死）：

- 消息用 `messageService.appendMessage`，`threadId: 'main'`，`meta` 按 `MessageMeta` 的 `reminder` 分支填全五个字段；`title` 取任务标题；`offsetMin` 取 `reminder.offsetMin`。
- `firedChannels` 记 `['inapp']`（本单只有站内）。
- 消息写入成功后才 `markFired`，**顺序不许反**：反了就会"标了已触发但消息丢了"，以后再也弹不出来。

### 3.3 调度器（新建 1 文件）

`src/main/scheduler/reminderScheduler.ts`，导出 `startReminderScheduler(): () => void`（返回停止函数）。

- **每 30 秒**扫一次（`setInterval`，常量 `REMINDER_TICK_MS = 30_000`），不用 `setTimeout` 到最近一条 + 心跳的双机制——30 秒误差对「提前 1 小时」完全够，且休眠唤醒后自然对齐。
- 启动时先跑一次「补发判定」：`listDue(now)` 里 **`now - fire_at ≤ 10 分钟`** 的，**只取最近 1 条**弹；更早的一律 `markFired` 不弹（关键：不许开机弹一堆历史提醒）。
- 每次 tick 调 `reminderService.fireDue(new Date())`。
- 在 `src/main/index.ts` 的 `app.whenReady` 之后启动，`before-quit` 里停（跟 `reviewSweeper` / `fxSweeper` 同一处，照抄它们的写法）。

## 8. 验收（用户真机手点，施工方不自验这几条）

1. 建一个限时任务，截止设在**明天这个点**（约 24 小时后），偏移留默认 `[-1440, -60]` → 两条都在未来：`-1440` 那条在 1 天后到点，按裁决是「前面的一条」= **轻**，应出现屏幕上方 1/8 屏高处的横幅。**注意：只有一个偏移存活时它必然是"最后一次"，限时=强、活动=轻**——所以只留 `-60` 的任务只会弹小窗，看不到横幅，这不是 bug。
2. 点横幅 → **立刻消失**，主窗没被打开。
3. 建一个限时任务，截止设在**65 分钟后**（默认 `-1440` 落过去被过滤、`-60` 剩 5 分钟）→ 约 5 分钟后弹出**屏幕中间 480×300 的小窗**（唯一存活的一条即"最后一次"）。
4. 建一个**活动**、发生时间 **2 小时后**、把偏移改成只留 `-60`（唯一存活的一条 = "最后一次"）→ 到点弹的是**横幅**，不是小窗。
5. 每日任务（比如「11 点前睡着」）到 daily_time 时**什么都不弹**。
6. 两条提醒同一时刻到点 → **只出现一个窗口**，关掉它之后**再弹第二个**。
7. 会话区能看到一条提醒消息，hover 出现「稍后提醒」→ 点它 → 15 分钟后**再弹一次**。
8. 关掉主窗（只留 HUD）→ 到点**照样弹**（程序没退出）。

## 9. 已知风险（不改，写在这里防扯皮）

- 窗口是自建的，**不进 Windows 通知中心**，离开电脑时看不到、回来也没有记录（只留会话区那条消息）。这是用户已知并接受的代价。
- 提醒**不自动消失**，所以一条不点掉，后面的提醒只写消息、不入队超过 5 条。用户已确认这个行为。
- 30 秒心跳意味着提醒可能晚最多 30 秒，对「提前 1 小时」无影响。
- 电脑休眠唤醒后，休眠期间的提醒会被判为"错过"，只有 10 分钟内的补 1 条，更早的只写消息不弹。
- 同一条提醒重复 `sync` 会重建 active 行——如果正好在 fire 的瞬间 sync，理论上可能漏弹一次。概率极低，不做互斥。
