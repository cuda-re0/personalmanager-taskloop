## 0. 为什么有这一单

W12 已经交付：`personas` / `memories` 两张表、六条 IPC（`persona.get/update`、`memory.list/add/update/remove`）、记忆自动提取、人物卡进 system prompt——**全都能跑，但全是后台数据，用户看不见也改不了**。「手动改记忆」这条裁决因此退化成"只能靠自动提取"，等于没做。

主窗目前**没有任何设置页**：`AppHeader.tsx` 的注释明写「04 §2 图里的 [设置] 归设置页，本轮不渲染——放一个点不动的按钮比不放更糟」。这一单就是把那个按钮点亮。

## 1. 已定的四条技术裁决（不要改）

| 裁决 | 内容 | 理由 |
|---|---|---|
| key 状态 | **新增一条 IPC `ai.keyStatus`**，返回 `{ configured: boolean }`，不联网 | 现成的 `ai.health()` 会**真发一次带图请求**探测多模态（`aiService.ts:679`），为显示一行状态花这笔钱不值，而且它 `await` 探测结果，慢的时候整行会一直挂着 |
| 模型名 | **两个模型名只读**，不给输入框、不给保存 | 改成不存在的模型名会让建任务与审核**全线失败**，而项目里没有恢复入口。要看不要改 |
| 清空记忆 | **不做「清空全部」** | 02 §3.8 已写死：「没有任何清空全部通道，批量删除属危险操作」 |
| key 输入 | **不做 key 输入框** | `ai/config.ts:141` 明写「`writeKey` 只留给将来的设置页，**不许注册成 IPC**」 |

## 2. 用户已裁决的四个界面决定（照做，不要换形态）

1. **形态 = 右侧抽屉 + 遮罩压暗**（不是弹窗、不是整窗切页）。
2. **人物卡 = 显式 `[保存]` 按钮**，有脏值才亮；不是即时保存。
3. **记忆 = 行内编辑 + 每行一个 `[删除]`**，新增入口在列表底部。
4. **语气三项文案 = `温柔` / `直率` / `活泼`**（对应存库 `warm` / `plain` / `playful`）。

## 5. 界面规格

### 5.1 顶栏按钮（`AppHeader.tsx`）

- 位置：`[悬浮条开关]` **右侧**（04 §2 图：右 `[悬浮条开关] [设置]`），两者间距 12px。
- 外观：无边框、透明底、`--text-sub` 字、13px、`padding: 4px 10px`、`border-radius: var(--r-sm)`；hover 底色 `--bg-hover`、字色 `--text`。
- 可见文字只有 `设置`，**不加图标**。
- `AppHeader` 新增 prop `onOpenSettings: () => void`，按钮 `onClick` 调它。开关那一整套逻辑**一行都不许动**。

### 5.2 抽屉（`SettingsDrawer.tsx` + `settings.css`）

| 项 | 规格 |
|---|---|
| 遮罩 | `position: fixed; inset: 0; background: rgba(0,0,0,.18); z-index: 40`；点击关闭 |
| 面板 | `position: fixed; top:0; right:0; bottom:0; width:420px; z-index:41`；`background: var(--bg)`、`border-left: 1px solid var(--border)`、`box-shadow: var(--shadow-float)`；内部纵向 flex，内容区 `overflow-y:auto` |
| 标题栏 | 高 56px，左 `设置`（15px / 500），右 `×` 按钮（28×28、`aria-label="关闭"`） |
| 关闭方式 | 三种：点遮罩、点 `×`、按 `Esc`。**不做**确认、不做动画过渡（直接出现/消失即可，别为 200ms 动画引依赖） |
| 挂载 | `{open && <SettingsDrawer ... />}`，**关闭即卸载**，每次打开重新拉数据 |
| 焦点 | 打开时焦点移到面板根元素（`tabIndex={-1}` + `focus()`）。**不做 focus trap、不做关闭还焦**——项目没有焦点管理设施，做一半比不做更怪 |
| 无障碍 | 面板根 `role="dialog"` + `aria-modal="true"` + `aria-label="设置"` |
| 响应式 | 不做。最小窗宽 980，420 永远放得下 |

`Esc` 的一个坑：**记忆行处于编辑态时，`Esc` 只退出编辑，不许顺手把抽屉关了**。编辑态的 keydown 处理里必须 `stopPropagation()`（或让抽屉的监听判断"当前是否在编辑"，二选一，你定，但行为要写死）。

### 5.3 人物卡块

| 元素 | 规格 |
|---|---|
| `名字` | input，`maxLength={20}`，初值 `persona.name` |
| `怎么称呼我` | input，`maxLength={20}`，初值 `persona.userCall`；空串合法（prompt 里回落成「你」） |
| `人设` | textarea，`rows={5}`、`maxLength={800}`、`resize: vertical`，初值 `persona.personaMd` |
| `语气` | 三个按钮横排，`aria-pressed` 标当前项；选中态 `--accent-weak` 底 + `--accent` 字，未选 `--border` 描边 + `--text-sub` 字。顺序固定：`温柔` `直率` `活泼` |
| `[保存]` | 主色按钮。**`disabled` 判据 = 无脏值 或 保存中**。无脏值 = 表单与"已保存快照"逐字段相等 |
| 保存动作 | 只提交**有变化的字段**（`persona.update` 是局部更新）。成功后：用返回的 `Persona` 覆盖表单与快照 → 按钮回禁用 → 显示 `已保存` 1.2 秒 |
| 失败 | 后端 `message` 原文显示在 `[保存]` 左侧（12px、`--danger`），不弹窗、不 Toast。**不做前端判空**：`name` 清空后仍可点保存，让后端报「助手名字不能为空」——一套规则比两套好 |

### 5.4 记忆块

| 元素 | 规格 |
|---|---|
| 列表 | 按后端给的顺序渲染（`memory.list()` 已 `updatedAt` 降序），**前端不重排** |
| 行布局 | `[内容 flex:1]` `[角标 身份 · 自动]` `[删除]`；行高 ≥ 32，行间 `1px` 分隔线用 `--border` |
| 进入编辑 | 点内容区 → 整行内容变 input（`maxLength={120}`，自动聚焦、光标置尾） |
| 保存编辑 | `Enter` 保存、失焦保存。调 `memory.update({ id, contentMd })`，成功后用返回值替换该行 |
| 取消编辑 | `Esc` 退出编辑并还原原文，**不调 IPC**；因 `Esc` 引起的失焦**不许**再触发一次保存 |
| 无变化 | 内容与原文相同、或 `trim()` 后为空 → 直接退出编辑，不调 IPC |
| 删除 | 调 `memory.remove({ id })`，成功后从列表移除；**无二次确认**（02 §3.8）。删除中该行按钮 `disabled` |
| 新增 | 底部一行：input（`maxLength={120}`、`aria-label="新的记忆"`）+ select（`aria-label="记忆类型"`，三项 `身份`/`偏好`/`事实`）+ `[添加]` |
| `[添加]` 判据 | `trim()` 后为空 → `disabled`。其余交给后端 |
| 新增成功 | 清空输入框；把返回的 `Memory` 插入列表**首位**；若返回的 `id` 已在列表里（02 §3.8：重复内容返回已有那条、不报错）→ **不重复插入**，列表不动即可。**不许**显示"已存在"之类自造提示 |
| 上限 50 | 前端**不预判**。撞上限就显示后端原文「记忆已达 50 条，请先删几条」 |
| 空列表 | 什么都不渲染（不许占位文案） |

### 5.5 AI 块

三行只读 key-value，值右对齐。数据来源：

- `任务模型` ← `bootstrap.settings['ai.provider'].model`
- `聊天模型` ← `bootstrap.settings['ai.chat.model']`
- `API Key` ← `ai.keyStatus()` 的 `configured` → `已配置` / `未配置`

模型名可以用 `--mono` 字体，`设置` 里没有输入框、没有编辑按钮、没有"修改"入口。

## 7. 渲染层结构（职责边界，别混）

### 7.1 `settingsModel.ts`——纯函数 + 三张表（node 环境可测）

| 导出 | 语义 |
|---|---|
| `TONE_LABEL: Record<PersonaTone, string>` | `{ warm: '温柔', plain: '直率', playful: '活泼' }` |
| `KIND_LABEL: Record<MemoryKind, string>` | `{ profile: '身份', preference: '偏好', fact: '事实' }` |
| `SOURCE_LABEL: Record<MemorySource, string>` | `{ auto: '自动', manual: '手动' }` |
| `toPersonaForm(p: Persona): PersonaForm` | 取四个可编辑字段，丢掉 `id`/`createdAt` 等 |
| `diffPersona(form, saved): PersonaPatch \| null` | 逐字段比较，**只返回有变化的字段**；全等返回 `null`；**不做 trim**（原样提交，与契约一致：字符数校验在主干） |
| `canAddMemory(raw: string): boolean` | `trim()` 后长度 1~120 |

`PersonaForm` = `{ name; userCall; personaMd; tone }` 定义在这个文件里，`PersonaPatch` 直接用 `Api` 里 `persona.update` 的入参类型（不要另抄一份）。

### 7.2 `useSettingsData.ts`

- 打开时并发：`persona.get()` + `memory.list()` + `ai.keyStatus()`；`settings` 从 `app.getBootstrap()` 里取，**不要为两个模型名单独开通道**。
- 返回一个 `SettingsData`：`persona` 表单、`saved` 快照、`memories`、`keyStatus`、`models`、`saving`/`busyId`、`error`（各块一个字段，不要一个全局 error 串到三块）、`notice`（只有 `已保存` 用）。
- 所有 IPC 结果按项目既有约定处理：`res.ok === false` → 把 `res.error.message` 放进对应块的 error。
- **不做乐观更新**：等返回值再改本地列表/表单。单用户界面，没有延迟问题，做乐观更新只会多出一套回滚。

### 7.3 `SettingsDrawer.tsx`

- 纯展示：所有状态与动作从 `data` 拿，**组件内不许直接 `window.api.*`**（wiring 测试会查）。
- 三个块可以拆成同文件内的小函数组件（不要求拆文件），但**不许**为此新增第 5 个文件——白名单只有上面那些。
