## 一、问题与定性

91 单让任务带上 `plannedDay`（打算哪天做），并且任务栏只显示 `plannedDay <= 今天` 的任务。结果是：**未来的计划任务从界面上彻底消失**——任务栏看不见，日历也看不见（`calendarModel` 的 `dayIndex` / `dayDetail` 全走 `due_at`）。

于是产生了两个直接后果：

1. 用户没法确认 AI 到底有没有填计划日。填了看不见，不填也看不见，等于整条 AI 链路无法验证。
2. 「整份长期计划哪天分了什么」这件事在界面上不存在，用户只能一条条点开任务看。

本单给它一个专门的地方：顶栏一个「计划」按钮，点开把右栏下半整块换成按天分组的只读列表。

## 二、规格

### 2.1 分组模型（新建 `src/renderer/main/features/plan/planModel.ts`）

纯函数模块，只 import `Task` 类型，不引 react / electron / db。

导出：

```ts
export interface PlanDayGroup {
  day: string
  tasks: Task[]
}

export function groupByPlanDay(tasks: Task[]): PlanDayGroup[]
```

规则按顺序：

1. 只收 `plannedDay !== null` **且** `parentId === null` 的任务。子步骤（父任务的 steps 落成的子任务）不进计划视图。
2. 按 `plannedDay` 分组成天，**同一 `plannedDay` 的任务必须在同一组**。
3. 组按 `plannedDay` 字符串升序（两边都是 `YYYY-MM-DD`，字典序即日期序，**不要**转 `Date`）。
4. 组内三级排序：`sortKey` 升序 → `createdAt` 升序 → `id` 升序。三级都相同才视为并列，保证结果稳定。
5. 不改入参数组、不改任务对象。

文件头注释写明：这是**只读视图的数据整形**，不做任何「顺延到今天」「滚动搬运」的逻辑；已完成的条目照常留在原来那一天，不移动。

### 2.2 数据 hook（新建 `src/renderer/main/features/plan/usePlanData.ts`）

导出 `usePlanData(): { tasks: Task[] }`，行为：

1. 首载调 `window.api.task.list({ status: ['todo', 'doing', 'pending_review', 'reviewing', 'done', 'missed'] })`。成功 `setTasks(res.data)`；失败 `console.error('[plan] task.list 失败', res.error)` 并保持空数组。
2. 订阅 `window.api.onEvent`：`event.type` 以 `'task.'` 开头时重新拉一次（与 `useTasksData` 同口径——单窗口、量级小，重拉比维护本地 diff 简单且不漂）。
3. 卸载时调 `onEvent` 返回的清理函数退订。
4. **不设 loading 态、不写错误 UI**（项目惯例：无数据留白）。

`status` 必须显式传全 6 个。不传的话 `taskRepo.list` 默认只返回 `todo / doing / pending_review / reviewing` 四个活跃态，已完成的历史条目会从计划里消失。
