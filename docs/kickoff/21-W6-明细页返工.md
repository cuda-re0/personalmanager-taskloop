## 2. 问题一（P1，必修）：从上一月的 `›` 回不到本月

### 2.1 实测证据（架构方在 `4be440b` 上用真实源码跑出来的）

```
canGoNext(2026-09-01, today=2026-10-29) = true      ← 按钮是亮的
stepMonthOf(2026-09-01, +1, 2026-10-29) = 2026-09-01 ← 点了不动
```

用户路径：明细页点 `‹` 退到 9 月 → 想回 10 月 → 点 `›` → **没反应** → 只能点 `←` 退出明细页重进。

跨月也会中：10 月就开着应用过夜到 11 月 1 日，`canGoNext(2026-10-01) = true`，点 `›` 仍然不动。

### 2.2 根因（理解它，别只改符号）

你在同一个谓词上问了两个不同的问题：

| 问题 | 谁问的 | 正确判据 |
|---|---|---|
| 当前所在月**还能不能往后翻**（按钮灰不灰） | `canGoNextMonth(month)` | `month < 本月` ✅ 你写对了 |
| **这一次翻月的落月合不合法**（翻月算不算数） | `stepMonthOf` 里的守卫 | `next <= 本月` ❌ 你复用了上面那个 `<` |

`next = 本月` 时，第一个问题答 false（对，本月不能再往后），第二个问题也答 false（**错，落到本月是合法的**）。于是「上月 → 本月」这一格永远失效。

### 2.3 改法

`stepMonthOf` 的守卫从「落月还小于本月」改成「落月不晚于本月」：

```ts
export function stepMonthOf(month: string, delta: number, today: string): string {
  const next = shiftMonthOf(month, delta)
  return next <= monthStartOf(today) ? next : month
}
```

`canGoNextMonth` **不要改**，它的语义是对的。`shiftMonthOf` 也不要改。

### 2.4 必须补的测试（缺一条我都退回去）

```
stepMonthOf('2026-09-01',  1, '2026-10-29') === '2026-10-01'   // 上月 → 本月，就是这次漏的那格
stepMonthOf('2026-10-01',  1, '2026-10-29') === '2026-10-01'   // 本月 → 原地（原有）
stepMonthOf('2026-10-01',  1, '2026-11-03') === '2026-11-01'   // 跨月后，10 月能前进到 11 月
stepMonthOf('2026-08-01',  1, '2026-10-29') === '2026-09-01'   // 前两月 → 次月
stepMonthOf('2025-12-01',  1, '2026-01-01') === '2026-01-01'   // 跨年 → 新年本月
```

再加一条**不变量**测试，把「按钮亮着就必须动」写死：

```
对过去 24 个月逐一断言：canGoNextMonth(m, today) === true  ⇒  stepMonthOf(m, +1, today) !== m
```

这条比单个用例值钱，以后谁再把两个谓词混到一起，测试直接红。

## 3. 问题二（P1，必修）：打开明细页不许卸载工作台

### 3.1 现在的行为

`index.tsx` 是二选一渲染：

```tsx
{view === 'workbench' ? (<div className="app-shell">…工作台…</div>) : (<LedgerPage … />)}
```

`view` 一变 `'ledger'`，整个工作台（`ChatPanel` + `TasksPanel` + `CalendarPanel` + `PointsPanel`）**被卸载**。于是：

- `ChatInput` 里的 `value` / `files` 是组件内 `useState` → **输入框草稿和已附的图片直接消失**；
- `useChatData` 的 `sending`、消息列表、滚动位置全部重来，`←` 回来会重新拉一遍消息、闪一下；
- 用户正在等 AI 回复时点开明细，回来看到的是清空后的输入框。

**数据丢失就是 P1**，不能留到下一轮。

### 3.2 目标

明细页**覆盖**在工作台之上。工作台在明细页打开期间**保持挂载**，只是不可见、不可点、不可聚焦。`←` 回来时一切原样，不重新拉数据、不闪、不丢。

### 3.3 做法（照这个方向，细节你定）

```tsx
<div style={{ display: 'flex', flexDirection: 'column', height: '100%' }}>
  <AppHeader />
  <div style={{ position: 'relative', flex: '1 1 auto', minHeight: 0 }}>
    {/* 工作台：永远挂载，靠内联 style 隐藏 */}
    <div
      className="app-shell"
      style={{ flex: '1 1 auto', minHeight: 0, height: 'auto', display: view === 'ledger' ? 'none' : 'flex' }}
    >
      <ChatPanel />
      <aside className="right-col">…</aside>
    </div>
    {view === 'ledger' && <LedgerPage … />}
  </div>
</div>
```

**坑，必须避开**：不要用 `hidden` 属性。`.app-shell` 自己有 `display: flex`（`features/tasks/tasks.css`），类选择器的 `display` 会盖掉 UA 的 `[hidden] { display: none }`，结果就是"隐藏了但还在"。只能用**内联 style**——内联优先级最高。

**要实测确认的一件事**：`display: none` 再显示，消息列表的滚动位置会不会复位到顶部。
- 不在意复位 → 用上面的 `display` 方案，收工。
- 在意 → 换成覆盖式隐藏：工作台 `position: absolute; inset: 0; visibility: hidden; pointer-events: none;`，`LedgerPage` 同时 `position: absolute; inset: 0`（或 `relative` + `z-index`）。这样布局还在，滚动位置保住。
- 报告里写清你选了哪个、以及滚动位置实测是什么结果。

### 3.4 连带的好处：那条"延后派发"可以删了

你上一单第五节第 3 条的偏离（`pendingFocus` + `useEffect` 里 `emitFocusTask`），根因就是「① 被卸载了、监听没挂」。工作台不再卸载之后，`useTasksData` 一直在订阅，**直接同步派发即可**：

```tsx
const openTask = useCallback((taskId: string) => {
  setView('workbench')
  emitFocusTask(taskId)   // 同一次交互里完成，回到契约 §5 的字面写法
}, [])
```

`pendingFocus` 状态与那个 `useEffect` **删掉**。同时把 `ledgerPageWiring.test.ts` 里断言 `pendingFocus` 形状的那条（`focus-task 在挂载之后派发`）改成断言「`openTask` 里同时有 `setView('workbench')` 和 `emitFocusTask(taskId)`」。

### 3.5 必须补的测试

- 源码断言：`index.tsx` 里工作台的 `<div className="app-shell">` **不在** `view === 'workbench' ?` 的三元里（即它不在条件分支中），且带 `display: … 'none' : 'flex'` 这类受 `view` 控制的内联样式。
- 源码断言：`pendingFocus` 已从 `index.tsx` 消失。
- 这两条都是源码断言（项目没有 DOM 栈），只能锁形状、锁不住行为——**行为必须靠 §6 的手点**，报告里写清你怎么点的。
