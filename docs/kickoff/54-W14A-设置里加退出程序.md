## 2. 规则（逐条写死，别发挥）

### 2.1 交互

- **点了就退，不弹确认、不做二次确认、不加 loading 态。** 用户明确选了"直接退，不问"。
- 退出语义 = **整个应用进程结束**：主窗、HUD 悬浮条、两个后台 sweeper 一起没了。不是"关掉设置抽屉"，也不是"最小化到托盘"。
- 不 await 退出结果：`app.quit()` 一旦生效，渲染进程就没了，Promise 不会正常回来。**不许**在它之后 `setState`、不许置"正在退出"标志。

### 2.2 文案（只准一个字面量）

界面上新增的中文**只有一个**：`退出程序`。

- **不许**加区块标题（不要 `应用`、`其他`、`危险操作` 这类小标题）。
- **不许**加任何说明、提示、副标题、图标、`aria-label`（按钮文字本身已经够读）。
- **不许**用自己的措辞替换 `退出程序`。

### 2.3 位置与形态

- 在 `settings-body` 内、AI 区块**之后**，新增一个 `section.settings-block`（沿用现有块间距 `.settings-block + .settings-block`）。
- 块里只有那一个按钮，右对齐（与 `.settings-save-row` 的 `justify-content: flex-end` 一致）。
- 按钮视觉用危险色：文字与描边取 `var(--danger)`，hover 反色（底色 `var(--danger)`、文字 `#fff`）。高度/圆角/字号与现有 `.settings-save` 一致（padding `6px 16px`、`var(--r-sm)`、`13px`）。

## 3. 逐文件改动

### 3.1 `src/renderer/main/features/settings/useSettingsData.ts`

1. `SettingsData` 接口加一个动作：

   | 成员 | 签名 | 语义 |
   |---|---|---|
   | `quit` | `quit(): void` | 退出整个应用，fire-and-forget |

2. 实现一个 `useCallback` 的 `quit`：
   - 调 `window.api.app.quit()`
   - 加 `.catch`，失败只 `console.error('[settings] app.quit 调用失败', e)`，**不做任何 UI 反馈**（进程都要没了，报错框没有意义，也违反 §2.2 不许加文案）
   - 不设任何 state

3. 放进 `useMemo` 的返回值与依赖数组（依赖为空数组，因为它不读任何 state）。

> 为什么必须放这里而不是组件里：§1 第 5 条，抽屉组件不许出现 `window.api`。

### 3.2 `src/renderer/main/features/settings/SettingsDrawer.tsx`

1. `settings-body` 末尾（`<AiBlock data={data} />` 之后）加：

   ```
   <section className="settings-block settings-quit-block">
     <button type="button" className="settings-quit" onClick={data.quit}>
       退出程序
     </button>
   </section>
   ```

   类名就用这两个，不要另造名词；`onClick` 直接引 `data.quit`，不要在 JSX 里包一层箭头函数（wiring 测试按字符串断言，包一层也不影响，但保持一致更好写）。

2. 顶部文件注释（第 14–26 行）里补一句：右上角 `×` 只是关抽屉，真正退出应用是底部那个按钮。**这条注释里不许出现 §1 第 7 条那两个禁词表里的词**（尤其"重置"）。

### 3.3 `src/renderer/main/features/settings/settings.css`

新增两条规则，放在文件末尾（AI 区块样式之后）：

```
.settings-quit-block   →  display: flex; justify-content: flex-end;
.settings-quit         →  §2.3 指定的 padding / 圆角 / 字号 / 危险色 / hover 反色
```

`.settings-quit` 的 `cursor: pointer` 与 `font-family: var(--font)` 跟现有按钮对齐，别漏（漏了会显示成系统字体）。

### 3.4 `src/main/ipc/registry.ts`

`row(CH.app.quit, g.quit, () => { app.quit() })` 改成**先 quit、再挂一个硬兜底**：

| 顺序 | 动作 |
|---|---|
| 1 | `app.quit()` |
| 2 | `setTimeout(() => app.exit(0), 800)` |

理由：`app.quit()` 会被任何一个 `close` 事件里的 `preventDefault` 中止（现在没有，将来可能有），用户点了按钮却什么都没发生是最糟的体验。800ms 后进程还在就强杀。

- 兜底用 `app.exit(0)`（**不是** 再调一次 `app.quit()`），它会跳过 `before-quit`；本项目 `before-quit` 只 clearInterval，进程都没了不存在泄漏，注释里写清这一点。
- 现有那条注释（"无入参、无返回值、不广播、不落库"）保留，在后面补一句兜底说明。
- **不要**改成 `await`、不要加返回值、不要改 guards。

### 3.5 `tests/renderer/settingsWiring.test.ts`

1. `ALLOWED` 里加一项 `'退出程序'`（按现有顺序追加在末尾）。
2. 新增一条接线断言，放在「接线」describe 里，与现有两条并列：

## 6. 验收

1. 打开设置抽屉，滚到最底部 → 只有一个 `退出程序` 按钮，右对齐，没有标题、没有说明文字。
2. 点它 → 主窗、悬浮条、托盘区都没有残留进程；任务管理器里 `taskloop.exe` 归零。
3. 重开程序 → 数据都在（设置、任务、聊天记录），说明是正常退出而不是异常中断。
4. 抽屉里其它一切照旧：`×` / 遮罩 / `Esc` 仍然只是关抽屉。
