## 背景与事实

`TasksPanel.tsx:259-262` 给限时 / 活动组的行首渲染一颗 8px 圆点：

```tsx
className={`task-dot task-dot--${task.status === 'pending_review' ? 'reviewing' : task.status}`}
```

所以实际存在的类名是 `task-dot--todo` / `--doing` / `--done` / `--missed` / `--reviewing`。CSS 里只定义了 `--doing`（`--accent`）和 `--reviewing`（`--warn`），其余全部落到 `.task-dot` 基类。

v0.67 把基类从 `--text-faint` 改成了 `--text-sub`。两个都是灰，用户看不出变化；而用户要的映射与 v0.67 相反：**未完成要蓝，完成 / 过期要灰**。

## 目标映射

| task.status | 渲染类名 | 现状 | 改成 |
|---|---|---|---|
| `todo` | `task-dot--todo` | 落到基类 = `--text-sub` 深灰 | `--accent` 蓝 |
| `doing` | `task-dot--doing` | `--accent` 蓝 | 不变 |
| `done` | `task-dot--done` | 落到基类 = `--text-sub` 深灰 | `--text-faint` 浅灰 |
| `missed` | `task-dot--missed` | 落到基类 = `--text-sub` 深灰 | `--text-faint` 浅灰 |
| `pending_review` | `task-dot--reviewing` | `--warn` 橙 | 不变（「在等结果」的既有标记，不是完成也不是过期） |

`--text-faint` 与 v0.67 定下的「完成态下沉」同口径（每日组的已完成勾选圈也是它），两处灰必须同一个值。

## 改动（唯一文件：`src/renderer/main/features/tasks/tasks.css`）

1. `.task-dot` 基类**保持** `background: var(--text-sub)` 不变——它继续兜底未知状态，不再承担 `todo` 的颜色。
2. 新增 `.task-dot--todo { background: var(--accent); }`。
3. 新增 `.task-dot--done, .task-dot--missed { background: var(--text-faint); }`。
4. 注释口径：把现有那行 `/* 限时/活动组的状态点 */` 扩成一句状态映射说明——未完成（todo / doing）主色蓝、完成与过期（done / missed）浅灰、待审核（reviewing）橙。只写颜色事实，不写「系统判定」「说明」这类解释性文案，不新增任何可见文字。
5. 顺序约束：`.task-dot--todo` 必须写在 `.task-dot` 基类**之后**。两者同为单类选择器、优先级相同，靠后写覆盖；写在前面会被基类盖掉。
