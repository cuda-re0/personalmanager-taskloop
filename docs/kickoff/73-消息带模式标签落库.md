## 背景（用户实际遇到的问题）

用户在**任务模式**下发了一条消息「说啥呢，我作业交给老师，怎么给你看」，助手指令回了「行，交给老师就算完成，这单我给你记上了」，**这一轮没有产出任何草稿卡**。v0.69 的分层是按「这一轮的有没有 `task_draft` / `task_review`」推断的，没卡 → 判成聊天轮 → 这条任务模式的对话掉进了聊天层。

用户原话：「就不能在该模式下发的消息给消息上个标签，然后根据标签来选择呈现与输入吗。」

**根因**：`msg.send` 的入参 `mode` 一路传到了 `aiService.runTurn`（`aiService.ts:249`），但**落库时被丢掉了**——`messages` 表（`001_init.sql:76`）没有 mode 列，`Message` 类型（`domain.ts:150`）也没有这个字段。分层只能靠猜，猜不准就串层。

本单把模式写进库，分层直接读标签；老数据（无标签）继续按轮推断兜底。

## 事实（已由架构方核实，不要重新调研）

- `ChatMode = 'chat' | 'task'`（`domain.ts:345`）。注意**不是** `parse`，任务模式的值是 `'task'`。
- 迁移清单在 `src/main/db/migrations/index.ts`，只增不改，版本号 = `PRAGMA user_version`，现有最高 version 5。
- `MESSAGE_COLUMNS`（`mappers.ts:628`）同时用于 SELECT 与 INSERT，加列要三处同步：`MessageRow`、`MESSAGE_COLUMNS`、`messageInsertParams`。
- `appendMessage` 的调用点共 8 处：`aiService.ts:265 / 276 / 424 / 459 / 550 / 660`、`messageService.ts:27`（定义本身）、`reminderService.ts:95`。
- 测试里的 `Message` 字面量构造点共 5 处：`tests/renderer/chatLayers.test.ts:15`、`tests/renderer/chatViewModel.test.ts:104`、`tests/renderer/reviewFlow.test.ts:80`、`tests/ai/chatPipeline.test.ts:109 / 121`，以及 `src/renderer/main/features/chat/__fixtures__/messages.ts:245`。加了必填字段后这些全会报 TS 错，必须一起补。

`ChatMode` 已在本文件第 345 行定义，直接用，不新建类型。

### G. `src/renderer/main/features/chat/layerModel.ts`

G1. 新增导出：

```ts
export function layerOfMessage(message: Message): ChatLayer
```

规则（三条，按顺序）：

1. `layerOfKind(message.meta.kind)` 为 `'task'` → 返回 `'task'`（卡片与提醒永远是任务层，不受 mode 影响）。

3. 其余（含 `mode === 'chat'` 与 `mode === null`）→ `'chat'`。

G2. `layersOfMessages(messages)` 改成两段：

G3. 文件头注释补一句：**有标签的按标签，没标签的（v0.73 之前的老行）按轮推断兜底**。
