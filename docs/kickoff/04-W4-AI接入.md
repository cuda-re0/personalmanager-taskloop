## 第 0 步：先做真机验证，**不通过就停下来**

在写任何 pipeline 之前，先建一个 `scripts/verify-ai.mjs`，用真实 Key 做三件事：

1. 发一次**纯文本**请求 → 确认返回可解析的 JSON
2. 发一次**带图片**的请求（一张含中文的截图）→ 确认模型真的描述了图里的内容，**不是敷衍一句"这是一张图片"**
3. 打印返回体的 `usage` 字段

把结果写进 `docs/verify-ai-result.md`（新建）：模型名、是否支持图片、一次调用的 token 消耗、耗时。

**如果图片请求失败或模型明显没看图，立刻停下来报告，不要自己换模型、不要自己加中转。** 这是产品级取舍，要由我决定。

## 交付

### 1. `provider.ts` + `glmClient.ts`

按 `03-AI-CONTRACT.md` §3.0 的 `AiProvider` 接口实现**只有一个实现**：`glmClient`。

- 走智谱 `https://open.bigmodel.cn/api/paas/v4/chat/completions`
- 模型 `glm-5.3-flash`
- `response_format: { type: 'json_object' }`；若上游不支持则退化为 prompt 强制 + 剥 ```json 围栏
- 超时 45s，`AbortController` 可控
- 重试 1 次（仅 zod 校验失败时，把校验错误拼进第二次请求让它自修）

**`harnessClient` 不要写。** 只保证 `aiService` 依赖 `AiProvider` 接口而不 import `glmClient` 具体类。设置里 `ai.provider.name` 不是 `zhipu` 时抛 `CONFIG` 错误，**不许静默降级成直连**。

### 2. `prompts/`

```
system.base.md       # 人格、语言、铁律
parse.system.md      # 03 §4.1 的抽取约束
review.system.md     # 03 §4.2 的审核判定标准
parse.fewshot.json   # 3-5 组正例
```

prompt 必须写在主程序里，不许外置到任何服务。

**prompt 里绝对不许出现具体分值。** 写"这个任务值 20 分"这种示例，模型会照抄，积分体系就废了。模型只输出 `difficulty` 和 `estimate_min`，分数由 `rubric` 算。

### 3. `schema.ts`

用 zod 定义 `ParseResultSchema`、`ReviewResultSchema`，字段严格对齐 `03-AI-CONTRACT.md` §4。

要点：

- `type` 只接受 `daily | deadline | event`
- `requires_evidence` 布尔
- `confidence` 0~1
- `due_hint` 允许 `null`
- `verdict` 允许 `pass | partial | fail | need_evidence`

**用 `.strict()` 或显式剥掉多余键。** 模型多给的字段不许进业务层。

### 4. `pipelines/parse.ts`

消息（文本 + 图片）→ 多模态 payload → `ParseResult` → `TaskDraft[]`。

补齐三样：

- `localId = nanoid(8)`
- `pointsPlanned = computePlannedPoints(difficulty, estimateMin)`（从 `@shared/points/rubric` 调）
- 按 `type` 生成 `reminderOffsets`（`deadline` = [-1440, -60] 分钟；`event` = [-10080, -4320, -1440]；`daily` = 无）

### 5. `pipelines/review.ts`

接收 `{ task, subtaskStatus, userText, evidence[] }`，按 03 §4.2 判定。

**关键：`requiresEvidence = true` 而 `evidence` 为空时，直接返回 `verdict: 'need_evidence'`，不要调模型。** 这一步是硬闸门，不是让模型判断的。

### 6. `aiService.ts`

- 写 assistant 消息（`kind` 用 `text` 或 `task_draft`）
- 广播 `ai.status`（`thinking` / `streaming` / `idle`）
- 失败时落一条 `kind='error'` 消息，`retryable: true`
- 每次调用把 `tokens_in` / `tokens_out` / `latency_ms` 写回 `messages`

**永远不 throw 到 IPC 外面。** 界面上宁可出现一条错误气泡，也不能白屏。

### 7. `ai.health`

返回 `{ configured, provider, model, multimodal }`。

`multimodal` 必须靠**一次真实带图调用**探测并缓存结果，不许读配置猜。

### 8. Key 存储

用 Electron `safeStorage` 加密后存文件，或 `keytar`。**不许明文进 SQLite、不许进日志、不许进 git、不许出现在任何 console 输出。**

## 验收

- [ ] `docs/verify-ai-result.md` 已产出，且图片那次调用模型确实读到了图里的中文内容
- [ ] "明天下午三点前把季度报告初稿写完" → 1 个 draft，`type='deadline'`，`due_hint` 非空且合理，`requires_evidence=true`
- [ ] "每天早上背单词" → `type='daily'`，`daily_time_hint=null`，`requires_evidence=false`
- [ ] "下周三考英语六级" → `type='event'`，偏移为 7/3/1 天
- [ ] 一张含三条待办的截图 → 最多 3 个 draft，标题不能编造图里没有的内容
- [ ] 一句"今天天气不错" → `intent='chat'`，`tasks=[]`，正常回复
- [ ] 一句"报告写完了" → `intent='review_task'`
- [ ] `requiresEvidence=true` 且无证据 → 返回 `need_evidence`，**没有调用模型**（在日志里确认）
- [ ] 断网 / 401 / 超时 → 落 `kind='error'` 消息，带 `retryable`，进程不崩
- [ ] 让模型返回带 ```json 围栏的文本 → 能正确剥离并解析
- [ ] 全流程控制台与日志文件里搜不到任何 key 片段（包括前 6 位）
- [ ] `ai.provider.name` 填 `'harness'` → 报 `CONFIG` 错误，不静默降级
