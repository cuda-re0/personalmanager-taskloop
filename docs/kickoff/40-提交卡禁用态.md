# 40 · 提交卡禁用态：无证据时 `[提交]` 真的变灰（v0.40）

基线：`6643cc7`（39 已合入 `02976b9`）。四命令 **53 文件 / 669 条**绿。
只动 **1 个 css + 1 个测试文件**。不碰 tsx、不碰主进程、不碰 hud。

## 0. 用户裁定

问「禁用态修在哪一层」，答：**只补提交卡这一处**。不要给 `.btn:disabled` 加全局规则。

## 1. 现象与根因（别复读现象，先看根因）

现象：待提交卡没有证据时，`[提交]` 是 `disabled`，但看起来仍是蓝色实心可点，左边一行小字「还没有证据」在说反话。

根因不是「漏了个修饰类」，是 04 的口径没落地：

- `04-UI-SPEC.md` §3.2b 原文：「`[提交]` 证据数为 0 时 **`disabled`**（**灰**、点不动）」。
- `chat.css` 里 `.btn--primary` 只定义了常态与 `:hover`，**没有 `:disabled`**。
- `.btn` 基础规则写了 `color: var(--text)`，把浏览器 UA 对 `disabled` 的 `GrayText` 覆盖掉了 → 灰不起来。

同一文件里已有正确样板：`.ci-send:disabled`（发送键）。本单就是把这套搬到提交卡上，**不发明新观感**。

## 2. 改法（`src/renderer/shared/styles/chat.css`）

在 `.submit-card` 那一段后面（`.submit-hint` 之前或之后均可）新增**一条**规则：

- 选择器：`.submit-card .btn--primary:disabled`
- 四个属性，值与 `.ci-send:disabled` 完全一致：
  - `border-color: var(--border);`
  - `background: var(--bg-hover);`
  - `color: var(--text-faint);`
  - `cursor: default;`
- 再加一条 `opacity: 1;`

最后这条的理由要写进注释：`.btn--primary:hover { opacity: .9 }` 在禁用态下仍会命中（disabled 的按钮照样匹配 `:hover`），我们的选择器特异性更高能压住 `background`，但压不住 `opacity`，不写就会悬停时闪一下亮度。

**不许做的事**：

- 不许写成 `.btn:disabled` 或 `.btn--primary:disabled`（去掉 `.submit-card` 前缀就是全局规则，用户明确否掉了）。
- 不许用 `!important`。
- 不许改 `.btn` / `.btn--primary` / `.btn--primary:hover` 现有三条规则的任何一行。
- 不许动 `SubmitCard.tsx`（`disabled={disabled || evidence.length === 0}` 保持原样）。
- 不许加 `opacity: .4` 这类整块变透明的写法——那会让边框一起淡掉，和 `.ci-send` 的观感不一致。

## 3. 测试（`tests/renderer/ledgerViewWiring.test.ts`）

该文件已经在读 `chat.css`（`CHAT_CSS`），**不新建测试文件**，加一条 `it`：

- 断言 `CHAT_CSS` 含有 `.submit-card .btn--primary:disabled` 这一段（用正则匹配「选择器 + 花括号」，别只 `toContain` 选择器字符串，否则选择器写在注释里也能过）。
- 断言该段内同时含 `--bg-hover`、`--text-faint`、`cursor: default`、`opacity: 1`。
- 再加一条反向守卫：`CHAT_CSS` 里**不出现** `^\s*\.btn:disabled` 或 `^\s*\.btn--primary:disabled`（行首，不加前缀的那种），防止后人图省事铺成全局。
