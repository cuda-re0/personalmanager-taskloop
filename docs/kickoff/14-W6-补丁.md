你要做的：

## 四、④ 明细的 `[撤销]` 入口（04 §4④ 已写规格）

在 `src/renderer/main/features/points/`：

- 只对满足 `entry.reasonCode === 'task_done' && entry.occurrenceId === null && entry.reversedAt === null` 的流水行，行尾渲染 `[撤销]`（三个条件缺一不可）。
- 点它 → `api.task.undo({ id: entry.taskId })`（`taskId` 为 null 的行本来就不满足条件）。
- 成功后刷新明细与余额（走现有 `usePointsData` 的刷新路径，别新开一条）。已冲销行 `reversedAt` 非空，`[撤销]` 自然消失。
- 走的是"行内文字按钮"还是复用现有 `.ledger-row` 的样式，你自己定，**但不要新增任何说明文字、图例、tooltip**——只在行尾放 `[撤销]` 两个字。
- 超窗（>24h）的行**不预先隐藏**：渲染层不读 `completed_at` 算窗口，直接调通道，主进程报「超过 24 小时的完成记录不能撤销」时就地提示（走现有错误提示路径）。
- 每日打卡（`occurrenceId` 非空）的行不显示 `[撤销]`——每日的撤销在 ① 的勾选框，不在这里。
