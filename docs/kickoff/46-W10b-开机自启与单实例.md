## 3. 设计规格

### 3.1 新文件 `src/main/autoStart.ts`

导出四个东西，**纯逻辑与 IO 分开**（纯逻辑必须可单测）：

| 导出 | 签名 | 语义 |
|---|---|---|
| `AUTOSTART_FLAG` | `const AUTOSTART_FLAG = '--autostart'` | 全项目**唯一**一处字面量。别处禁止硬写 `'--autostart'` |
| `isAutoStart` | `(argv: string[]) => boolean` | **精确匹配**某个元素等于 `AUTOSTART_FLAG`。`--autostart=true`、`--auto` 一律 `false` |
| `loginItemArgs` | `(opts: { isPackaged: boolean; execPath: string; appPath: string }) => { path: string; args: string[] }` | 见下表 |
| `seedAutoStart` | `() => void` | 一次性播种（幂等、永不抛） |

**`loginItemArgs` 的两种形态（这是本单唯一的"聪明"处，别省）：**

| 场景 | `path` | `args` |
|---|---|---|
| 已打包（`isPackaged === true`） | `execPath` | `[AUTOSTART_FLAG]` |
| 开发期（`isPackaged === false`） | `execPath`（= `electron.exe`） | `[appPath, AUTOSTART_FLAG]`，`appPath` 含空格时自己加一层双引号 |

- 为什么开发期要带 `appPath`：`electron.exe` 单跑会去开默认窗口，必须把应用目录当第一个参数传进去。
- 为什么含空格才加引号：Windows 的 Run 键把 `path` + `args` 用空格拼成一条命令行，**Electron 不会替每个 arg 加引号**；含空格的 arg 会被拆成两个，应用起不来。本机路径不含空格，换目录就会炸，这层必须有。
- **不许**判平台（本项目 Windows only），别写 `darwin` / `linux` 分支。

**`seedAutoStart()` 的判定顺序（照抄，别改顺序）：**

1. 非 Electron 环境（`app` 不是对象、或 `app.getPath` 不存在，测试宿主就是这种）→ **直接 return**。判定写法照 `src/main/ai/config.ts` 的 `hasApp()`。
2. 标记文件已存在 → return（**已播过种，此后永不碰注册表**）。
3. `app.getLoginItemSettings().openAtLogin === true` → 不重复写，跳到第 5 步。
4. `app.setLoginItemSettings({ openAtLogin: true, ...loginItemArgs({...}) })`。
5. 写标记文件。

**标记文件**：`join(app.getPath('userData'), 'autostart.seeded')`，内容是 `new Date().toISOString()`（只为排查能看出哪次播的种，不参与任何判断）。

**失败处理**：第 3–5 步整体包 `try/catch`，异常只 `console.warn('[autostart] ...', e.name)`，**绝不 rethrow**。写注册表失败也照样写标记（环境问题重试无意义，反复重试反而每次启动都碰一次注册表）。标记文件写失败同样只 warn。

### 3.2 `src/main/windowManager.ts`

1. `createMainWindow(options: { show?: boolean } = {})` —— 新增可选参数，**默认 `true`**（既有调用点一个字不用改）。
2. `show === false` 时：`ready-to-show` **不** `show()`；窗口照建、渲染层照加载（IPC 照常就绪）。
3. 新增并导出 `getMainWindow(): BrowserWindow | null`——写法与 `getHudWindow()` 同款：句柄模块级、`closed` 时置 `null`、返回前判 `isDestroyed()`。
4. 新增并导出 `showMainWindow(): void`：

   ```
   const win = getMainWindow()
   if (!win) { createMainWindow(); return }   // 主窗被 × 关掉了：重建
   if (win.isMinimized()) win.restore()
   win.show()
   win.focus()
   ```

   - `createMainWindow()` 这里**不传** `{ show: false }`（要的就是弹出来）。
   - 这个函数是**唯一**的"叫出主窗"入口：`index.ts` 的 `second-instance` 与 `app:showMain` 的 handler **都**调它，不许各写一遍。

### 3.3 `src/main/index.ts`

1. **顶层、`whenReady` 之前**：

   ```

   if (!gotLock) { app.quit() }
   ```

   `whenReady().then(...)` 只在拿到锁的分支里注册。**不许**在拿不到锁时还继续建库、建窗、注册 IPC。

五处改动，缺一处 `typecheck` 就红：

| 文件 | 动作 |
|---|---|

## 9. 验收（5 条，别做分子料理）

1. 启动一次应用 → 注册表 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 下出现 `taskloop` 项，值形如 `"...\electron.exe" "C:\...\任务管理审核" --autostart`。
2. 直接照那条值在命令行里跑一遍 → **只出悬浮条，主窗不弹**（任务栏没有主窗）。
3. 点悬浮条 → 展开面板 → `设置` → 第 4 项 `打开主界面` → **主窗出现并获得焦点**。
4. 把主窗 `×` 关掉（悬浮条还在）→ 再点 `打开主界面` → 主窗**重新出现**（不是空操作）。
5. 保持应用在跑，再启动一次 → **没有第二个进程**（任务管理器里只有一个），已有主窗被拉出来。
