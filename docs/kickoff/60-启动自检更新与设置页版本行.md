## §0 范围与形态

用户裁决：**不接远程分发**，只做本机绿色版自更新；**下载/校验完立刻重启**；**设置页加一行手动入口**。

形态写死（不要另外设计）：

- 绿色版目录结构不变，`taskloop.exe` 同级新增 `updates/` 目录。
- `updates/latest.json`：`{"version":"0.60.0"}`，只有版本号一个字段。
- `updates/app/`：**新版本的 `out/` 内容 + `package.json`**，即替换源（xcopy 覆盖到 `resources/app/`）。
- 应用启动后延时 8 秒检查一次；发现 `latest.json` 的版本**大于**当前 `app.getVersion()`，就写脚本、退出、覆盖、拉起。
- 覆盖前把 `out/` 备份成 `out.bak`，`package.json` 备份成 `package.json.bak`；`xcopy` 返回非 0 时回滚并重启旧版。

**明确不做（越界即返工）：**

- 不引 electron-updater、不引 electron-builder、不加任何 npm 依赖。
- 不联网、不校验签名、不算 sha256（本机拷贝，不做传输层校验）。
- 不做增量更新、不做多版本回滚菜单、不做更新日志展示。
- 不在主窗/HUD 里加任何更新提示气泡。**唯一的 UI 是设置页那一行。**

## §1 版本号与打包脚本

### §1.1 版本号

`package.json` 的 `"version": "0.0.0"` → `"0.60.0"`。

> 之后每次要发新版，改这一个字段再跑打包脚本即可。主进程一律用 `app.getVersion()` 读，**不许把版本号硬编码进任何 ts 文件**。

### §1.2 新增 `scripts/pack.mjs`

职责：把当前构建产物装进 `dist/taskloop/updates/`。**必须在 `npm run build` 成功之后再跑。**

行为，逐条写死：

1. 读仓库根 `package.json` 的 `version`；读不到或为 `0.0.0` 时直接退出并打印一行错误（`console.error` 即可），**不产出任何文件**。
2. 目标目录 `dist/taskloop/updates/`：先整个删除，再重建。
3. 建 `dist/taskloop/updates/app/`。
4. 把仓库根的 `out/` 整目录拷到 `dist/taskloop/updates/app/out/`。
5. 把仓库根的 `package.json` 拷到 `dist/taskloop/updates/app/package.json`。
6. 写 `dist/taskloop/updates/latest.json`，内容 `{"version":"<version>"}`（两空格缩进，末尾换行）。
7. 结束打印 `updates ready: <version>`。

`package.json` 的 `scripts` 加一条：`"pack": "node scripts/pack.mjs"`。**不要**把 `pack` 串进 `build`（build 是自检用的，不该顺手改 dist）。

> 为什么带上 `package.json`：主进程的版本号来自 `resources/app/package.json`。只覆盖 `out/` 而版本号不变，下次启动还会判定「有新版本」，直接进入无限重启。

## §2 主进程更新服务

新增 `src/main/update/updateService.ts`。**这是纯逻辑 + 文件操作，不 import 任何窗口/IPC 模块。**

### §2.1 常量与纯函数

```ts
// 伪代码，表达语义，不是要求照抄
const UPDATE_DIR = join(dirname(process.execPath), 'updates')   // exe 同级
const STATE_FILE  = join(app.getPath('userData'), 'update-state.json')
```

导出 `compareVersion(a: string, b: string): number`：

- 按 `.` 分段，逐段转数字比较，返回 `-1 / 0 / 1`。
- 段数不同按缺省 0 处理（`0.60` 与 `0.60.0` 相等）。
- 任一段不是有限数字时，该段按 0 处理（不抛异常）。
- 纯函数，不读文件、不读环境。

导出 `readManifest(dir: string = UPDATE_DIR): { version: string } | null`：

- 读 `<dir>/latest.json`；文件不存在、不是合法 JSON、`version` 不是非空字符串 → 返回 `null`。
- **任何异常都吞掉返回 `null`**（更新检查永远不能让应用启动失败）。

### §2.2 `checkUpdate(): Promise<CheckResult>`

`CheckResult = { current: string; latest: string | null; hasUpdate: boolean; applying: boolean }`

- `current = app.getVersion()`。
- 读 manifest；`null` → `{ current, latest: null, hasUpdate: false, applying: false }`。
- `hasUpdate = compareVersion(manifest.version, current) > 0`。
- `applying`：仅当 `hasUpdate` 为真、且**这次要真的执行安装**时为 `true`。

### §2.3 防重启循环（**本单最容易写错的地方**）

`update-state.json` 的形状：`{ "attemptedVersion": string | null }`，读不到就当 `{ attemptedVersion: null }`。

规则，逐条：

1. 若 `hasUpdate === false` → 什么都不做，返回。
2. 若 `hasUpdate === true` 且 `manifest.version === state.attemptedVersion` → **不安装**，返回 `{ current, latest, hasUpdate: true, applying: false }`。
   这条的含义：同一个新版本已经尝试过一次但版本没变（覆盖失败），不再自动重试，避免无限重启。
3. 否则：把 `attemptedVersion = manifest.version` **先写盘**，再执行安装。

> 安装成功后 `current` 会变成新版本，`compareVersion` 自然返回 0，规则 1 生效，标记失去作用——不需要在成功时清标记。

### §2.4 `applyUpdate(): void`

在**确认 `hasUpdate` 且允许尝试**之后调用。顺序写死：

1. 计算 `resourcesApp = join(dirname(process.execPath), 'resources', 'app')`。
2. 在 `%TEMP%/taskloop-update/` 建工作目录（已存在则先删）。
3. 写 `apply.cmd` 到该目录（见 §2.5），内容中把三个绝对路径替换进去：`updates/app/`、`resources/app/`、`process.execPath`。
4. 调用 `app.quit()`。**不要**自己在这里做 xcopy——进程没退出前 `out` 里的文件仍被占用。

`applyUpdate` 只负责「写脚本并退出」，不负责「覆盖」。

### §2.5 `apply.cmd` 的内容规范

```
@echo off
:wait
tasklist /fi "imagename eq taskloop.exe" 2>nul | find /i "taskloop.exe" >nul && (
  timeout /t 1 /nobreak >nul
  goto wait
)
if exist "<RES>\out" if exist "<RES>\out.bak" rmdir /s /q "<RES>\out.bak"
if exist "<RES>\out" move "<RES>\out" "<RES>\out.bak"
if exist "<RES>\package.json" copy /y "<RES>\package.json" "<RES>\package.json.bak" >nul
xcopy /s /e /y /i "<SRC>\*" "<RES>\"
if errorlevel 1 (
  if exist "<RES>\out" rmdir /s /q "<RES>\out"
  if exist "<RES>\out.bak" move "<RES>\out.bak" "<RES>\out"
  if exist "<RES>\package.json.bak" copy /y "<RES>\package.json.bak" "<RES>\package.json" >nul
)
start "" "<EXE>"
```

要点：

- `tasklist` 里写死 `taskloop.exe`。**不要**用 `%EXE%` 反推文件名。
- 路径全用双引号包围，且都替换成绝对路径（`\` 分隔）。
- 成功路径**也保留** `out.bak`（下一轮覆盖成功时才会删），不要一成功就删——留下最后一次可回滚的副本。
- 脚本自身不删（临时目录，无害），也不要尝试自删技巧。

## §3 启动钩子

`src/main/index.ts` 的 `app.whenReady()` 里，**在建主窗之后**挂一次：

```ts
setTimeout(() => { void runStartupUpdateCheck() }, 8000)
```

`runStartupUpdateCheck` 放 `updateService.ts`，职责：`if (!app.isPackaged) return`（开发模式不跑）→ `checkUpdate()` → 若 `applying` 为真则 `applyUpdate()`。

- **不要在 `whenReady` 之前跑**（要等窗口就绪，用户至少能看到界面）。
- 定时器不需要 `unref`、不需要清理。
- 更新失败（manifest 读不到、脚本写失败）一律静默，只 `console.error`。**不许弹任何窗口、不许改任何界面状态。**

## §4 IPC 与 preload

- `src/shared/channels.ts`：`app` 段加 `checkUpdate: 'app:checkUpdate'`。
- `src/main/ipc/guards.ts`：加 `checkUpdate: z.object({})`（无参，但必须有 guard，跟同段其它无参通道一致）。
- `src/main/ipc/registry.ts`：`row(g.checkUpdate, ...)` → 调 `checkUpdate()`，拿到 `applying === true` 时**不在这里**调 `applyUpdate`（见 §5 的手动路径：手动点完要 2 秒后才重启，留给渲染层把按钮状态画出来）。
  所以 registry 里只返回结果，并在 `applying` 为真时用 `setTimeout(() => applyUpdate(), 2000)` 延迟执行。
- `src/preload/index.ts`：`app.checkUpdate: () => invoke<CheckResult>(CH.app.checkUpdate)`。

`CheckResult` 类型定义在 `src/shared/types/ipc.ts`，与 §2.2 一致，**主进程与渲染层共用这一个类型**。

## §5 设置页一行

### §5.1 `useSettingsData.ts`

新增：

- `update: { version: string; latest: string | null; hasUpdate: boolean; checking: boolean; note: string | null }`，初值 `{ version: '', latest: null, hasUpdate: false, checking: false, note: null }`。
- `refreshUpdate(): Promise<void>`：`checking = true` → 调 `window.api.app.checkUpdate()` → 成功则写回 `version / latest / hasUpdate`，`note` 按结果设：
  - `hasUpdate === true` → `'正在更新'`
  - `hasUpdate === false` → `'已是最新'`
  - 失败 → `res.error.message` 原文
  → `checking = false`。
- `note` 的清除复用现有 `flashNotice` 的思路：**2.6 秒**后置 `null`（用 `setTimeout`，组件卸载时清，与 Drawer 里现有 `settings-notice` 的时长一致）。
- 挂载时调一次 `refreshUpdate()`（拿版本号，顺便让 `version` 有值）。

### §5.2 `SettingsDrawer.tsx`

在设置抽屉**最底部**（现有 API Key 区块之后）加一行 `settings-kv`：

- 左：`<span className="settings-kv-key">版本</span>`
- 中：`<span className="settings-kv-value">v{data.update.version}</span>`
- 右：一个按钮，文字 `检查更新`；`disabled={data.update.checking}`；点击 `void data.refreshUpdate()`。
- 状态文字（`note`）显示在同一行尾部，**只在非 null 时进入 DOM**，复用 `settings-notice` 类，不加新样式。

**硬规定（违反即返工）：**

- 本行**只允许**出现这四个中文字面量：`版本` / `检查更新` / `已是最新` / `正在更新`。
- **不许**加 placeholder、不许加说明文字（不解释「更新放在哪」「为什么要重启」）、不许加图标、不许加 tooltip。
- **不许**在 `SettingsDrawer.tsx` 里出现 `window.api`（IPC 只能写在 `useSettingsData.ts`，`settingsWiring` 有一条 `not.toContain('window.api')`）。
- **不许**给这行加 `aria-label`（左侧已有可见文字标签）。

### §5.3 中文白名单

`tests/renderer/settingsWiring.test.ts` 的 `ALLOWED` 集合里补这四个词：`版本`、`检查更新`、`已是最新`、`正在更新`。

> 这条不是可选项：该文件用中文白名单钉死 Drawer 里的全部字面量，漏一个就红。`已保存` / `接口地址` / `保存` 等已在集合里，不要重复添加。

## §9 危险与回滚（写给你和用户看，不要写进代码注释以外的地方）

- 这套东西会**覆盖正在运行的绿色版代码并重启应用**。任何时刻 `out.bak` 都是上一次可用版本的副本；应用打不开时，把 `resources/app/out.bak` 改名为 `out` 即可恢复。
- `updates/app/` 里的内容必须是**当前源码构建出的 `out`**。手工往这个目录塞别的东西，等于给应用换内脏。
- 没有签名、没有校验：这是本机自用的取舍，不要因为它「不够安全」而自作主张加 sha256 或联网校验——那是下一单的事。
