## 背景（用户原话）

> 「对于任务卡的反驳，有时并不缺少证据，所以比如我这个说作业要交给老师，不能给它看我是怎么交的，这种申诉要有地方写。」

实际场景：用户上传了作业完成照片，AI 驳回「只见作业完成的照片，未见提交作业的记录或截图」。但作业是**当面交给老师**的，客观上不存在"提交记录截图"。用户没有任何地方能解释这件事，只能反复补图，被卡死。

**好消息：底层全部已通，只缺一个输入口。**

- `Evidence` 联合类型早就有 `{ kind:'text', text, addedAt }`（`domain.ts:28`）。
- 渲染层 `toEvidenceViews`（`chatViewModel.ts:266`）已经处理 `kind==='text'`，`EvidencePanel` 的 `EvidenceChip`（`EvidencePanel.tsx:66-73`）已经会把文字证据渲染成一个胶囊。
- 审核管线 `reviewEvidenceOf`（`aiService.ts:643`）已经把 text 证据序列化成 `{ kind:'text', text }`，`review.ts:81` 会写成 `1. 文字证据：…` 送进模型。
- `taskService.addEvidence`（`taskService.ts:257`）已经校验「文字证据不能为空」。

**唯一缺口**：没有任何 UI 能造出一条 text 证据；而且 `review.system.md:7` 写死「用户说"我交了"不构成证据」，模型拿到文字证据也会照旧无视。

### B. `src/renderer/main/features/chat/useChatData.ts`

B1. 在 `addEvidence` 之后新增 `addTextEvidence`（`useCallback`，依赖 `[]`）：

1. `const body = text.trim()`；`body.length === 0` → `return null`。
2. `body.length > 200` → 截断到 200（`Array.from(body).slice(0, 200).join('')`，按码点截，不要按 `length`，避免切坏 emoji）。
3. 调 `window.api.task.addEvidence({ id: taskId, evidence: { kind: 'text', text: body, addedAt: new Date().toISOString() } })`。
4. `!added.ok` → `return added.error.message`。
5. 成功后与 `addEvidence` 一样就地更新 `setTaskById` 与 `setPendingList`（**不要**拉整表，**不要**调 `reloadPending`）。
6. `catch` 返回 `e instanceof Error ? e.message : String(e)`。

B2. 返回的 `actions` 对象里加上 `addTextEvidence`，依赖数组补上它。

F2. 在「# 非活动类任务」之后、「# 不要做的事」之前，新增一节：

```
# 6. 文字说明怎么用

`文字证据：…` 是用户自己写的一段话。它不是截图、不是文件，用法有三条：

1. **纯文字、没有任何附件证据** → 最高只能 `partial`，`gaps` 写明缺什么。
   话说得再诚恳也不给 `pass`——一段话不能证明产出存在。
2. **用来解释某一类证据为什么不存在**：交给老师、纸质提交、线下当面完成、别人代交，
   这类情况下"提交记录截图"客观上拿不到。如果文字说明与任务描述相符，
   并且**已有的附件证据能证明产出本身**（作业照片、报告文件），就按产出判 `pass`，
   不要再因为缺提交记录反复 `need_evidence`。
3. **文字说明与附件证据互相矛盾**（说明说交了、截图显示没做）→ `need_evidence`，
   `followup` 指出矛盾在哪。

活动类任务的**结果**不适用第 2 条：分数、名次、证书必须有能看见的东西，
文字说明不能替代结果证据。
```

F3. 文件头 `<!-- v1 2026-10-29 -->` 改成 `<!-- v2 2026-11-05：加第 6 节文字说明 -->`。

**除这三处，本文件其它字一个都不许改**（尤其第 2 条「这次没有任何证据 → 只能 need_evidence」和第 5 条「判不准用 need_evidence」，它们是 62 单定的硬闸门口径）。
