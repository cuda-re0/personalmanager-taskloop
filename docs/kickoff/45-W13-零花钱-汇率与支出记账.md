## 0. 一句话目标

积分不只是分数，是**零花钱额度**。这一单给它三样东西：**能换成钱的汇率**（每周由 AI 按上周完成情况小幅浮动）、**一个记账的地方**（填金额，自动扣积分）、**能纠正记错的账**（撤销）。

## 1. 用户已裁决的八条（照做，不要换）

| # | 裁决 | 内容 |
|---|---|---|
| 1 | 基准汇率 | **500 积分 = 500 元**，即 1 积分 = 1 元，作为 100% 基准 |
| 2 | 记账单位 | **填金额（元）**，系统按当期汇率自动换算成积分扣掉 |
| 3 | 超支 | **允许扣成负数**，余额为负时 ③ 的大数字变红，不拦截 |

| 6 | 浮动方向 | **做得好就升值**（1 分换更多钱），懈怠则贬值 |

## 2. 术语与精度（这一节是账本的地基）

- **`rate` 定义：1 积分值多少元。** 基准 1.0，合法区间 `[0.85, 1.15]`，两位小数。
- **扣分公式**：`delta = -roundPoints(amountCents / 100 / rate)`
  - 例：`rate=1.08`，花 100.00 元 → `100/1.08 = 92.5925…` → **-92.59 分**
  - 例：`rate=0.85`，花 100.00 元 → **-117.65 分**
  - 例：`rate=1`，花 12.50 元 → **-12.5 分**
- **金额一律用整数「分」**（`amount_cents`）。**禁止** `parseFloat(x) * 100`——会出现 `12.5 * 100 = 1250.0000000000002`。解析规则见 §7.1。
- **取整只准用 `roundPoints`**（`shared/points/rubric.ts`）。全项目 `Math.round` / `toFixed` 只准出现在它内部，这一单不许破例。
- **汇率快照**：每笔支出把当时的 `rate` 写进流水行。**改汇率永不重算历史**——历史是事实。
- 若算出 `delta === 0`（金额小到扣不进 1 分），**拒绝**并返回「金额太小，扣不进积分」，不许写一条 0 分流水。

## 5. 服务层

### 5.1 `pointsService`（改）

- `spend({ amountCents, note })`：
  1. 校验 `amountCents` 是正整数且 `<= MAX_SPEND_CENTS`，否则 `INVALID_INPUT`（文案见 §8）；
  2. 取当期汇率 `fxService.currentRate().rate`；
  3. `delta = -roundPoints(amountCents / 100 / rate)`，为 0 则拒绝；
  4. 一个事务里：写流水（`taskId: null`、`occurrenceId: null`、`kind: 'spend'`、`reasonCode: 'pocket_spend'`、`reasonText: note ?? ''`、`day: todayLocalDay()`、两个新列填值）+ `statsRepo.addPoints(day, delta)`；
  5. 返回 `PointEntry`。

  **不许**复用 `adjust()`：它的 `kind`/`reasonCode` 是写死的，硬塞进去会让「手动调整」和「花钱」在明细里混成一类。
- `spendMonth()`：返回 `{ entries, totalCents, rate, weekStart }`。月份取**当前月**（本地日），不传参——界面只看本月。`entries` 只含未撤销的支出行。
- `spendUndo(entryId)`：
  1. 取该行，不是 `kind='spend'` 或已 `reversedAt !== null` → `NOT_FOUND` / `CONFLICT`（文案见 §8）；
  2. 复用现成的 `rollback(entry, '撤销支出')`（打 `reversed_at` + 写反向 `adjust` 行）；
  3. 返回反向行。

  `rollback` 一个字都不许改：它同时服务任务撤销，改坏了 `uq_ledger_task_done` 的谓词会一起崩。

### 5.2 `fxService`（新）+ `fxSweeper`（新）

**`currentRate()`**：本周（周一起算，本地日）有记录就用它；没有就用最近一条；一条都没有则 `{ rate: 1, weekStart: 本周一 }`。**永远不抛错**——记账不该因为汇率缺失而失败。

**`ensureWeek(now)`**（幂等，供 sweeper 调）：本周已有记录 → 直接返回，什么都不做。否则：
1. AI 未配置 → 写 `source='fallback'`、rate = 上期（无上期则 1.0）；
2. 上周**没有任何可看的数据**（`tasks_done`、`occurrences_done`、`missed` 三者合计为 0）→ 同样走 fallback，**不调 AI**（不为一片空白烧一次 token）；
3. 否则调 AI 评估（见 §5.3），失败也写 fallback 行；
4. 写库后广播 `fx.changed`。

**每期只尝试一次**：失败也写一行 fallback，这样本周不会再重试，避免 sweeper 每 30 分钟烧一次钱。

**`fxSweeper`**：抄 `reviewSweeper.ts` 的形状——启动立即跑一次、之后每 30 分钟一次，返回 `stop()` 由 `main/index.ts` 的 `before-quit` 调用；单轮异常只 `console.warn`，不许掀掉主进程。

### 5.3 AI 评估（`ai/pipelines/fx.ts` 新 + `ai/prompts/fx.system.md` 新）

- **输入**：上周一到周日的 `daily_stats`（day / points / tasks_done / occurrences_done）+ 上周 `status='missed'` 的限时/活动任务数。拼成一段紧凑 JSON 放进 user 消息。
- **模型**：`chatClient`（`ai.chat.model`，便宜纯文本），`temperature: 0`，走 `chatJson`。
- **schema**：`z.object({ rate: z.number(), reason: z.string().max(200) })`。
- **钳制（两步，顺序不能换）**：
  1. 非法值（NaN / Infinity / 负数）→ 当作评估失败；
  2. `clamp(rate, RATE_MIN, RATE_MAX)`，再 `roundPoints` 到两位小数。

  **没有「相对上期最多变动 X」这一层**：区间已经收在 0.85~1.15，AI 可以在两期之间从 0.85 直接给到 1.15，不要自己再叠一个平滑。
- **`reason` 只进 `basis` 列**，不上界面、不进日志的可见字段（可作为 `console.info` 的调试信息）。
- 提示词要求：说明 1 积分 = 1 元的基准、允许 0.85~1.15、完成得好应升值；**要求只输出 JSON**，不给用户写任何话。
