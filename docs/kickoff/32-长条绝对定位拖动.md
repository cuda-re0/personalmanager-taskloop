## 0. 用户反馈（原话）

> 「我测试发现当我长按时，会自动偏移，而不是随着我的光标移动而移动，这样，当移动时不需要改变状态，
> 改变状态只有点击和位置判断，就是你移动出来后，判断在什么位置，再考虑是否展开
> （我觉得超过屏幕的1/8就展开应该可以）。而且放上去鼠标样式不要变，那个小手不好看。」

| # | 反馈 | 本单要求 |
|---|---|---|
| 1 | 长按后窗口自动偏移，不跟光标 | 拖动模型从"读窗口位置 + 加增量"换成**绝对定位**（§1） |
| 2 | 移动时不要改状态；松手按位置判，阈值 = 屏宽 1/8 | 长条展开阈值 `48px` → `workArea.width / 8`（§2）；拖动中一律不判形态 |
| 3 | 鼠标放上去样式不要变，小手不好看 | 删掉长条侧全部 `cursor` 声明（§3） |

## 1. 拖动：改成绝对定位

### 1.1 根因（这决定改法，先读懂再动手）

上一版 `dragBy(dx, dy)` 让主进程 `getBounds()` 读窗口当前位置、加增量、再 `setBounds`。
`setBounds` 是异步的，读回来的常常还是上一帧的位置 → 增量一帧帧漏掉或错位 → 窗口不跟光标、越拖越偏。
只要还是"增量累加"，换了参数也会再偏。**必须换模型。**

### 1.2 目标模型

拖动位置只由两个量决定，每帧重算，不累积：

```
抓取偏移 grab = 按下点的屏幕坐标 − 长条按下时的左上角
每帧目标位置  = 当前指针屏幕坐标 − grab
```

丢帧也不会累积误差，因为下一帧重新对齐光标。

### 1.3 通道（删一条、加两条，总数 42 → 43）

| 通道 | 入参 | 返回 | 语义 |
|---|---|---|---|
| ~~`hud.dragBy`~~ | — | — | **删除** |
| `hud.dragBegin` | 无 | `{ x, y }` | 返回长条当前左上角（屏幕绝对坐标 DIP）。渲染层据此算 grab |
| `hud.dragTo` | `{ x, y, end }` | `void` | 把长条左上角移到绝对坐标 x/y；`end:false` 只移窗，`end:true` 落库 + 判一次形态 |

- `x/y` 坐标系与 `getBounds()` 一致（DIP 绝对屏幕坐标），不是增量。
- `dragTo` 仅 `ball` 态有效，`panel` 态直接返回（面板走原生头部拖动）。
- `x/y` 非有限数直接返回，不做任何位移。
- 位移结果必须走**现有的** `applyBounds()`（回声抑制在里面），不许自己 `setContentBounds`。
- 位置一律经 `clampBallPoint` 收口：长条整条不出工作区（v0.31 既定口径，不改）。

### 1.4 判形态的时机

- `end:false`：只移窗。**不落库、不判形态**（用户第 2 条：移动时不改状态）。
- `end:true`：先落 `hud.position` / `hud.displayId`，再按 §2 判一次形态；命中展开走现有的 `enterMode('panel', …)`，不自己拼 bounds。
- `dragBegin` 不校验 mode——它只读一次坐标，面板态不会调到它。

## 2. 展开阈值：工作区宽度的 1/8

- 新增比例常量 `1/8` 与换算 `expandGap(workArea) = round(workArea.width / 8)`；1920 屏 = 240。
- `resolveDragStep` 的长条分支改为：`edgeGap(workArea, rect) > expandGap(workArea)` 才 `expand`。
- **删掉固定常量 `EDGE_EXPAND = 48`**（全仓 0 引用，测试里引用它的地方按新函数改）。
- 边界取"超过才展开"：正好等于 `expandGap` 时**不展开**。
- 面板态收起仍是 `PANEL_COLLAPSE_RATIO = 1/3`（出屏超过自身宽度 1/3），不动。
- 判定时机不变：长条由 `end:true` 直接判，**无 120ms 去抖**；面板仍走去抖 + `settle` 补判。

## 3. 鼠标样式：全程系统默认

- 删长条侧全部 `cursor` 声明：`.hud-hit` 的 `pointer`、`.hud-ball` 的 `grab`、`.is-dragging` 的 `grabbing`（该规则只做这一件事，整条删）。
- `HudBall.tsx` 里只用于切换 `.is-dragging` 的 `useState` 一并删掉，拖动标志改用 ref 记逻辑。
- 面板侧不动。

## 4. 渲染层手势（HudBall.tsx）

状态放 ref，除必要渲染外不要新增 state。需要记的东西：

```
startX/startY    按下时的屏幕坐标（点按判定 + 算 grab 都用它）
lastX/lastY      最近一次屏幕坐标
dragging         已过长按阈值
cancelled        手抖作废
grab             抓取偏移；null = dragBegin 还没回来
target           最近一次的绝对目标点；null = 还没移动过
```

判定表（顺序不可调换）：

| 阶段 | 条件 | 动作 |
|---|---|---|
| pointerdown | `e.button !== 0` | 直接 return |
| pointerdown | 主键 | `setPointerCapture`；初始化状态；起 260ms 定时器 |
| 定时器到点 | — | `dragging = true`；调 `dragBegin`；成功则 `grab = 按下点 − 返回值`；失败只记日志、不拖 |
| pointermove | 未 dragging | 位移 > 4px → `cancelled = true` 并清定时器；始终更新 last |
| pointermove | dragging 但 `grab === null` | 只更新 last，**不发**（grab 未就绪发会把窗口甩一下） |
| pointermove | dragging 且有 grab | `target = 指针 − grab`；请求下一帧发送（每帧最多一次 IPC） |
| pointerup | — | 统一收尾，允许点按 |
| pointercancel / lostpointercapture | — | 统一收尾，不允许点按 |

收尾函数（三处共用，顺序重要）：

```
先取出 gesture 并立刻置 null（防止丢捕获二次发送 end）
清定时器
若 dragging 且有 target → 发 dragTo(target, end: true)
否则若允许点按 && !cancelled && 位移 ≤ 4px → setMode('panel')
```

- 位移一律用 `screenX/screenY`（`clientX` 随窗口移动会漂）。
- `target` 为 null 且要 end 时不发（没移动过就不需要落库/判形态）。
- 不发形态判定给渲染层做——形态只由主进程判。

## 6. 测试（锁行为，不逐像素）

`hudService.test.ts`（工作区基准 1920×1040，1/8 = 240）：

1. `dragBegin` 返回值 = 长条当前左上角（贴右时 `{1788, 104}`）。
2. `dragTo(-20, 130, false)` → 窗口移到 `{1768, 130}`，且 `hud.position` 未被写。
3. `dragTo` 给到屏外极值 → 被夹成 `{0, 0}`（整条不出屏）。
4. `dragTo(1788, 104, true)` → 位置落库，形态仍 `ball`。
5. 离右边 241（>240）松手 → 形态变 `panel`，且走 `enterMode`（不是自己 setBounds）。
6. 离右边正好 240 松手 → **不展开**（边界取"超过才展开"）。
7. `panel` 态调 `dragTo` → bounds 与 position 都不变。
8. `expandGap`：1920 宽 → 240；1280 宽 → 160。

`hudWiring.test.ts`（源码结构断言）：

- `HudBall.tsx` 含 `dragBegin` / `dragTo`，不含 `dragBy`；
- 不含 `onClick=`，不含 `cursor` 字样；
- `hud.css` 里没有 `cursor: pointer` / `grab` / `grabbing`；`.hud-ball` 块内无 `-webkit-app-region`；
- 全仓 `EDGE_EXPAND\b` 0 命中。

## 7. 验收（三条主路径）

1. **跟手**：长按长条半秒再慢慢拖——窗口贴着光标走，停手就停住；快速拖一大段，松手后窗口就在光标处，不偏、不回弹。
2. **阈值**：从右边缘往左拖约 1/10 屏宽（1920 屏约 190px）松手 → 仍是长条；
   拖到超过 1/8（1920 屏超过 240px）松手 → 变面板。拖动**过程中**形态不变。
3. **鼠标样式**：鼠标移到长条上样式不变（不是小手、不是抓手），拖动中也不变。
