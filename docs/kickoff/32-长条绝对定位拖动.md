# 32 · 长条拖动改成绝对定位 + 展开阈值 1/8 + 去掉鼠标样式（v0.32 修正）

基线 `2563bf4`（kickoff/31 已交付）。单独跑，别与任何会话并行。

## 0. 用户的三条反馈（原话）

> 「我测试发现当我长按时，会自动偏移，而不是随着我的光标移动而移动，这样，当移动时不需要改变状态，
> 改变状态只有点击和位置判断，就是你移动出来后，判断在什么位置，再考虑是否展开
> （我觉得超过屏幕的1/8就展开应该可以）。而且放上去鼠标样式不要变，那个小手不好看。」

拆成三条：

| # | 反馈 | 本单怎么改 |
|---|---|---|
| 1 | 长按后窗口自动偏移，不跟光标 | 拖动模型从「读窗口位置 + 加增量」改成**绝对定位**（§1） |
| 2 | 移动时不要改状态；松手按位置判，阈值 = 屏宽 1/8 | 长条展开阈值 `48px` → `workArea.width / 8`（§2） |
| 3 | 鼠标放上去样式不要变，小手不好看 | 删掉全部 `cursor` 声明（§3） |

## 1. 拖动改绝对定位（替换 `dragBy`）

### 1.1 为什么必须换模型（写进注释，别再改回增量）

上一版是 `dragBy(dx,dy)`：主进程 `getBounds()` 读当前窗口位置，加 delta，再 `setBounds`。
`setBounds` 是异步的，读回来的常常还是**上一帧的位置**，于是增量一帧帧漏掉或错位 →
窗口不跟光标、越拖越偏。绝对定位每帧用「光标屏幕坐标 − 抓取偏移」重算目标位置，丢帧也不会累积误差。

### 1.2 通道改两个

`src/shared/channels.ts` hud 段：**删 `dragBy`**，加两条：

```ts
dragBegin: 'hud:dragBegin',
dragTo: 'hud:dragTo'
```

通道 42 → **43**。`tests/ipc/handlers.test.ts` 与 `tests/ipc/registry.test.ts` 里的 WIRED 条数同步 42 → 43。

### 1.3 主进程（`hudService.ts`）

删 `dragBy`，换成：

```ts
/** 长条开始拖动：返回当前左上角（DIP），渲染层据此算抓取偏移 */
export function dragBegin(): { x: number; y: number } {
  const rect = requirePort().getBounds()
  return { x: rect.x, y: rect.y }
}

/** 把长条左上角移到绝对坐标；end 时才落库并判一次形态 */
export function dragTo(x: number, y: number, end: boolean): void {
  const current = requireState()
  if (current.mode !== 'ball') return                 // 面板走原生拖动
  if (!Number.isFinite(x) || !Number.isFinite(y)) return

  const area = requireDisplays().nearestWorkArea({ x, y, width: BALL_W, height: BALL_H })
  anchor = clampBallPoint(area.workArea, { x: Math.round(x), y: Math.round(y) })
  current.displayId = area.displayId

  if (!end) {
    applyBounds()   // 内部设 expectedRect 做回声抑制；不落库、不判形态
    return
  }

  persistPosition(anchor)
  persistDisplayId(area.displayId)

  const step = resolveDragStep('ball', area.workArea, {
    x: anchor.x, y: anchor.y, width: BALL_W, height: BALL_H
  })
  if (step === 'expand') {
    const panel = peekPanelBounds(area.workArea, anchor, panelSize)
    enterMode('panel', area, { x: panel.x, y: panel.y })
    return
  }
  applyBounds()
}
```

- 坐标语义：`x/y` = 长条**左上角**在屏幕上的绝对位置（DIP），与 `getBounds()` 同一坐标系。
- 仍复用 `applyBounds()`（回声抑制在里面），**不许**自己 `setContentBounds`。
- `dragBegin` 不查 `state.mode`——它只读一次坐标，面板态根本不会调它。

### 1.4 guards / registry / preload

- `guards.ts`：删 `hudDragBy`；加 `hudDragTo`（`x/y` 有限 number、`end` boolean）与 `hudDragBegin`（无入参，直接复用现有的无参 schema 写法，不要新造）。
- `registry.ts`：删 `hud.dragBy` 那行，注册 `hud.dragBegin` / `hud.dragTo`；hud 段条数注释同步。
- `preload/index.ts`：暴露 `dragBegin` / `dragTo`，删 `dragBy`。
- `types/ipc.ts`：`HudApi` 里 `dragBy` 换成
  `dragBegin(): Promise<IpcResult<{ x: number; y: number }>>` 与
  `dragTo(input: { x: number; y: number; end: boolean }): Promise<IpcResult<void>>`。

## 2. 展开阈值改成工作区宽度的 1/8

`hudService.ts`：

```ts
/** 长条松手后离左右边超过「工作区宽度 × 1/8」才展开（v0.32 用户裁决，替代固定 48px） */
export const EDGE_EXPAND_RATIO = 1 / 8
export const expandGap = (workArea: Rect): number => Math.round(workArea.width * EDGE_EXPAND_RATIO)
```

`resolveDragStep` 的 ball 分支改成：

```ts
if (mode === 'ball') return edgeGap(workArea, rect) > expandGap(workArea) ? 'expand' : 'none'
```

- 删掉常量 `EDGE_EXPAND = 48`（全仓 0 引用；测试里引用它的地方按新函数改）。
- 面板态收起仍是 `PANEL_COLLAPSE_RATIO = 1/3`，**不动**。
- 判定时机不变：长条由 `end:true` 直接判（无 120ms 去抖）；面板仍走去抖 + settle。
  **拖动过程中一律不判形态**（用户第 2 条），这条现在就成立，别改坏。

## 3. 鼠标样式：全程系统默认

`hud.css` 删三处：

- `.hud-hit` 里的 `cursor: pointer`；
- `.hud-ball` 里的 `cursor: grab`；
- `.hud-hit.is-dragging`（或 `.is-dragging`）整个规则删掉 —— 它只做 `cursor: grabbing`。

`HudBall.tsx` 里 `dragging` 的 `useState` 与 `className={dragging ? 'hud-hit is-dragging' : 'hud-hit'}`
一并删掉（没有视觉状态了，只用 ref 记逻辑标志）。

## 4. 渲染层手势（`HudBall.tsx`）

状态（全部用 ref，除 `gesture` 外不要 state）：

```ts
interface Gesture {
  startX: number; startY: number      // pointerdown 时的屏幕坐标（点按判定 + 抓取偏移都用它）
  lastX: number; lastY: number
  dragging: boolean                    // 已过长按阈值
  cancelled: boolean                   // 手抖作废
  grab: { x: number; y: number } | null // 抓取偏移；null = dragBegin 还没回来
  target: { x: number; y: number } | null // 最近一次的绝对目标
}
```

流程：

1. `onPointerDown`（只接 `e.button === 0`）：`setPointerCapture`；初始化 gesture；起 `LONG_PRESS_MS` 定时器。
2. 定时器到点：`g.dragging = true`，并 `void window.api.hud.dragBegin()`；
   成功（`res.ok`）后若 gesture 仍在且 `dragging` 仍为 true，则
   `g.grab = { x: g.startX - res.data.x, y: g.startY - res.data.y }`（拿 `Ok<T>` 的载荷，与现有
   `hud.getState` 调用点同一写法）。失败只打日志、不拖。
3. `onPointerMove`：
   - 未 dragging：位移 `> TAP_TOLERANCE` → `cancelled = true` + 清定时器；始终更新 `lastX/lastY`；return。
   - 已 dragging 但 `grab === null`：只更新 `lastX/lastY`，**不发**（grab 未就绪时发会把窗口甩一下）。
   - 已 dragging 且有 grab：`g.target = { x: e.screenX - grab.x, y: e.screenY - grab.y }`，`schedule()`。
4. `flush(end)`：拿 `target` 发一次 `hud.dragTo({ x, y, end })`；`target` 为 null 且 `end` 时**不发**
   （没移动过就不需要落库/判形态）。
5. `onPointerUp`：更新 last、`finish(true)`。
6. `onPointerCancel` / `onLostPointerCapture`：`finish(false)`。
7. `finish(allowTap)`：取 gesture → **先置 `gesture.current = null`** → 清定时器 → 若 `dragging` 且有 target
   发 `flush(true)`；否则若 `allowTap && !cancelled` 且位移 ≤ 4px → `setMode('panel')`。

- 每帧最多一次 IPC（`requestAnimationFrame` 合并），这条保留。
- 位移只用 `screenX/screenY`。

## 6. 测试

`hudService.test.ts`（工作区 1920×1040 基准，1/8 = 240）：

1. `dragBegin()` 返回长条当前左上角（贴右时 `{1788, 104}`）。
2. `dragTo(-20, 130, false)` → 窗口 `x 1788 - 20 = 1768`、`y 130`；`hud.position` **没被写**。
3. `dragTo(-5000, -5000, false)` → 被 `clampBallPoint` 夹在 `{0, 0}`（整条不出屏）。
4. `dragTo(1788, 104, true)` 贴右松手 → 位置落库，形态仍 `ball`（gap 0 < 240）。
5. `dragTo(1788 - 241, 104, true)` → 离右边 241 > 240 → 形态变 `panel`（走 `enterMode`）。
6. `dragTo(1788 - 240, 104, true)` → 正好 240 **不展开**（边界取"超过才展开"）。
7. `panel` 态调 `dragTo` → 直接返回，bounds 与 position 都不变。
8. `expandGap({width:1920,...}) === 240`；`expandGap({width:1280,...}) === 160`。

`hudWiring.test.ts`：

- `HudBall.tsx` 含 `dragBegin` / `dragTo`，**不含** `dragBy`；
- `HudBall.tsx` 不含 `onClick=`，不含 `cursor` 字样；
- `hud.css` 里没有 `cursor: pointer` / `cursor: grab` / `grabbing`，`.hud-ball` 块内没有 `-webkit-app-region`；
- 源码里有 `EDGE_EXPAND_RATIO`，`grep "EDGE_EXPAND\b"` 0 命中（旧的 48 常量已删）。

## 7. 验收（三条主路径）

1. **跟手**：长按长条半秒，慢慢拖——窗口贴着光标走，停止时也停住；快速拖一大段，松手后窗口位置就在光标处，不偏。
2. **阈值**：把长条从右边缘往左拖约 1/10 屏宽（1920 屏约 190px）松手 → 仍是长条；
   再拖到 1/8 以上（约 250px）松手 → 变成面板。
3. **鼠标样式**：鼠标移到长条上没有变化（不是小手、不是抓手），拖动中也不变。
