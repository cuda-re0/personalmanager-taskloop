## 交付

1. **月视图**（04 §4②）：7 列网格、周一起始、红点行（有任务的日子）、**完成变空心圈**、今日描边、上/下月切换。
2. **数据只从两条通道来**：切月时对目标月**只发一次** `calendar.dayIndex`；不许按天循环调用，不许缓存预热，不许调 `ensureRange`（那是每日任务的事）。
3. **按日展开浮层**：点日期 → `calendar.dayDetail` → 浮层列表（时间 + 标题 + 分值）；点击外部关闭；列表空时给空态。
4. **点行跳任务**：浮层行点击后派发 `window.dispatchEvent(new CustomEvent('taskloop:focus-task', { detail: { id } }))` 并关闭浮层——接收方是右栏任务面板（W6 接线）。**未接通不算失败**，但事件名与 detail 形状必须是这个（集成交接点，写进报告）。
5. **本地日**：所有日期计算走项目既有的本地日工具（`date` 字段是 `YYYY-MM-DD` 本地日），**不许 `toISOString().slice(0,10)`**——那是 UTC，跨时区会错一天。
6. **文案**：月份/星期头/空态/浮层标题若 04 §1 没有登记行，报架构方补登记；不许自己发明。

## 红线（审核逐条查）

1. **不在渲染层算红点**：`total > 0` 就是红点，`doneCount === total` 变空心——口径只来自主进程。
2. **切月一次调用**：同一个月重复点击或 React 重渲染不许重复发请求（用月份 key 做依赖）。
3. **不碰主进程**：本线没有任何 `src/main/**` 改动。
4. **不调 `ensureRange` / `occurrence.*`**：日历只读既有数据，补行是每日任务链路的职责。
5. **文案登记**：每个可见串有 04 §1 出处。
6. **不引 UI 框架/日期库**：用现有 React + 项目工具。
