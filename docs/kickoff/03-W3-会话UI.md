## 交付

### 1. 消息流

- 虚拟滚动：消息 > 200 条时性能不塌（用 `@tanstack/react-virtual` 或自己写，二选一）
- 新消息自动滚到底；**用户手动上滚后暂停自动滚**，滚回底部再恢复（不做这个，用户翻历史时会被强行拽下去）
- 向上翻页加载更多

### 2. 五种消息组件（`04-UI-SPEC.md` §3.1）

| kind | 要点 |
|---|---|
| `text` | 普通气泡，user / assistant 左右区分 |
| `task_draft` | 草稿卡片，见下 |
| `task_review` | 审核结果卡，左侧色条表示 verdict（pass 主色 / partial 琥珀 / fail 灰） |
| `reminder` | 提醒条，醒目但不刺眼 |
| `error` | 错误气泡，带 `[重试]`，**不许白屏或弹 alert** |

### 3. 草稿卡片（本阶段最重要）

按 `04-UI-SPEC.md` §3.2 的 ASCII 图做，包含：

- 标题、难度、时长、截止**四项就地可改**
- 右上角分值徽标：改难度或时长后**立刻刷新**（调 `window.api.points.preview`；W2 那边可能还没实现，先本地 import `@shared/points/rubric` 算，但要加 `// TODO(W2)` 注释说明）
- `missing_info` 非空时，底部用「待补」标签逐个列出，**不加任何引导语**（04 §7 纪律）
- `confidence < 0.5` 时左边框变虚线（视觉弱提示，不写字）
- `[确认]` `[丢弃]` 两个按钮
- 确认后卡片变灰、按钮消失、显示已关联，不可再改

### 4. 输入区

- 多行自适应（1-6 行，超过滚动）
- Enter 发送，Shift+Enter 换行
- 粘贴图片 → 生成缩略图条，可删除
- 拖入文件 → 同上
- 发送中状态（禁用发送 + loading，**不许用 toast 说"发送中"**）

### 5. markdown 渲染

段落、列表、粗体、行内代码、代码块即可。

**安全要求**：不许 `dangerouslySetInnerHTML` 直出。用 `react-markdown` 或自己写解析。要挡住 `<script>` 和 `![x](javascript:...)`。

### 6. 空会话状态

用 `04-UI-SPEC.md` §7 那句话。**如果不是 04 里写的句子，先问我，不要自己编。**

## 数据从哪来

W2 正在同时写 IPC，你开工时 `window.api` 可能还不完整。

正确做法：

1. 所有组件**只接收 props**，不在组件内部直接调 `window.api`
2. 写一份 `__fixtures__/messages.ts`，用 `@shared/types/domain` 的 `Message` 类型构造 5 种消息各一条（**类型必须 import，不许自己定义一份长得像的**）
3. 用 fixture 完成全部验收
4. 等 W2 落地后，只改外层容器的数据源，组件不动

这样你和 W2 完全解耦。如果 W2 的 `window.api` 已经能用了，直接用，但组件仍然只收 props。
