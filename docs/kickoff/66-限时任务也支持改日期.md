## §0 为什么改

**用户要求（2026-11-04）：**

> 限时任务也加上这个改日期功能

v0.65 只给活动任务（`event`）开了行上点日期改的入口。限时任务（`deadline`）同样有截止日期，用户要求一并支持。

**关键差异（已核实数据库，不要重新调研）：**

限时任务的 `due_at` **有两种精度**，同一张表里并存：

| 任务 | `due_at` | 精度 |
|---|---|---|
| 完成数值计算方法第5、6章作业 | `2026-11-03` | **day**（只有日期） |
| 完成大物第15章作业 | `2026-11-03T05:00:00.000Z` | **minute**（日期+时间） |

**用户裁决（2026-11-04）：**

> 保持原样，不强加时间。

即：`day` 精度的任务只给**日期选择器**（改完还是 `2026-11-05`，绝不能变成 `2026-11-05 23:59`）；`minute` 精度给日期+时间；两种都不得改变原有的精度形态。

**明确不做（越界即返工）：**

- **不改** `due_at` 的存储格式，**不做**数据库迁移。
- **不给** `month` 精度开编辑（本项目当前没有月精度任务；`dueEditKindOf` 对它返回 `null` 即不可编辑）。
- **不给** `daily` 任务开编辑（它没有 `dueAt`，走的是 `dailyTime`）。
- **不加**任何可见文字、标签、图标、tooltip。
- **不改** `done` / `missed` / `pending_review` 行的行为（不可编辑）。
- **不改** `fmtDueLabel` / `toDatetimeLocal` / `dueInstant` / `duePrecisionOf` 的既有实现。
- **不动** CSS（`.task-due-btn` / `.task-due-inline` / `.task-due-edit-input` 原样复用）。
- **不碰** `useTasksData.ts`、`main/**`、`hud/**`。

## §1 模型层（`src/renderer/main/features/tasks/tasksModel.ts`）

### §1.1 import

- `@shared/due` 的 import 增加 `duePrecisionOf`（现在只有 `dueInstant`）。
- `@shared/format` 的 import 增加 `toDatetimeLocal`（现在只有 `fmtDueLabel, fmtRemaining`）。

### §1.2 新增 `DueEditKind` 与三个纯函数

```ts
/** 日期编辑用哪种控件（v0.66）：minute = datetime-local，day = date；其余精度不放开 */
export type DueEditKind = 'minute' | 'day'

/** null = 不给编辑（无日期 / 月精度 / 解析不出来） */
export function dueEditKindOf(dueAt: string | null): DueEditKind | null

/** 输入框的 value：minute 走 toDatetimeLocal；day 取原串前 10 位（**不许**补 23:59） */
export function dueEditValueOf(dueAt: string | null): string

/** 输入框值 → 写库的 dueAt：minute → new Date(v).toISOString()；day → v 原样 */
export function duePatchOf(kind: DueEditKind, value: string): string
```

规则写死：

- `dueEditKindOf`：`duePrecisionOf(dueAt)` 为 `'minute'` → `'minute'`；为 `'day'` → `'day'`；其它（`'month'` / `null`）→ `null`。
- `dueEditValueOf`：`kind` 为 `'minute'` → `toDatetimeLocal(dueAt)`；`'day'` → `dueAt` 的前 10 个字符；`kind` 为 `null` → `''`。
- `duePatchOf`：`'minute'` → `new Date(value).toISOString()`；`'day'` → `value`（就是 `YYYY-MM-DD`，直接写回，**不要**转 Date、不要补时分秒）。

**为什么 day 精度必须原样写回**：`due_at` 的 day 精度串本身是本地日历日，转一道 `Date` 再 `toISOString()` 会在东八区串成前一天（`2026-11-05` 变 `2026-11-04T16:00:00.000Z`），显示就从 `11-05` 变成 `11-04 24:00`。这是本单最容易写错的一处。

### §1.3 `canEditDueOf` 扩展

```ts
export function canEditDueOf(task: Task): boolean {
  // 类型：活动与限时；状态：todo / doing；且必须有可编辑精度的日期
  ...
}
```

三个条件同时满足才 `true`：

1. `task.type === 'event' || task.type === 'deadline'`
2. `task.status === 'todo' || task.status === 'doing'`
3. `dueEditKindOf(task.dueAt) !== null`

第 3 条是新增的：没有日期（`dueAt` 为 `null`）或月精度的任务不显示可点入口。

## §2 行内编辑（`src/renderer/main/features/tasks/TasksPanel.tsx` 的 `TaskRight`）

现在的 `TaskRight` 有三处硬编码 `datetime-local` / `toDatetimeLocal` / `toISOString`，全部改成走 §1 的三个函数：

1. 组件顶层（非条件分支里）算 `const kind = dueEditKindOf(task.dueAt)`。
2. 点日期按钮进入编辑时：`setDraft(dueEditValueOf(task.dueAt))`。

4. `commit` 改成：

```

```

其余全部保持 v0.65 的形态：外壳 `<span className="task-remaining">`、`aria-label="日期"`、`autoFocus`、`onClick` / `onMouseDown` 拦冒泡、`onDragStart` 阻止、`onBlur` / Enter 提交、Escape 取消。

## §9 已知影响

- **没有日期的限时任务改不了日期**。新建限时任务必须带日期，所以实际不会遇到；真遇到时行上只显示剩余时间，没有可点目标。
- **月精度任务保持不可编辑**（项目里目前没有）。要支持得另做「月份选择器」，不在本单。
- **日精度任务的提醒时间**仍是 `dueInstant` 的既有口径（当天 23:59:59），改日期只换日历日，不改时分。这一条与 v0.59 之前的创建行为一致。
- **两处入口（行上 / 详情底部）继续并存**，且共用同一套 `dueEditValueOf` / `duePatchOf`，不会出现两处口径不一样。
