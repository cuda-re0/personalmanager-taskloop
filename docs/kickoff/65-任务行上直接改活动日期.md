## §0 为什么改

**用户实测反馈（2026-11-03）：**

> 我这好像还是不能更新活动的日期？
> （追问后确认：**根本找不到改日期的入口**）

**已核实的事实（不要重新调研）：**

- v0.59 的日期编辑框只存在于「点开任务行 → 展开详情 → 滚到最底部」之后，且**没有任何可见标记**（`aria-label="日期"` 只给读屏，屏幕上不显示字）。
- 任务行右列现在是一个纯字符串：`<span className="task-remaining">{taskRightLabel(task, now)}</span>`，形如 `6d · 11-13 17:00`。点它等于点整行，只会展开详情。
- 用户数据库里 3 条活动任务的 `updated_at` **全部等于创建时刻**，说明日期一次都没写成功过——不是写失败，是这条路径从未被走到。
- 后端链路完好：`taskPatchSchema` 允许 `dueAt`，`taskRepo.update` 会写 `due_at`，`task.updated` 广播后渲染层 `reloadTasks()`。

**用户裁决（2026-11-03）：**

> 点行上的日期就能改。

即：**任务行右列的日期本身就是入口**，点它就地把右列换成 `datetime-local` 输入框，改完失焦写库。不展开详情、不新增任何可见文字、不新增图标。

**明确不做（越界即返工）：**

- **不加**任何可见文字、标签、提示（不许出现「日期」「点击编辑」之类）。
- **不加**图标、tooltip、`title` 属性、动画。
- **不改**行的其它交互：点标题/空白处仍然展开详情；拖拽排序照常。
- **不改** `BUDGET`/尺寸类的东西（这里没有，提一句防止顺手改 `hud`）。
- **不删**详情里已有的那个日期框（v0.59 的 `task-due-edit` 原地保留，两条路都能改）。
- **不改** `daily` 组（`DailyGroup`）的行，日期编辑只属于活动任务。
- **不碰** `useTasksData.ts`（`updateTask` 已经够用）。
- **不加**「日期不能早于现在」之类的校验（与 v0.59 详情框同口径，本单不引入新规则）。

## §1 模型层（`src/renderer/main/features/tasks/tasksModel.ts`）

### §1.1 新增 `canEditDueOf`

```ts
/** 活动任务的日期能否就地改（v0.65）：口径与 v0.59 详情框完全一致，不许出现第二套判断 */
export function canEditDueOf(task: Task): boolean {
  return task.type === 'event' && (task.status === 'todo' || task.status === 'doing')
}
```

### §1.2 新增 `taskRightParts`，并让 `taskRightLabel` 复用

```ts
/** 行右列的两段（v0.65）：拆开是为了让「日期」那段单独可点，拼接规则仍归 taskRightLabel */
export function taskRightParts(task: Task, now: Date): { remaining: string; due: string }
```

规则**与现在的 `taskRightLabel` 一模一样**：

- `status === 'done' || status === 'missed'` → 两个都是 `''`
- 否则 `remaining = remainingLabel(task, now)`、`due = fmtDueLabel(task.dueAt)`

`taskRightLabel` 的函数体改成「调 `taskRightParts` 再拼」：

- 两个都空 → `''`
- 只有 `remaining` → `remaining`
- 只有 `due` → `due`
- 都有 → `` `${remaining} · ${due}` ``（` · ` 是空格-中点-空格，与现在一字节不差）

**现有 4 条 `taskRightLabel` 测试必须继续全绿**（`tests/renderer/tasksModel.test.ts:188` 起）。它们一个字都不许改。

## §2 行右列（`src/renderer/main/features/tasks/TasksPanel.tsx`）

### §2.1 新增内部组件 `TaskRight`

在 `TaskGroup` **之前**定义（`DailyGroup` 之后即可），签名：

```ts
interface RightProps {
  task: Task
  now: Date
  actions: TasksActions
}
function TaskRight({ task, now, actions }: RightProps): ReactElement
```

自带两个状态：`editing: boolean`（初值 `false`）、`draft: string`（初值 `''`）。

**外壳必须仍然是** `<span className="task-remaining">` —— 类名、层级、位置一个都不许变（现有样式与测试都锁着它）。

### §2.2 非编辑态

按 `taskRightParts(task, now)` 渲染：

- `remaining` 非空 → 一个普通 `<span>`，内容就是它。
- `remaining` 与 `due` 都非空 → 两者之间插一个文本节点 `' · '`（**必须是带空格的三个字符**，与 `taskRightLabel` 的拼法一致）。
- `due` 非空且 `canEditDueOf(task)` 为真 → 渲染
  `<button type="button" className="task-due-btn">`，内容 `due`。
- `due` 非空但不可编辑（`deadline`、`done`、`pending_review` 等）→ 普通 `<span>`，与今天视觉完全一致。
- 两段都空 → 什么都不渲染。

点这个按钮时：

```
event.stopPropagation()      // 不触发展开行
setDraft(toDatetimeLocal(task.dueAt))
setEditing(true)
```

### §2.3 编辑态

右列内容整体换成：

```tsx
<input
  aria-label="日期"
  autoFocus
  className="task-due-inline"
  draggable={false}
  type="datetime-local"
  value={draft}
  onChange={...}
  onClick={stop}
  onMouseDown={stop}
  onDragStart={prevent}
  onBlur={commit}
  onKeyDown={...}
/>
```

要求：

- `aria-label` 必须是 `"日期"`（与详情框同值，不新增文案）。
- `onClick` / `onMouseDown` 都要 `event.stopPropagation()`：行有 `onClick`（展开）且是 `draggable`，不拦会在点击定位时误展开或误拖。
- `onDragStart` 里 `event.preventDefault()`：防止从输入框拖出幽灵图。
- `onBlur` → 提交；`onKeyDown`：`Enter` 提交、`Escape` 取消。
- 提交规则**与 `TaskDetail.commitDue` 完全一致**：
  - `draft` 为空串 → 不写库，直接退出编辑
  - `draft === toDatetimeLocal(task.dueAt)` → 不写库，直接退出编辑
  - 否则 `actions.updateTask(task.id, { dueAt: new Date(draft).toISOString() })` 后退出编辑
- 提交/取消都只做 `setEditing(false)`，不重置 `draft`（下次进入时重新赋值）。
- **不要**在这里再实现一份"退出后重置成 task.dueAt"——`task.updated` 回来后右列会重渲染成新值。

### §2.4 换掉行里的写法

`TaskGroup` 里这一行：

```tsx
<span className="task-remaining">{taskRightLabel(task, now)}</span>
```

换成：

```tsx
<TaskRight actions={actions} now={now} task={task} />
```

import 相应调整：`taskRightLabel` 若不再被本文件使用就从 import 里去掉，加 `canEditDueOf`、`taskRightParts`；`toDatetimeLocal` 保留（新组件要用）；`fmtDueLabel` 不需要引入（走 `taskRightParts`）。

### §2.5 详情里的判断改为复用

`TaskDetail` 里现在这行：

```ts
const canEditDue = task.type === 'event' && (task.status === 'todo' || task.status === 'doing')
```

改成：

```ts
const canEditDue = canEditDueOf(task)
```

**行为不变**，只是把口径收到一处。`TaskDetail` 其余部分一行都不许动。

## §8 已知影响

- **编辑态会挤压标题**。输入框固定 132px，长标题会被推到省略号；这是行内编辑的必然代价，松手即恢复。
- **不校验过去时间**。与 v0.59 详情框同口径；日期改到过去，任务照旧会显示「逾期」，由现有逾期逻辑处理。
- **两处入口并存**：行上点日期可改，展开详情底部也有输入框。用户选的就是这个形态，不做二选一。
- **`pending_review` / `done` / `missed` 的行不可点**（`canEditDueOf` 只放 `todo` / `doing`），与 v0.59 一致。
