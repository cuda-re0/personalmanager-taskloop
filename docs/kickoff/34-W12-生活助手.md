## 1. 用户裁决（原话，不要再问，也不要"优化"）

1. **「生活小助手」**：像豆包那样能日常对话，能记住「我是谁」（人物卡）。
2. **双模式**：「聊天建任务双模型，左下角一个模式切换按钮」。按钮**只有两个字「模式」**，放**加号旁边**，当前态**靠底色区分**。
3. **聊天不用识图**：聊天模型纯文本。
4. **忘了切模式**：「我自己处理，而且损失也不大，几乎没有」——**不许**做自动识别、不许做提示、不许在模型回复里教用户切模式。
5. **聊天模式发图不拦**：「我发不发图片我自己不知道吗」——`+` 号照常能点，不置灰、不加提示。图片照常落库，但**不进 prompt**。
6. **记忆 = 自动提取 + 手动可改**（丙方案）。
7. **逐字显现，不与模型 token 同步**：主进程一次拿完整回复，渲染层负责"打出来"。

## 4. 双模式入口

### 4.1 契约

`msg.send` 入参加 `mode?: ChatMode`，**省略按 `'chat'`**（`02 §3.3`）。`ChatMode = 'chat' | 'task'`，定义在 `domain.ts`。

### 4.2 主进程分派（`aiService.runTurn`）

```
runTurn({ messageId, text, attachmentIds, mode })
  mode === 'task'  → 现有 parse 链路，一行不改（chatJson + glm-5.3-flash + 草稿卡）
  mode === 'chat'  → chat 管线（§5），chatText + ai.chat.model，落 text 消息
  两个分支共用：占位消息 → patch → message.appended / message.patch / ai.status 的既有节奏
```

**不许**在 `runTurn` 里写 if/else 判断文本内容。`mode` 只能来自入参。

### 4.3 渲染层按钮（`04 §3.4.1`）

`ChatInput.tsx` 的 `ci-row` 里，`+` 按钮**右侧**插一个按钮：

- props 加 `mode: ChatMode` 与 `onToggleMode(): void`
- 类名 `ci-mode`；`aria-label="模式"`；`aria-pressed={mode === 'chat'}`
- `task` → `ci-mode--task`（实心 `--accent` 底、白字）；`chat` → `ci-mode--chat`（无底色、`1px --border` 描边、`--text` 字色）
- 尺寸/圆角/padding 与 `.ci-plus` 完全一致（复用同一条 CSS 规则或变量，别各写一套）
- **文字恒为 `模式`**，不显示当前模式名、不加图标、不加 tooltip、不加动画
- 点击后**不清空**已输入文字与已选附件

模式状态放 `useChatData` 里（`const [mode, setMode] = useState<ChatMode>('task')`），**不持久化**（重启回 `task`）。

## 5. chat 管线（`src/main/ai/pipelines/chat.ts`，新增）

规格见 `03 §4.3`，实现上就四步：

```
buildChatRequest({ text, persona, memories, brief, summary, recent })  → ChatTextOptions
  messages = [ { role:'system', content: 五段拼装 }, ...recent(20 条 text), { role:'user', content: text } ]

runChat({ messageId, text })
  1. 取 persona（personaService.get）、memories（前 12 条 + touchHits）、
      brief（buildTodayBrief()）、summary（chatStateRepo.get()）
  2. provider.chatText({ messages, temperature:0.8, maxTokens:800, signal })  ← 用 ai.chat.model 的 client
  3. patchMessage(messageId, { contentMd: r.text, status:'sent', tokensIn/out, latencyMs }) + message.patch
  4. 异步（不 await）调 §6 的记忆提取与 §7 的摘要检查
```

`buildTodayBrief()` 放 `src/main/services/chatBrief.ts`（**新文件，纯函数**：入参是任务数组 + `todayStat()` + 余额，返回那三行字符串）。**必须是纯函数**，测试直接喂数据。

模板与省略规则**逐字**照 `03 §4.3.1` 第 3 段，包括：

- 待办最多列 5 条，超出加「等 N 条」
- 标题超 12 字截断加 `…`
- 每日任务写「每日」，限时/活动写截止时刻（今天 → `今天 HH:mm`，其他 → `MM-DD HH:mm`）
- 空数据时不要出现「0 条待办，0 条已完成」这种机器腔

`provider.chatText` 与 `AiProvider` 的改动见 `03 §3.1`。`GlmClient` 要能接收不同模型名——**在 `aiService` 里按用途各构造一次 client（模块级缓存），不许每轮 new，也不许在渲染层传模型名**。

## 6. 记忆提取（`src/main/ai/pipelines/memory.ts`，新增）

规格见 `03 §4.4`。要点：

- 在 `runChat` 成功后**异步**跑（`void runMemoryExtract(...)`，不要 await、不要 try/catch 冒泡到用户）
- `chatJson` + `ai.chat.model` + `temperature: 0` + `15s` 超时
- 输出 `{ memories: [{ contentMd, kind }] }`，最多 2 条，空数组是常态
- 落库走 `memoryService.addAuto`（`source='auto'`，满 50 条先淘汰）
- **失败只写 `console.warn`**，不落 error 消息、不弹任何东西

## 7. 摘要压缩（`src/main/ai/pipelines/summarize.ts`，新增）

规格见 `01 §2.10`：`upto_message_id` 之后的原文 > 40 条时触发，压「旧摘要 + 前 20 条」→ 新 `summary_md`（≤600 字，`prompts/summarize.system.md`），`upto_message_id` 前移到第 20 条。

- 同样异步、失败静默、下轮再试
- 用 `chatJson` + `ai.chat.model`，`temperature: 0`
- **本单可以只做「触发条件 + 写回」的空壳**，把压缩调用留成 TODO，条件是：如果它拖慢了主链路。但**必须**在报告里写明只做了哪一半——不许写成"已完成"。

## 8. 逐字显现（渲染层，`04 §3.4.2`）

新增 `src/renderer/main/features/chat/typewriter.ts`，**纯逻辑、可单测**：

```
createTyper({ text, onUpdate, now? }) → { tick(nowMs), finish(), stop() }
  速率 40 字/秒；text.length > 400 时 80 字/秒
  按已过时间算应显示字数（不做逐字 setTimeout），每帧最多推一次 onUpdate
```

`useChatData` 侧：

- 收到 `message.patch` 且该消息 `role==='assistant'`、`contentMd` 从空变成非空、且 id 在**本次会话内**的 pending 集合里 → 起 typer
- 打字期间只改该条的显示文本（存 `displayText: Record<messageId, string>`），**不动 `messages` 数组本身**
- 打完（或用户点该气泡）→ 全显、清掉 typer、markdown 才解析
- `msg.list` 拉回的历史消息**一律不重放**
- 组件卸载 / 切换会话 → `stop()` 所有 typer

样式：只加 `.ci-mode`、`.ci-mode--task`、`.ci-mode--chat` 三条。**不要为整洁动别的样式。**

## 10. 测试（锁关键行为，不逐像素）

纯逻辑：

1. `buildTodayBrief`：有 3 条待办 + 2 条已完成 → 字符串里条数与标题都对；0 条待办 → 不出现「0 条待办」；8 条待办 → 只列 5 条且带「等 8 条」；12 字以上标题 → 截断加 `…`。
2. `createTyper`：注入 `now`，40 字/秒；总长 401 字时速率翻倍到 80；`tick` 停在末尾不越界；`finish()` 立即全显。
3. `personaService.get`：空表首次调用返回默认行且此时表里有 1 行；第二次调用返回同一行（不重复插入）。
4. `memoryService.addManual`：同一 `contentMd` 加两次 → 返回同一条、库中 1 行；第 51 条 → `INVALID_INPUT`。
5. `memoryService.addAuto`：满 50 条时插入新条目 → 总数仍 50、被淘汰的是 `hits` 最低那条。
6. `msg.send` 的 mode 默认值：不传 → `'chat'`（断言走的是 chat 管线，不是 parse）。
7. 注册表：`WIRED_CHANNELS.length` 比 W7 合入时 **+6**；新增六条全在 WIRED 里；`NOT_WIRED` 条数不变。

## 11. 验收（四条主路径，真机手点）

1. **闲聊**：切到聊天模式，问「我今天还有什么事」→ 回答里的任务条数、积分与右栏一致；再随便聊两句，回复是整段话、不带草稿卡。
2. **不许假装建任务**：仍在聊天模式说「帮我记个明天下午三点交作业」→ 它如实说这个模式不能建任务（**不许**出现「好的，已记下」）；切到建任务模式说同一句 → 出草稿卡。
3. **记忆**：先说「我每天早上七点起床」，聊足几轮后关掉重开 → 再问「我早上一般几点起」，它能答出来（说明记忆被提取并进了 system）。这一条**跑不通就如实写**，别粉饰。
4. **逐字显现**：发一条让它回答超过 200 字的消息 → 文字是逐字出现的，不是一次性蹦出来；打字途中点一下气泡 → 立即全显。
