## 1. 用户裁决（原话，不要再问，也不要"优化"）

1. **「生活小助手」**：像豆包那样能日常对话，能记住「我是谁」（人物卡）。
2. **双模式**：「聊天建任务双模型，左下角一个模式切换按钮」。按钮**只有两个字「模式」**，放**加号旁边**，当前态**靠底色区分**。
3. **聊天不用识图**：聊天模型纯文本。
4. **忘了切模式**：「我自己处理，而且损失也不大，几乎没有」——**不许**做自动识别、不许做提示、不许在模型回复里教用户切模式。
5. **聊天模式发图不拦**：「我发不发图片我自己不知道吗」——`+` 号照常能点，不置灰、不加提示。图片照常落库，但**不进 prompt**。
6. **记忆 = 自动提取 + 手动可改**（丙方案）。
7. **逐字显现，不与模型 token 同步**：主进程一次拿完整回复，渲染层负责"打出来"。

## 4. 双模式入口

### 4.1 契约

`msg.send` 入参加 `mode?: ChatMode`，**省略按 `'chat'`**（`02 §3.3`）。`ChatMode = 'chat' | 'task'`，定义在 `domain.ts`。

现状是 `guards.msgSend = z.object({ text, attachmentIds? })`，只加一个字段，别的不动。

### 4.2 主进程分派（`aiService.runTurn`）

现状 `runTurn` 是一个函数体直接走 parse（`buildParseRequest` → `chatJson` → `patchAssistant` → `appendDraftMessage`）。

改成按入参 `mode` 分两支，**共用的部分抽出来，不要复制两份**：

```
runTurn({ ..., mode })
  mode === 'task'  → 现有 parse 链路，一行不改（chatJson + ai.provider.model + 草稿卡）
  mode === 'chat'  → chat 管线（§5），chatText + ai.chat.model，落 text 消息，不产草稿卡
  两支共用：ai.status:thinking → patchAssistant → ai.status:idle / handleTurnFailure
```

**不许**在 `runTurn` 里写 if/else 判断文本内容。`mode` 只能来自入参。

### 4.3 渲染层按钮（`04 §3.4.1`）

`ChatInput.tsx` 的 `ci-row` 里（现状是 `ci-plus` 后紧跟文本框），在 `+` 按钮**右侧**插一个按钮：

- `Props` 加 `mode: ChatMode` 与 `onToggleMode(): void`（现状 `Props` 只有 `{ sending, onSend }`）
- 类名 `ci-mode`；`aria-label="模式"`；`aria-pressed={mode === 'chat'}`
- `task` → `ci-mode--task`（实心 `--accent` 底、白字）；`chat` → `ci-mode--chat`（无底色、`1px --border` 描边、`--text` 字色）
- 尺寸/圆角/padding 与 `.ci-plus` 完全一致（把 `.ci-plus` 的尺寸声明抽成共用选择器或用同一组变量，别各写一套）
- **文字恒为 `模式`**，不显示当前模式名、不加图标、不加 tooltip、不加动画
- 点击后**不清空**已输入文字与已选附件（`ChatInput` 内部 state 不许被这个信号重置）

模式状态放 `useChatData` 里：`const [mode, setMode] = useState<ChatMode>('task')`，**不持久化**（重启回 `task`）。

**注意**：`send` 是 **`ChatData` 的顶层方法**（`chatTypes.ts:113` 的 `send(text, attachments)`），**不在 `ChatActions` 里**。所以新增的是 `ChatData.mode`、`ChatData.toggleMode()`，以及 `send` 加第三个参数。不要往 `ChatActions` 里塞 `send`——那里没有它。

### 8.1 文本怎么进气泡（写死，别自己发挥）

**不改 `MessageList` / `MessageItem` / `TextBubble`。** 它们拿到的一直是 `Message`，`TextBubble` 内部走 `MarkdownText`。

做法：在 `useChatData` 派生 `visibleMessages` 时，**只替换正在打字那一条的 `contentMd`**，其余消息**保持同一个对象引用**：

```
visibleMessages = visibleChatMessages(messages, submitTaskIds)   // 41 的过滤先做，不许绕开
  → 若 typingId 非空，map 一遍：id === typingId 的返回 { ...m, contentMd: displayText[typingId] }，
    其余原样返回 m（不是 {...m}）
```

**两条硬约束**：

1. **先过滤再替换**。`visibleChatMessages` 是 41 的一任务一卡位，替换不能顺手把隐藏集丢了。
2. **未变的消息必须返回原引用**。`MessageItem` 是 `memo`，返回 `{...m}` 会让 20 条全部重渲染 + 每行重新测量，打字时整列会抖。

打字期间**照常走 `MarkdownText`**（`04 §3.4.2` v0.43）：半截的 `**` 会短暂显示成字面量，打完即正常。**接受这个瑕疵**，不许为此给 `TextBubble` 加"纯文本模式"分支。

### 8.2 生命周期

- 收到 `message.patch` 且该消息 `role==='assistant'`、`contentMd` 从空变成非空、且 id 在**本次会话内**收到过 `ai.status` 的集合里 → 起 typer
- 打字期间只改 `displayText: Record<messageId, string>`，**不动 `messages` 数组本身**
- 打完 → `displayText` 删掉该 key（回到原 `contentMd`，等价于全显）、清掉 typer
- `msg.list` 拉回的历史消息**一律不重放**
- 组件卸载 / 切换会话 → `stop()` 所有 typer
- **不做「点气泡立即全显」**（`04 §3.4.2` v0.43 已撤销），不许为它改 `MessageItem` / `TextBubble`

样式：只加 `.ci-mode`、`.ci-mode--task`、`.ci-mode--chat` 三条。**不要为整洁动别的样式。**

## 11. 验收（四条主路径，真机手点）

1. **闲聊**：切到聊天模式，问「我今天还有什么事」→ 回答里的任务条数、积分与右栏一致；再随便聊两句，回复是整段话、不带草稿卡。
2. **不许假装建任务**：仍在聊天模式说「帮我记个明天下午三点交作业」→ 它如实说这个模式不能建任务（**不许**出现「好的，已记下」）；切到建任务模式说同一句 → 出草稿卡。
3. **记忆**：先说「我每天早上七点起床」，聊足几轮后关掉重开 → 再问「我早上一般几点起」，它能答出来（说明记忆被提取并进了 system）。这一条**跑不通就如实写**，别粉饰。
4. **逐字显现**：发一条让它回答超过 200 字的消息 → 文字是逐字出现的，不是一次性蹦出来；打完后文本完整、`**` 正常加粗。切走面板再回来**不重放**。
