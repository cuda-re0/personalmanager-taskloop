# 59 · 活动任务可改日期 + 右列同时显示目标时间（v0.59）

> **类型**：功能新增（走外部施工方）。**必须在 58b 打完之后做**（基线与白名单都按 58b 已合入计算）。
> **需求原话**：用户 2026-11-01 21:48「活动任务加一个日期的更改，然后右侧不仅显示剩余时间，还要显示目标时间」。
> **裁决**（用户逐项选定）：
> - 改日期**只给活动任务**，限时/每日不动；
> - 入口在**展开详情里加一行日期输入**；
> - 右列**一行**：剩余在前、目标在后，中间 ` · ` 分隔（例：`2d · 11-03 14:00`）。

## 1. 现状（已查证，别重新调研）

- 右列剩余时间：`TasksPanel.tsx:175` 的 `<span className="task-remaining">{remainingLabel(task, now)}</span>`，只出一个值（`2h` / `明天` / `逾期` / `7d`）。
- `remainingLabel` 在 `tasksModel.ts:108`，实现已于 v0.58 上移到 `@shared/format` 的 `fmtRemaining`。
- **目标时间的格式化已经有现成实现**：`reminderService.ts` 里的私有函数 `dueLabelOf(dueAt)` + `pad2`，产出 `11-01 22:00` / `11-01` / `2026-11`（三档精度各自的样子）。本单把它上移到共享层，不另写一份。
- **活动任务目前没有任何改日期的入口**：`TaskDetail` 只有 `detail_md`、步骤勾选、偏移摘要、`[完成]`。`task.update` 通道与 `TaskPatch.dueAt` 早就存在，`TasksActions` 里**没有**对应动作。
- `task.update` 的 handler 在 v0.58 起已经会调 `reminderService.syncForTask`，所以改完日期提醒会自动重建，本单不用管提醒。
- 右列样式 `.task-remaining`（`tasks.css:187`）是 `flex: 0 0 auto`，没有 `nowrap`——加上目标时间后必须补，否则会折行。

## 2. 改动清单

### 2.1 共享层两个格式化（1 文件）

`src/shared/format.ts` 末尾新增两个导出（**唯一一份**，主进程与渲染层都用它）：

**① `fmtDueLabel(dueAt: string | null): string`** —— 从 `reminderService.dueLabelOf` 原样上移，规则一字不改：

- `duePrecisionOf(dueAt)` 为 `null` → `''`
- `dueInstant(dueAt)` 为 `null` → `''`
- `month` → `YYYY-MM`（例 `2026-11`）
- `day` → `MM-DD`（例 `11-03`）
- `minute` → `MM-DD HH:mm`（例 `11-03 14:00`）
- 一律用 `dueInstant` 拿归一后的时刻、`getFullYear/getMonth/getDate/getHours/getMinutes` 取**本地**字段，零补位自己算（原实现的 `pad2` 一并搬过来）

**② `toDatetimeLocal(dueAt: string | null): string`** —— 给 `<input type="datetime-local">` 的 value：

- `dueInstant` 为 `null` → `''`
- 否则返回本地 `YYYY-MM-DDTHH:mm`（例 `2026-11-03T14:00`），**不带秒、不带时区后缀**
- 日/月级 due 会归一成当天/月末的 `23:59` —— 这是 `dueInstant` 的既有口径，**不要为它另做特殊处理、不要改成 09:00 之类**

### 2.2 右列一行（1 文件 + 1 处样式）

`src/renderer/main/features/tasks/tasksModel.ts` 新增并导出：

```
taskRightLabel(task: Task, now: Date): string
```

规则（写死）：

1. `task.status === 'done' || task.status === 'missed'` → `''`（与现状一致，已完成/已失败右列留空）

## 6. 验收（用户真机手点，施工方不自验）

1. 右栏限时/活动任务行，右侧一行显示两个值，例如 `2d · 11-03 14:00`；目标时间的日期与时刻和任务一致。
2. 日级 due 的任务（如"11月3号前"）显示 `明天 · 11-03`（只有日期，不出现 `00:00` 之类编出来的时刻）。
3. 已完成/已判失败的行，右侧仍然是**空**（不是 ` · ` 也不是 `0`）。
4. 点开一个活动任务 → 详情里出现一行日期时间输入框，值等于当前发生时刻；改成别的日期 → 松手（失焦）后立刻生效，行右侧的两个值跟着变。
5. 把输入框清空后点别处 → 值回到原来的时间，任务没被改动。
6. 限时任务的详情里**没有**这一行输入（只有活动有）。
7. 改完日期后，提醒行跟着重建（原来那个提前量不再弹已过去的时点）——这条是 58 已有的行为，本单不该破坏。

## 7. 已知风险（不改，写在这里防扯皮）

- 活动任务若原本是日级精度（`2026-11-03`），打开输入框会显示 `23:59`（`dueInstant` 的归一值）；改完再存会变成分钟级。这是 `datetime-local` 的必然结果，不做特殊处理。
- 右列变宽约 90px，标题可用宽度相应变窄——标题本来就是单行省略号截断，只影响截断位置。
- 改日期不做范围校验：改成过去的时间也允许，此时右列直接显示 `逾期`，提醒按"过去的直接丢"不再排。
