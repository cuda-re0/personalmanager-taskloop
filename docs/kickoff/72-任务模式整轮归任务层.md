## 背景与事实（已由架构方核实）

现在的分层只看**单条消息**的 `meta.kind`：文字 → 聊天层。于是任务模式那一轮——用户「明天中午1点前完成大物第15章作业」+ 助手「记了：明天下午一点前完成大物第15章作业」——虽然整轮都是在建任务，却全落在聊天层。用户要的是：**任务模式发的整轮归任务层，聊天层只留纯聊天**。

消息**没有存发送模式**：`messages` 表（`001_init.sql:76`）没有 mode 列，`Message` 类型（`domain.ts:150`）也没有这个字段。所以不能直接按模式分。

能可靠拿到的信号：**一轮里有没有 `task_draft` / `task_review`**。实测用户库 13 轮：11 轮任务轮（每轮都有 draft 或 review 消息）、2 轮纯聊天轮，按这个信号 100% 分对。

**另一个必须遵守的事实**：分层判定要用**全量** `data.messages`，不能只用 `visibleMessages`。`visibleChatMessages`（`chatViewModel.ts:194`）会隐藏「同一任务的旧审核卡」和「已被待提交卡替代的审核卡」；若某轮唯一的任务信号恰好是那张被隐藏的卡，用可见数组判就会把整轮错判进聊天层。`ChatData.messages` 本来就是全量（`chatTypes.ts:110`），直接可用。

## 改动

### A. `src/renderer/main/features/chat/layerModel.ts`

A1. 保留 `ChatLayer` / `MessageMetaKind` / `layerOfKind`。`layerOfKind` 语义不变（只按单条 kind 判基础层），注释补一句「轮规则见 `layersOfMessages`，不在这里」。

A2. 新增：

```ts
export function layersOfMessages(messages: readonly Message[]): Map<string, ChatLayer>
```

规则逐条写死：

1. **轮切分**：`role === 'user'` 的消息开启新一轮；其后的消息（含 assistant）归入该轮，直到下一条 user 消息；第一条 user 之前的消息**不属于任何轮**。
2. **轮标记**：轮内只要有一条 `meta.kind === 'task_draft'` 或 `'task_review'`，本轮标记为 task。`reminder` **不作为轮标记**（它是任务通知，不代表这轮在建任务）。
3. **每条消息的层**：先取基础层 `layerOfKind(meta.kind)`；若基础层是 `'chat'` 且所属轮被标记 → 改判 `'task'`。基础层是 `'task'` 的（卡片、提醒）永远 task，不会被轮规则拉回 chat。
4. 轮外的消息：只按基础层判。
5. 返回 `消息 id → 层` 的 Map，条目数与入参一致（每条消息都要有键，不许漏）。

A3. `messagesOfLayer` 换签名：

```ts
export function messagesOfLayer(
  visible: readonly Message[],
  layers: ReadonlyMap<string, ChatLayer>,
  layer: ChatLayer
): Message[]
```

- 逐条 `layers.get(message.id)`；取不到（不在 Map 里）→ 回退 `layerOfKind(message.meta.kind)`，**不许吞消息**。
- 保持原顺序，不重排、不去重。
